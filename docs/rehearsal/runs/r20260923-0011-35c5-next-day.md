# 正式建模启动清单（准备项，未改变正式模型）

本轮使用合成五行直线数据，只验证协作和可复跑交付，不证明正式赛题的模型性能。正式资料以届时公布的题目、附件与要求为准。

## 开始前

1. 固定全员代码版本和 Python 锁文件。Windows 使用已审查的兼容补丁版本；PR #11 尚未合并，本轮没有授权自动合并。原生 Windows 仍有符号链接测试权限限制，不能把目标回归通过写成全套通过。
2. 把工作区未提交内容保留在原位置；每项工作独立分支/worktree。各人用本人 GitHub 账号，不共享密钥或本地会话链接。
3. 本轮预演状态与权限结束后保留取证。正式图谱使用独立状态与明确的成员权限，不把本轮合成任务迁成正式进度，不自动复用预演授权。
4. 成员的本地 `team serve` 要保持运行才有网页与周期同步；每人打开自己进程打印的网址。队长必须在线才能接受写请求。网页不是任务调度器，空闲 Agent 需本人恢复会话。

## 拿到题目后的第一轮

- 先共同确认题意、评价目标、输入输出、单位、限制、交付格式与时间；没有确定前不急着堆模型。
- `data/raw/` 原件只读；登记来源、下载时间、文件哈希、编码与单位。清洗代码和产物分离，记录缺失值、异常值和样本排除依据。
- 先做一个可复跑基线，再比较改进；任务卡写清目标、输入、输出、限制、验收和截止。按实际工作并行分配，不预设虚构成员或模型结论。
- 每次实验保留输入哈希、代码提交、锁定依赖、参数、种子、命令和独立结果目录。保留失败例与局限；涉及泛化评估时先固定切分规则，防止数据泄漏。
- 每份交付关联代码、结果、图表与论文段落。科学绘图使用已安装的 scientific-figures，数字来自实际结果，不手改图表数据。
- 队长独立重跑关键结果并核对单位/数量级/假设，再接收任务；看板done、签名accepted、数值验证和人眼检查分开记录。

## 联测遗留的处理原则

报告逐项标注PASS/FAIL/未测；未完成的会话恢复、人眼检查或成员环境项保留，不阻止已经验证的独立计算与PR流程。Atlas发生阻塞时可继续用任务卡、Issue、独立脚本/结果/PR协作，不为了展示进度修改正式模型或关闭验证。只在需要对应能力时做最小复测，避免再次扩展整套预演。
