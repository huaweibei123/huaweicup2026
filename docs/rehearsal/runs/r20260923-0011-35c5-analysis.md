## 潜在风险和未测项

1. **Windows断电持久性较弱（已知保证限制）**：文件fsync仍在，但父目录项替换没有额外刷新保证。签名和校验可发现不一致，不能恢复丢失的目录项。本轮没有断电试验，不能宣称崩溃耐久性等同POSIX。正式长期使用前应确定备份/恢复办法，并在独立临时状态验证失败恢复，不能拿正式模型做破坏性测试。
2. **队长离线恢复未测**：原F3被用户人工拖动测试替换；成员自身停启与最终停服不等于队长离线时请求pending/恢复同ID单回执。需要用独立预演状态做一次最小复测，而不是重跑整轮。
3. **完整任务签名生命周期未测**：计算先独立完成、队长置done；后测protocol.doing不能补证fit.doing→review。看板status只是协作字段，成员可写权限并不自动实施人审流程。
4. **其他两位Windows启动未知**：有通知无STARTED回执；不能推断已拉取补丁、已开启服务、已关机或Agent仍活跃。只把他们实际完成的Mailbox/计算判PASS。
5. **空闲Agent不会被Issue唤醒（产品能力边界）**：多次等待并非能证明消息传输失败；GitHub发布与成员实际读取、执行、回报要分列。建议每个阶段用明确的待办和期限，一次报告阻塞，不循环刷确认或期待隐式后台唤醒。
6. **证据中的时间与环境冲突**：farmer的早期材料有时间占位符及无WSL表述，但其真实检测被客户端禁止，只能记未知。报告应保留原始事实并更正摘要，不把猜测作环境证据。

## 优先改进顺序

- 正式工作前：确定统一Windows补丁版本及平台保证；每位参与者确认本人本地网页、同一项目/epoch、更新回读。无需重复整个协议联测。
- 小改优先：启动/停服回执包含当前网址及检查时刻；将“已指派、Agent已开始、已排队、已接受、结果验收、真人观察”分开显示；收尾前先停止新请求、收齐最终回执，再撤权，避免最后review与撤权竞态。
- 后续机制补测：队长离线恢复、Windows支持环境下的路径/符号链接保护，以及有明确范围的崩溃恢复。未测试前保持风险标记。
- 不建议为本次演示增加永久服务、公共网络入口或默认自动唤醒；这会扩大运行与安全范围。正式建模首先依赖题意、可复跑实验和结果审查，Atlas提供共享视图。

本文件仅分析，未擅自修改Atlas运行代码、正式模型或全局服务。
