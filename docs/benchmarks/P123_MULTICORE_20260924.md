## 数值指标

`makespan_cycles` 是官方事件模拟的完工周期数。求解器运行几秒和计划执行多少周期是两个不同量，本报告不把它们相除称为加速比。

P1/P2 的逐用例多核加速比定义为：

```text
multicore_speedup(case, k) = official_singlecore_cycles(case) / makespan_cycles(case, k)
```

官方 singlecore 将全部非 COPY 操作合并成一个子图，放到核心 0，通过官方 P1 路径执行；其等待参数仍读取官方配置。它不等于“任意算法在 cores=1 时产生的计划”。P1/P2 有效单核基线行的比值为 1。

P3 的主要 Cache 对照保持图、计划字节、核心数及配置身份相同：

```text
cache_speedup(case, k) = same_plan_P2_cycles(case, k) / P3_cycles(case, k)
```

这里的无 Cache（也可在图上标作 noL2）是原版 P2 执行模型；有 Cache 是原版 P3。没有将官方 Cache 容量改为零，没有用另一个 P2 优化计划作分子。P3 的 `official_singlecore_cycles / P3_cycles` 单独提供为补充多核指标，不能与上述 Cache 收益混为一项。配对 P2 失败时，P3 本身仍可有有效 Makespan，但 Cache 比值记为 NA。

官方配置保持 L1=524288 bytes、UB=131072 bytes、DDR 带宽=60 bytes/cycle、P1 同核/跨核等待=100/1000 cycles、P2/P3 跨核 COPY delay=500 cycles、P3 Cache 容量=1048576 bytes、Cache 带宽=250 bytes/cycle。原文件不修改。

`cache_stats.hit_rate` 直接取官方按字节命中率，不改用命中次数/访问次数。`data_movement_bytes` 保留官方完整字段映射，不猜测字段含义或把计划 COPY 字节总量当成实际 DDR 字节。周期数不经整数强制转换修饰。

每个问题、核数和指标分别计算有效逐用例比值的算术平均，并列有效数/预期 100、失败、缺失、指标不可用数量；中位数与极值另列。它不是总周期之比。未覆盖全 100 时，只能称“有效子集均值”，不能称完整 100 图均值。失败或缺失单元保持灰色 NA，不补零、不填理想核数，也不从旧研究结果补格。
