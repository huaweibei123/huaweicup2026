## 候选变化与批次

当前在线批大小为 **1**；候选从输入结构决定，无按分数自适应迭代。
已完成研究批次每图2～3候选，同 op→core、singleton编号及mapping插入顺序，
只改 core_schedules；7个不同计划按固定次序完成P2/P3对照。
后续只读输入亲和/相位可能改 op→core、分组和顺序，尚未执行；不可把当前固定分核条件
写成评估器永久缓存前提。需要按完整有序计划身份判断重用，不能排序JSON键后假定等价。

同图常驻 worker 对未来同图多个冷候选可能有用，但 Q3 目前没有256/1024等大批需求。
请求单候选低延迟与公平排队；不为凑高并发而增候选。

## 输出精度和层级

| 使用阶段 | Q3需要 | 是否必须完整缓存事件 |

| 将来普通候选筛选 | 合法性/失败类别、Makespan、各COPY字节分项、完整聚合cache_stats、route与身份 | 否 |
| 少数机制诊断/反例 | 逐操作起止/pipe/核、Cache hit/insert/evict、逻辑key/大小/时间、最终FIFO、内存/跨核信息 | 是 |
| 最终官方验收/关键回归 | 未修改对应问题E0的完整JSON，必要时从它派生可视Trace | 是 |
| 当前单候选在线路径 | 在线官方P3完整结果，计入solver wall | 当前已保存全量 |

聚合cache_stats至少保留copy_in_hits/misses、hit_bytes/miss_bytes、hits/accesses和按字节hit_rate。
普通评分不需要把全部事件串行化/传回。排查FIFO在飞命中被逐出、退休再插入、同key并发miss、
同刻退休后发射时，才要求逐事件记录。简化结果不得用hit次数比代替字节命中率。

当前P23接口中 `full=True` 走官方E0，不把它误当低成本native事件开关；如果新接口
支持native diagnostic，必须区分它和 `official_full`，清楚记账，不能悄悄用full请求烧真值额度。
E2有开发者P3证据，Windows等独立验收仍未完成；本需求不将E2升格为真值。

同计划P2/P3配对用于Cache机制对照，需要独立problem身份和相同plan/config的关联键；
不要求每一个P3搜索候选都配P2。P2评分不能硬筛P3候选，已经有080实测排名反转。

## 乱序、取消与缓存身份

可以设计为按candidate_id/pair_id收取乱序结果，但**当前Q3消费者尚未实现此接口**。
希望记录experiment_id、generation/epoch、candidate_id、有序plan字节hash、graph/confighash、
problem、官方/实现版本及route。结果先进入ID映射，仅在当前一代所需结果齐备或停止条件满足后决策；
不能让完成先后无意决定胜者。P2/P3任一半缺失标为不完整配对。

可以取消未开始项。需要可核对的queued/started/completed/cancelled状态：开始前确定取消才能释放
资源预留；已启动/状态不明保守计调用，不因客户端超时就重复投递。已完成晚到结果保留证据但不
回写过期一代。worker异常、timeout、官方拒绝、原生不支持和e0_fallback分开，不能合成一个劣分。

## 资源与预算

本机迄今1 worker，无内层并行/云任务；当前没有新增调用批准或在途预算占用。
旧两阶段分别为24上限实际17、另准3实际3，均已封存；不能从“24−17”推导继续调用权。
已执行限制为30秒/进程；第一原始批处理300秒，在线检查120秒/90秒后停发；这些不是新的默认额度。
Q3下一实验需在独立实验账本声明worker/调用/wall；公平排队不能自动扩大这些数值。

实际观测：首批单个E0进程最大RSS约38.19MiB；没有父+worker合计硬RSS或大图测试，
不把38.19MiB填为通用容量/硬上限。新的服务应由主机级资源入口统一配额，Q3默认只申请1个并发
任务，不各会话各取全部CPU。图常驻、待执行队列、诊断输出及编译缓存需有总量边界；
现有16MiB编译缓存上限不能当进程内存上限。

## 当前最有价值的瓶颈

在线全程wall为99.95/105.95/120.78ms。内层构造约11ms，
`official_import_config_evaluate_seconds`为56.61/62.16/74.75ms；
这一段合并了官方模块加载、配置和完整评价，**尚未单独分离局部编译与事件回放**。
因此优先减轻单个冷候选的完整验证/编译及IPC固定开销，保持质量/正确性，
而不是把同计划重复回放吞吐或提高并发数量当作在线加速。用相同硬件、同计划、同所需输出
比较完整solver路径；若新架构仍要求一次E0最终验证，该成本仍应计入，不能隐去。

Q3可先接窄接口的单worker评分，再扩到有限候选与跨实验公平排队。跨主机若分片，
只需独立实验分片的身份/资源/预算/结果收据；不先引入跨主机共享可变Cache状态。
此处Cache是每次官方模拟内部状态，不同候选之间不得延续模拟缓存内容。
