# Q3 首批构造方法与可验证边界

Q3 在每核一个 Task 的 B 模型上增加只读 FIFO Cache。真实优化变量仍只有
`node_to_subgraph` 和 `core_schedules`；不能提交开始时间、额外指令或 Cache 策略。
本实现只编译优先级，最终可执行性与优劣由未修改 P3 E0 判断。

## 三个直接构造

1. **分量顺序基线**：调用冻结官方 `_build_op_adjacency` 和
   `_contract_excluded_copy_nodes`，保留跨 COPY 的非 COPY 依赖，取弱连通分量。
   根据各 Pipe 的计算量进行确定性贪心分核，分量不切开，每核逐分量拓扑排列。
2. **仿射交错**：同一分核，对每核作业 j 的第 i 个操作用
   `prefix_cycles(j,i) + j * max(1, floor(max_job_cycles/8))` 排序。
   正的计算前缀保证每个分量的拓扑顺序；此坐标随构造丢弃，不是操作开始时间。
   1/8 来自 Pro2 已有研究的固定假设，本批不扫参数、不针对结果再调。
3. **资源序列**：仅接受真正串行、同构 M(a)→V*(b)→M(a)，b≤2a。
   令 h=1+ceil(b/a)，M 管线用 F0…F(h−1), B0,Fh,B1,F(h+1)…；V 管线按作业串接。
   将这些先后边与原依赖合并后做拓扑最长前缀，按前缀排序形成提交优先级。
   首尾不足 h 个作业显式处理。非同构、分叉或其他 Pipe 结构明确跳过。

三者都用全局拓扑位置作稳定 singleton 子图 ID，同一个 JSON mapping 插入顺序，
相同操作核归属。只改变 `core_schedules`；这样可减少重新编号/核归属引入的混杂。
子图细化会改变官方插入 COPY 的所属优先级，不能假定优先级等于物理执行顺序。

在 COPY 收缩后的图上，弱分量不存在互相之间的依赖，所以分量内拓扑顺序足以保证
该层优先级合法。**这不是完整执行可行性的证明**：真实 tensor、Step2 spill、Step3
内存依赖及逐 Pipe FIFO 仍可能造成不同的执行约束。每份正式方案要通过 E0。
官方收缩过程自身可能反复遍历 COPY 链；其后索引与构造为 O((V+E)log V + C K P)，
C 为分量数、K 为核数、P=4。无评分循环或随分数反复生成候选。

## Cache 与质量判断

只有 COPY_IN 在发射时查询；key 为非 DDR 输出的 logical_tid，缺省 local tensor ID。
每次 COPY_IN 完成都尝试插入；已经存在不刷新 FIFO。一次命中在飞期间仍可能被逐出，
完成后会重新插入。同 key 的并发请求不先验合并，COPY_OUT 不刷新/失效 Cache。
CACHE_READ 与 DDR 各自共享带宽，退休后才发射，同刻遍历和向上取整均保留官方行为。

因此高命中率不保证低 Makespan；P2 的候选排名不能直接作为 P3 硬筛选。
本批每份计划保持字节一致做 P2/P3 对照，外部评估不计作直接构造器在线开销，
但研究比较、事后择优所花的全部时间另报。若将评分用于线上选优则必须计入求解墙钟。
搬运字段是计划 COPY 字节；P3 不能把它直接叫物理 DDR 字节，另用命中与未命中字节说明。

## 来源、协作与当前限制

构造思路基于已归档 Pro2 原件：
`3a4505d4101e23d54580d15560da3820e02d05da:results/a/pro-research-20260924/source/pro2-r2-prototype/{construct,resource_word}.py`。
本实现增加冻结官方 COPY 收缩、串行性/理想范围守卫和跨候选稳定映射；不是作者原计划的字节复现。
理想双管线结论不包含 COPY、内存、Cache、跨核带宽，因此不宣称 P3 最优或零 spill。
源数据/源码的清单哈希随实验记录；原作者分数与本机分数分开。

Q1 交接明确 A Task 级门控不迁入 P3；Q2 已在 Issue33 收到接口问题与本批范围。
E2 P23 在603b074有开发接口和作者macOS证据，但第一小批用E0建立真值；未引入E2评分，
未通过P3独立/Windows验收，也不宣称≥10倍E1。已有Q1 Pro请求仍由Q1维护。

可用于论文的方法段：我们基于真实依赖的弱连通分量，将多管线负载分配与核内优先级构造分开。
在保持操作核归属的对照中，使用单调计算前缀及受结构守卫的资源序列交错独立作业，
通过官方事件模拟评估其对完成时间、局部 spill 与 Cache 字节命中的共同影响。
首批仅为公开开发图上的机制与基线研究，不代表全用例、全核数泛化或实际硬件收益。
