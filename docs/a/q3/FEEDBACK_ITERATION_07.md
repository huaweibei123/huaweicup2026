# Q3 迭代07：重载核交替收集归约结果

2026-09-25（Asia/Taipei）。本协议在新官方评分前冻结。

1. **目标**：在重复向量通道阶段图上减少归约与下一阶段广播的关键路径等待；首要指标为官方 Makespan，同时完整报告新增 DDR、spill、Cache 字节命中率与求解端到端墙钟。
2. **输入**：原始 051、024、016，固定官方配置，五核。严格沿用阶段结构守卫、每 lane 的固定核归属和原 ADD 树，恰好两个核承担最多 lane 时逐阶段交替使用这两个核作为 collector。不按 case ID 或历史成绩选择构造；其他核数/图不在本批评分。
3. **输出**：`src.q3.tree_solve --tree-method stage-rotate`；结果保存在 `results/a/q3-nikolastarx/rotate-20260925/`。每个新候选只一次在线 E0，计划、全结果、调用账本、代码与输入身份一同归档。旧固定四核阶段成绩只作机制背景，不能作为五核改善百分比的分母。
4. **限制**：最多 3 次新 E0、1 worker、每 job 90 秒、全批从首阶段 T0 起 600 秒；先仅派 051/k5。其合法且优于同身份五核历史 incumbent、解释与静态模型相符后，才显式继续 024/016；同版本、同 T0、同额度。首失败或首例无收益即停，不重试、不扫描参数、不新增 P2/单核分母。新机制预算独立于已封存批次，不能滚动补额。与 P1 已约定窗口错开。
5. **验证**：输入图、lane 归属不变，原 ADD 树不变；归约任一叶到根跨核次数至多一；每核优先词与原依赖合并无环。独立增强 FIFO DAG 下界检查。静态构造不是完整官方执行，也不是官方 Makespan 上界；交替 collector 的字节/Cache 变化必须从本批真实结果解释。原固定 policy 默认行为保持不变。
6. **后续**：有收益则将完整原件交成绩台单写者，提出不同核数覆盖；失败则保存证据。无论结果如何，不称全100图/1～5核超过目标，更不声称全局最优。对允许拆 lane、动态改变归属的更大方案族，另需证明或反例。

理论动机：每阶段全部计算都依赖前一 root 并到达本阶段 root，因此不存在跨阶段计算流水；但两个最重核分别作为前后 collector，可以让它们各支付一次跨核延迟，较轻核承担的第二次延迟有机会藏在负载差内。该分析忽略 COPY 服务、容量和争用，不能代替 E0。
