2026-09-24，运行前固定协议。前三阶段各自封存，用户授权继续研发；本阶段验证一个
确定性的组合求解器，而不是事后挑表格最小值。样本来自全100图的零评价结构普查，
而非临时搜索成绩好看的图。先做完整适用单树核数覆盖，再扩展其他数学家族。

## 六字段

1. **目标**：将release构造与已评价基准结合，首要最小化官方P3 Makespan，同时报告
   在线E0次数与从启动至计划落盘退出的wall、额外搬运、spill和字节Cache命中率。
2. **输入**：固定官方源码/config；全部三棵单归约树002/062/063，每图1～5核；
   多树控制037/080的4核；全部三个resource-word图008/084/095的5核。
   总20个job，算法不读取case名字或历史成绩。它们是公开开发图，不称独立盲测。
3. **输出**：`results/a/q3-nikolastarx/guarded-20260924/` 完整20job原件、所有内部已评分候选、
   被剪枝但未评分的plan/数学下界、逐次调用ledger、输入/源码身份、全成本及完整成绩台feed。
   旧单核分母复用原字节及SHA，不增单核/P2配对评分。
4. **限制**：20job、最多40次新E0、1worker、每job60s、整批600s；无重试、首异常停，
   未用额度不自动恢复/补格。非独占本机已与P1两workers协调，不用GPU/Colab。
5. **验收**：源码固定后执行所有相关单测与批次；成功结果必须来自未修改官方E0，
   最终计划必须逐字节等于成功候选中严格最低Makespan者，平手保留先评价的基准。
   证据预检/主库发布/成绩台接收/独立复核分别记录；不把本轮20格称500格全面验收。
6. **截止与后续**：本批结束后分析未改善/守卫外图，结合在途Pro数学答复选择下一机制。
   这不是停止P3研发的条件。新增阶段须按具体证据定义新样本与预算，不能续额度暴力试参。

## 在线求解规则

入口 `src.q3.guarded_solve`，固定族 `q3-guarded-release`，variant `anchor-release-bound-e0`。

1. 若是单棵归约树，用旧balanced构造作anchor；否则沿用原结构选择器（同构MVM用resource-word，
   其余affine_eighth）。先对anchor完整E0一次。**非退化保证仅相对该次anchor**，
   不谎称同时优于历史所有算法或旧safe_solve的双候选结果；anchor失败仍报失败。
2. 构造一个固定粒度release-place提案。非归约森林自然不适用；多树且没有发生任何切分时，
   保留结构baseline交错。这个范围限制由080反例触发，不是所有未切森林顺序的支配定理。
3. 与anchor完全相同则不重复评分。否则在`pipe_bound`适用守卫内计算严格下界。
   若下界≥anchor的官方Makespan，不能严格改善主目标，记录未评分计划后免E0淘汰；
   不排除次要搬运指标改善，当前采用主目标严格改善政策。
4. 下界不可用或更低均不直接接受。完整E0至多再调用一次；严格改善才替换anchor，平手或退化保留anchor。
   官方合法性拒绝会保存失败并保留已确认anchor，研究runner在此停止后续dispatch；
   未识别的异常直接失败，不能伪造有效结果。

算法只有两个有明确作用的直接构造：保留已有正确输出及引入本轮机制改进。
没有随机搜索、参数网格或取跨进程历史最优。下界计算/原件保存/E0全部计入在线wall，
不是把评分工作藏成离线预计算。已有高分成绩只用于外部研究比较，不读入solver。
