# P1：拆分工作量占主导的大分量

`components >= cores` 只保证存在足够多的不相连块，不保证工作可均衡。
05f8的完整分量分配在此条件下保留整个巨型分量，可能把85–97%的主导Pipe
工作压在一核。静态审计指出003/049/056/068/088等正式图存在这一问题，
当前方案没有spill也没有接近计算负载下界。原件来自161cdb35的固定500表。

## 可直接提交的构造

入口 `src/q1/heavy_suffix.py`，参数固定 `dominant_percent=80,max_rounds=64,max_sinks=64`。
先构造已有sink/bounded回退，再对组件数不少于核数且核数>1的图：

1. 在官方COPY收缩计算DAG上求弱连通分量，统计每个Pipe的工作量。
2. 选择总工作量最大的Pipe，只有某组件至少占其80%时激活；比较使用整数交叉乘法。
3. 仅对该组件执行sink独占后缀剥离（沿用d89a6cbf的已定义操作），逆序形成前向波。
   超过64轮/64个sink或不存在多个独立包则完整回退，不提交部分分解。
4. 将其余小组件各作为完整包，加入最后一波；每波按各Pipe负载贪心分配给核。
   同波同核包合为Task，核内Task按波递增。原操作、原ID均保留，输出只有题面两键。

80%是冻结研究触发阈值，不是最优性定理。小组件放末波避免另加一层核内等待，
但仍可能延迟最后输出、改变FIFO或增大内存压力；需要E0比较，不能保证不退化。
当前只拆一个主导多sink组件；对更均衡的大组件、单sink叉归约、多Pipe细流水还未解决。

这里的“小组件”只是选定主导Pipe之外的其余组件，**不保证在其他Pipe工作很小**。
静态审查已给出一个合成的另一Pipe重组件反例：末波装箱忽略各核已有前缀，
会人为延后独立工作。证据见 `results/a/q1-heavy-suffix-review-20260924/REVIEW.md`。
其中替代完成值89002仅属compute-only简化模型，不是未运行的官方E0成绩。
当前固定4c8构造保留此限制，不能声称其对任意图不退化；正式图探针独立记录。

## 增广DAG合法性

独占后缀剥离保证同波不同包无计算依赖，跨波边严格前向。不同弱分量间无
COPY收缩后的计算边；把小分量完整加入末波不会新增跨组件依赖，也不会拆开
其内部路径。每核顺序边严格从较早波到较晚波。因此跨Task边与核序边共同
具有波号严格递增势函数，增广Task图不可能成环。末波包合并仍满足同波无依赖。
实现另逐边检查势函数，并调用官方derive_multicore_plan/validate_task_order。

这只证明结构合法，不是Step2容量、数值运行、Makespan或零spill证书。
共享输入可跨组件复用/复制，弱连通不代表张量字节互不相交。

## 复杂度与验证

分量/负载索引O(n+e)，至多R=64轮位集剥离O(R(n+e))（sink位宽上限64），
每波包排序和最多K=5核放置总计O(n log n+Kn)。额外存储O(n+e)；已有回退和
官方COPY收缩/验证函数的开销另计，未替它们声称新的最坏界。无在线评分、搜索或查答案。

五项合成测试覆盖大量小组件掩盖重fork、保持小diamond、完整回退、COPY桥、
参数拒绝和输入不变。它们不替代真实图E0。最小机制对照预选049/k5与088/k5：
同10波、分别V主导/低输入与M主导/大输入，检验是否把单核集中工作改为有效并行。
两格固定05f8结果复用，真实新构造与官方E0另建有限新run，全部失败与退化保留。

本机完整Q1合成回归57项通过（Python3.12.13，13.406秒），包含既有测试与本次5项。
测试耗时不计作真实图求解性能，合成测试通过不替代官方E0复评。
