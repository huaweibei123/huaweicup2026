## 从提交顺序看活跃前沿

这里的“打开”是**priority 序前缀已经碰到组件第一个 op、尚未经过它最后一个 op**，不是墙钟上同时执行的组件。raw tensor 前沿把原 tensor 在每核第一个至最后一个 touched eligible op 的区间作闭区间，按字节计数，原 DDR tensor 按 P2 builder 转为 UB。它是有明确口径的静态指标，尚不是官方扩展 incarnation 图的精确驻留量。

### 独立组件：014 与 025

014 有 1,340 个弱连通组件（最大 124 个 op）；DAG EFT 将 1,200 个拆到全部 4 核，另外 140 个拆到 3 核，**没有任何组件保持完整**。每核打开组件峰值为 1,221/1,177/1,249/1,213；raw L1 前沿为 11,629,056/12,277,248/10,993,152/11,392,512 B，远超 524,288 B。

现成 whole-component assignment 的每核计算工作是 4,721,558/4,721,532/4,718,666/4,715,416 cycles，仍接近均衡；它能确定地把所有原始计算依赖留在同核，消除上述 19,153 个跨核对。这是结构结论，不需 E0，也不保证最终 Makespan 一定改善。

在同一 whole-component ownership 下，原 `component` 顺序每核打开峰值为1；`affine_eighth` 为6/6/7/7；`pipe_ready` 却为297/298/297/298。可见仅改变 ownership、再套全局 pipe-ready，仍可能过早打开很多组件。

025 有2,666个7-op组件。DAG EFT 将300个拆到2核、2,366个保持完整，但每核仍同时打开667个组件。raw前沿每核约 L1 4,786,176 B、UB 2,049,024–2,052,096 B。整组件闭合顺序可降为 L1 35,328、UB 6,144 B；这解释了为何开组件顺序值得优先改，而不是只削减几条跨核边。

### 单组件：062 与 016 不能沿用整块分核

062只有一个组件，是无 fork（每 op 出度至多1）的多层归约结构；当前各核raw L1峰值最高5,846,016 B、UB最高784,896 B。把整个组件放在一个核会丢失并行，且原ID顺序本身仍有3,351,552 B的UB前沿，所以既不能整块分核，也不能仅以原ID为普遍内存最优顺序。后续可用保持依赖的归约子树闭合顺序（加权 Sethi–Ullman/后序思想）配合子树划分；需要单独构造和验证，未在这里实现或宣称最优。

016-k2每核raw UB峰值229,376 B，大于131,072 B容量；016-k4每核恰为131,072 B，官方报告0 spill。k2实际大量spill、k4无spill与此容量阈值一致，但不能由一次吻合推出raw前沿就是所有图的官方spill判据。单纯“组件活跃数”在这两者均为1，对组件内部的大分支前沿没有解释力。

## 新单候选规则：整组件 ownership + 容量包络封闭批

接口 `component_envelope.build(graph, cores, config)`。若组件数少于 cores，抛出 `UnsupportedStructure`，交给父路由处理；不偷偷将单组件都塞到一个核。

1. 复用既有按分 Pipe 负载均衡的完整组件分核和确定性组件次序。每个组件内部固定其原来的 ID 优先拓扑序。
2. 对每个核，把被该核多个组件触碰的 tensor 记为 shared。其在**最终组件次序**中的 first–last 区间持续保留，包括中间不直接使用它的组件。冻结图的单 producer 条件下，这类跨独立组件共享 tensor 必为无 eligible producer 的图输入。
3. 其余 tensor 是 private。对每个组件单独计算固定内部序上 private tensor 的 inclusive first–last 前沿峰值 `P[j,p]`。
4. 顺次将组件加入一个批。批 `B` 的上界为 `E[B,p] = 本批区间相交的 shared tensor 并集字节 + Σ(j∈B)P[j,p]`。任何一个 L1/UB 上界会超容量时，先封闭旧批，再开始新批。若一个组件自身就不能满足充分条件，单独输出、标 `within_capacity=false`；这仅表示没有证书，不表示必然 spill 或非法。
5. 批内通过四类 pipe-head 堆交错各组件的下一个 op，**保持每个组件完整相对顺序**；批与批之间不交错。不使用参数网格、固定人造job窗口或评价器选优。

在任意批内priority前缀，各组件private状态不超过其独立序峰值，而所有shared状态都包含在持续预留的并集中。因此原tensor前沿满足 `F[p] <= E[B,p]`；priority上打开组件数不超过批大小。跨批没有仍活跃的private tensor，但shared输入可以跨越任意多批，代码明确保留。

这个证明只覆盖**原tensor priority前沿及priority组件活跃数**。它没有制造真正的执行barrier，不能限制真实同时执行组件数；也未证明 Step2/Step3 完整扩展图零spill、合法性或质量。`zero_spill_claim` 固定为 false，防止元数据越界。

一次静态尝试表明，按shared输入签名字典序聚类反而把014部分核包络提高到约2.85MB；该附加启发式已删除。最终规则保留既有组件次序，只做可解释的容量封闭，不隐藏一个调参搜索过程。
