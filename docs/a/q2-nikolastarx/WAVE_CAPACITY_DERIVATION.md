# Shared-input wave 的原始 touch 峰值容量式

范围：`shared_input_wave._sequence` 生成的**单核整组** `m` 个组件，以及 `_raw_peak` 按张量首次/末次 touch（两端都计入）计算的 L1、UB 峰。DDR 张量按 `_pool` 计入 UB。这里不是 Step2/Step3 执行内存、COPY/spill 或官方零 spill 证书。

## 精确式的额外条件

`_recognize` 保证每个共享外部输入恰有一个对应 consumer/组件，且各组件有相同的操作签名；波次按首组件的 anchor 顺序，每波逐组件输出其尚未输出的 anchor 依赖闭包，最后逐组件输出余下操作。因此，对同一共享张量 `t`，一核内它从该波第一个组件的 anchor touch 活到最后一个组件的 anchor touch；不同波的共享张量区间不交叠。

**仅当前 guard 不足以从一个组件精确外推私有峰。** `private_input` 签名只含位置和大小，不记录同形状私有输入是否在多个操作间复用；`close` 对独立前驱按实际 op ID 排序，也可能令同签名组件的块内顺序不同。精确式需再验证：各组件在每个波块和尾块的操作签名顺序相同，且私有张量的身份/消费关联在组件间存在保留位置、大小及首次/末次 touch 的一一对应。可在一次全图扫描中核对；核对失败时使用下述保守式，不能把首组件数值称为全组精确峰。

## 单组件状态及 `O(template_size)` 计算

把单组件按 `_sequence` 切成 `W` 个非空波块及可能为空的尾块。对池 `p ∈ {L1, UB}`，在块 `b` 定义：

- `A_b`：进入块时仍活着的私有张量字节数，即首 touch 在先前块、末 touch 在本块或更后；
- `Z_b`：离开块后仍活着的私有张量字节数，即首 touch 在本块或更早、末 touch 在后续块；
- `v_b(q)`：块内第 `q` 个操作处的私有活跃字节数，包含首次及末次 touch 当步；`V_b=max_q v_b(q)`。

这些值由**一个组件**的私有张量 touch 区间用差分扫描求得，时间/空间随模板张量与操作数线性。对波块 `b`，令 `s_b` 为该波共享张量在池 `p` 的字节数，`a` 为 anchor 在块中的位置，并定义 `Vfirst_b=max(max_{q<a}v_b(q), max_{q≥a}(v_b(q)+s_b))`、`Vlast_b=max(max_{q≤a}(v_b(q)+s_b), max_{q>a}v_b(q))`；空区间的最大值按 `−∞` 处理。第 `r` 个组件块外已有 `r−1` 个组件走到 `Z_b`，尚有 `m−r` 个留在 `A_b`，故私有基数为 `(m−r)A_b+(r−1)Z_b`。共享张量在首块仅从 anchor 起活跃，在末块仅到 anchor 止，中间组件整块活跃。于是每池每波的精确峰为：

```
m = 1: max_q [v_b(q) + s_b·1(q=a)]
m ≥ 2: max(
    (m−1)A_b + Vfirst_b,                 # 首组件
    (m−1)Z_b + Vlast_b,                  # 末组件
    (m−2)A_b + Z_b + V_b + s_b,         # 中间组件首个，m≥3
    A_b + (m−2)Z_b + V_b + s_b          # 中间组件末个，m≥3
)
```

中间组件的基数随 `r` 仿射变化，因此只检查两端。必须保留首组件 anchor 前和末组件 anchor 后的无共享峰：例如 `m=2,A_b=100,Z_b=1,s_b=1`，首块 anchor 前 `v=150`、anchor 处 `v=51`，真实首块峰为 `100+150=250`；若只在 `q≥a` 求首块最大值会低估。尾块无共享 touch；非空时其峰为 `V_b+(m−1)max(A_b,Z_b)`，为空则跳过。取所有块公式的最大值即该核 `_raw_peak`；L1、UB 分别计算。以上只需扫一次单组件模板，之后每个 `m` 的判定是 `O(W)`，无需构造/遍历 `m` 组件调度。

## 未核同构时的安全上界与容量选择

在当前 guard 下仍可从模板得到粗上界：每池令 `B_p` 等于**每个操作的私有输入 touch 字节数之和**加**每个操作的私有输出字节数之和**；重复 touch 也重复计数。相同签名使此数对各组件相同，它不小于任何组件全部不同私有张量的总字节数。令 `S_p` 为各波共享张量在池 `p` 的最大大小（该池无共享张量则为 0）。于是 `U_p(m)=m B_p+S_p` 是原始峰的保守上界；它可能很松，但无需私有别名或块内顺序一致。若希望较紧而仍安全，可扫描全部组件，按各自实际块顺序求私有 `A/Z/V` 的逐项最大值，再代入上式；这是 `O(全图大小)` 预处理和 `O(W)` 每次查询，不是单组件精确式。

更实用的安全界是扫描同一核组内每个组件在实际波次顺序下的单组件投影序列，删去共享张量后求私有峰 `P_j,p`，取 `Pmax_p=max_j P_j,p`，再用 `m·Pmax_p+S_p`。任一全组时刻，每个组件的私有活跃量不超过其投影峰；共享波区间互不重叠，至多再加一个 `S_p`，所以不会低估。`P_j,p` 必须按全组实际块顺序投影并只计私有张量；若改用原组件拓扑序、把跨组件张量误归私有，或放宽共享单次消费/波区间不重叠条件，此证明不适用。

对两池同时要求 `peak_p(m)≤capacity_p`。已验证精确同构时，分别检查 `m=1,2`；`m≥3` 的各项均为非负斜率的仿射式，可逐项解最大整数 `m`，并限制 `m≤组件总数`（或单调二分）。保守式直接解 `m B_p+S_p≤capacity_p`。若任一池不合格，缩小每核组件数/增加活跃核数；若合格，只能说明该**原始 priority touch** 上界合格，仍需官方语义验证。不能在未核同构、组件分配/波次规则变化、共享输入并非每组件单次消费或出现跨组件依赖时沿用精确式；这些情况可令首组件峰低估实际值，也可能破坏上述单调判定。
