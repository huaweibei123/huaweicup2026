# Q2 强核分配与核内次序组合

本分支与 Fang 协同，保留其固定 `0b58c123cccf02fc993b741d79dcd8511e4dd38f` 的 Stage B 结果。原 M1 搜索分核与粒度，M2 始终从 D 核分配出发。本次只检验 M1 胜者上的次序改进，不覆盖原开发者目录，也不宣称取代其算法。

## 构造

`FixedAssignment(graph, parent)` 用官方 COPY 收缩依赖和原计划恢复逐操作核归属。每个计算操作建立固定编号 singleton；所有候选保留父计划 mapping 键插入顺序。四个确定性策略为：

- `id`：最小编号就绪操作，用作粒度/原优先级变化的控制。
- `critical32`：复用 Fang 的“ID 最小的至多32个就绪操作，再按剩余计算关键路径排序”规则，测试已有次序策略与好分核的组合。
- `critical`：在全体就绪操作中按剩余计算关键路径排序。
- `earliest_start`：以逐核逐 Pipe 的计算可用时间和已排前驱完成时间取最大值，选择最早可开始操作；平局按剩余关键路径、ID 排序。

每次都从计算 DAG 的就绪集选择，故计算依赖被保留；这只是构造合法偏序的证明。P2 还会生成 COPY、spill 和内存/FIFO依赖，必须由完整官方 P2 评价确认。计算代理没有 DDR、COPY延迟、容量约束，不是实际Makespan下界或安全剪枝条件。首批002的最早开始策略退化至92004，说明该代理不能独立选优。

singleton候选之间只有核内次序变化，mapping值/键序、核分配相同；它们相对M1父计划还改变粒度，因此父子差值不是单独次序的因果实验。固定核分配下spill前分区COPY字节相同，spill仍可能随顺序变化。

## 复杂度与成本边界

索引依赖官方 COPY 收缩实现；尾长在收缩图上 O(V+E)。当前全 ready 扫描/heap重建为 O(V²+E log V) 上界，仅用于小范围证伪原型；静态critical可改成优先堆至 O((V+E)log V)，需要后续单独比较。earliest_start的动态键不能直接用不更新的优先堆代替。

本轮从既有强种子开始，历史搜索成本没有重跑，不能把几毫秒生成或2.83秒整批当作完整求解器速度。正式算法应把分核构造、索引、候选、在线匹配评分、失败回退与输出全部计时。本批官方评价是外部开发实验，事后选优单独声明。

```

.venv/bin/python -m src.q2_nikolastarx.pilot results/a/q2-nikolastarx/NEW-RUN
```

NEW-RUN须不存在。该命令会消耗新的最多13次P2 E0，不属于旧实验余额；复现前声明本人预算。源版本与输入哈希由协议记录，调用前持久预留，不自动重试。本批4项结构测试不等于官方完整执行验证；实际13次官方结果另附。

## 后续判据

002有小幅收益，044保留原M2最佳。不能据两图选择单一通用优先级。下一步优先解释关键等待和阶段结构，利用已有Q3受守卫资源词实现；不把多扫几个参数当作核心算法突破。若遇到异构阶段/有限容量的构造或可证剪枝难点，整理最小反例和待证命题后，在huaweicup project内请教网页版6 Pro。当前尚未发送新Pro问题，现有实验证据不足以声称存在新定理。

测后零评价诊断已由 `python -m src.q2_nikolastarx.diagnose <结果目录>` 保存到 `diagnostics.json`。002的全ready critical与earliest_start，在全部四核上最后一个M操作结束时刻分别相同；其中core0/1/3的完整M操作时间线也逐项相同。最终关键核core3的M后尾段从6259增加到26207 cycles，恰好对应总Makespan增加19948；COPY总字节与spill均未变。因此下一步应检查V/COPY收尾、跨核释放与FIFO次序，而不是继续仅压缩计算M负载。这个时间账目没有隔离单一原因，也不是改变计划后的固定工期预测。044的尾段仅79–197 cycles，瓶颈结构明显不同，不能据002强行统一两例策略。
