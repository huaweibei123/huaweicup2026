# Experimental COPY-event priority retiming

`src/q2_nikolastarx/copy_event_retime.py` is an optional fixed-owner singleton-plan retimer. It adds explicit boundary and cross-core COPY events before deriving new original-operation priorities. It is not enabled in c665 or any reported full500 solver.

The source-derived construction follows frozen P2 `_build_scene_b_tasks` before its Step1/Step2/Step3 calls. The frozen builder cannot be invoked as a lightweight extractor because those stages are fused in one function; this module imports only its shared tensor-view helper and explicitly implements a guarded event approximation. It rejects logical tensor aliases, multiple eligible producers and contracted COPY paths not represented by the event dependencies. The official input validator also rejects duplicate directed edges; a synthetic attempted duplicate confirmed this boundary. Valid distinct zero-byte direct edges remain separate COPY pairs.

Each core has one calendar per Pipe, including MTE2 and MTE3. Static cross transfer is `producer → source MTE3 OUT → configured release delay → target MTE2 IN → consumers`, with fanout shared per physical tensor and destination core. Input/output boundary COPYs occupy the same calendars. Ready events are prioritized by remaining critical-path duration; only eligible operation order is emitted, with owner preserved and structural validation repeated.

This model excludes shared DDR contention, Step2 spill/capacity and the official reordering of inserted COPYs. Its event finish is neither an official prediction guarantee nor a global lower bound. A current-plan ablation may help test timing hypotheses, but must not be called a cold full-dataset algorithm. Any production integration must generate its seed online and include its full scoring/preparation cost.

Five synthetic tests passed locally: fanout and MTE serialization, a hand-derived six-event timeline finishing at 515 cycles, duplicate-edge entry rejection, excluded COPY-path rejection, and logical-alias rejection. The later [controlled Colab ablation](../../../results/a/q2-nikolastarx/copy-event-colab-pilot-20260925/README.md) ran three real fixed-owner constructions and official E0 checks: two gains and one large spill-related regression. This does not establish full-dataset improvement. No native E2 check of these new candidates has yet been performed.
