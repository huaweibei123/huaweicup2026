# Isolated-transfer weighted hypercut prototype

`latency_hyperrefine.build(graph, plan, config)` runs the existing bounded pairwise chain hypercut with `region_width=16` and the existing initial Pipe-load caps, then retimes an improved placement with `gap_retime.retime`. It is an experimental candidate constructor, not part of the frozen production solver.

For an internal unique-producer physical tensor or one direct edge, a cut to each distinct additional core costs `cross_core_copy_delay_cycles + 2*ceil(size/bandwidth)`. A shared external input costs `ceil(size/bandwidth)` per additional consumer core. This is a **sum of isolated-transfer proxy cycles**, not official Makespan, an official COPY-byte count, or a lower bound. A zero-size internal tensor or direct edge still incurs the fixed cross-core delay. Duplicate direct edges remain separate records; tensor fanout remains one shared net. Input load from DDR and output costs that do not vary with placement are omitted from this proxy.

The default `gap_hyperrefine.refine` continues to use exact original COPY bytes. The new route reports `before_isolated_transfer_proxy_cycles` and `after_isolated_transfer_proxy_cycles`, plus static retiming detail; these values must not be compared to official E0/E2 Makespan without an actual evaluation. No real case, official evaluator, or end-to-end solver timing has been run for this prototype. The synthetic tests check exhaustive three-operation connectivity costs, single-pin move deltas, anchored two-label minimum cut, input/internal/zero-size/duplicate weights, and the original byte-mode tests.
