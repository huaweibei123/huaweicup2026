# P1：逐Pipe组件超载与商图就绪调度

入口 `src/q1/component_overload.py`。这是独立候选，已完成预声明的18张激活图五核官方验证：相对原 bounded，14图改善、4图退化；尚无本方法全100成绩。
源于五图heavy-suffix实测、任意Pipe超载静态审计及049/088轨迹审查。
继承的80%方案只有主导Pipe守卫，并把其余组件集中在末波；这会漏掉另一Pipe
很重的组件，也可能延迟本来独立的工作。本方案改变这两个限制，不声称拆分必优。

## 选择与可提交构造

1. 先得到既有heavy/sink/bounded回退。单核或弱组件数<K保持这条已定义路线。
2. 对COPY收缩图的每个组件C及每条Pipe p计算工作 W(C,p)。仅在
   `W(C,p) > ceil(W(all,p)/K)` 的某个p上成立时尝试该组件的sink后缀剥离。
   保留64轮/64sink上限；预算失败或始终没有两个独立包则保留完整组件。
3. 各被拆组件的每波独立包按Pipe负载装为至多K个粗Task；此处只决定分区，
   桶号不是最终core。所有未拆组件保持完整，再按Pipe负载装为至多K个独立Task。
4. 用实际原图依赖建立Task商图。先核对无环，再计算以Task最大Pipe工作为权重
   的逆向最长路优先级。不断从就绪队列取优先级最大的Task，对K个core比较
   预测完成时刻，采用最早者，追加到该core队列。相同值按明确的整数键打破。
5. 预测释放取该core上个Task完成+100、同core数据前驱完成、跨core数据前驱
   完成+1000的最大值；预测时长仅Task最大Pipe计算量。它遗漏FIFO、COPY、容量，
   **不是真实Makespan模拟或性能保证**。已有动态评分器没有被调用。
6. 最后应用原bounded的4096/1024独立组件软切块，并进行官方结构检查。
   最终严格仅输出`node_to_subgraph`和K条`core_schedules`，原op/ID/顺序保留。

组件未拆时，其任一Pipe工作是这个受限方案族的必要时长；超过平均分担值说明
完整组件约束阻止了该Pipe达到平均负载。然而平均负载本来就可能不可达，其他
资源可能更慢，拆分还增加搬运/等待。因此这个不等式是结构候选的理由，不是
拆分收益证明，更不是全局最优性或近似比。

## 增广DAG正确性

单组件的sink剥离中，同波包互不依赖，跨波依赖前向；只合并同波独立包，故每个
组件的商图无环。不同弱组件间无计算边，未拆组件的合并也不会引入环。
就绪队列每次仅调度所有数据前驱已经放置的Task，其放置次序本身是拓扑序。
每核的追加序也是该统一拓扑序的子序列。所有数据边和core序边都严格增加放置
序号，因此联合图无环。最后的独立组件软切块在原Task位置替换为同core链，
保持这个证明；官方derive/validate另行核查。该证明不覆盖Step2容量或数值性能。

## 边界与复杂度

没有跨实例或按case ID的路由，不枚举多个完整plan评分。每条Pipe至多K−1个
组件能严格超过其均值，所以候选组件数受Pipe数与K约束；各组件节点不相交，
至多R=64轮剥离的工作按被选节点/边求和。新分区、商图和就绪放置的常见部分
为O(R(N+E)+N log N+K(N+E))，另加原回退、官方COPY收缩与验证以及原bounded
first-fit可能的二次开销；不能把整个CLI笼统称为线性。

负载过均值但只有一个sink的重组件仍保留，这可能仍是主要瓶颈。就绪时刻
模型忽略DDR竞争和FIFO，不保证比按波映射更好；未拆组件新的装箱可改变输入
副本数量，不能沿用旧方案DDR不变结论。粗Task可以制造额外同步，所以没有把
全局下界与当前候选商图上的最长路混为一谈。Task软切块后，记录的placement
代理仅对应切块前模型，不是最终计划时长。

6项合成测试覆盖任意Pipe守卫、独立另一Pipe重任务早释放、64个四节点DAG的
联合无环与确定性、预算/单sink回退、坏收缩拒绝、COPY桥和非法core域。
这些测试不调用E0/E1/E2。另一次独立审查新增6项合成检查，12项均通过；记录在
`results/a/q1-component-overload-review-20260925/`，未修改原算法。
