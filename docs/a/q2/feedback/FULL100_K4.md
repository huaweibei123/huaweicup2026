# 同一冻结算法的四核全100图补齐协议

算法固定 `e64723bdf99669c44f76d8e90ab0379a8578522e`，variant `tensor_packet`。R4 已有十图四核的真实冷启动 solver 和独立 E0：002、016、024、028、035、040、058、064、067、073。复用这十份**完全相同算法/参数/输入/官方配置**的原始记录；其余90图按 case ID 排序分为 A/B/C 三个固定30图批。不是为每图挑历史赢家，也不把P3移植证据或结构扫描当作新评分。

三个事前 spec 为 `round5a-spec.json`、`round5b-spec.json`、`round5c-spec.json`，各批独立新目录，源文件与 runner 不变。每批最多30solver+30E0、单worker、solver30秒、E0 90秒、总1800秒含15秒收尾、不重试、首个意外失败停止。若预算未足以保留完整下一单元，则如实记录未运行项，不填补分数或偷偷续跑。各批仅在同机既有测量窗口释放后开始，批间可供P1/P3使用。

最终按100个唯一 `(case,P2,k4,算法SHA)` 汇总 B/M 的算术平均，同时列成功/失败/未运行数、每图Makespan、实际solver墙钟、独立E0墙钟、额外DDR与spill、典型/尾部时延、资源及原始记录入口。不混淆同机不同窗口的文件缓存与系统负载；本协议是单次逐图测试，不是重复独占延迟试验。发生失败时不能只取成功子集均值冒充100图成绩。

图片四核参考为3.96，来源/分母尚未给出；本队仍严格使用冻结官方A单核的100个分母。R4十图均值3.222624仅是开发集结果，不能提前代表全库。本协议也只解决四核，距离用户要求的1～5核完整对照、全面优于强方案和接近理论界的证明仍有工作。

R4相对旧连续算法十格Makespan均改善，但并非全面指标支配：058的spill从22753280升至23633920字节；016/064仍落后已知队长强方案。不得把这些代价隐藏在平均加速比里。新方法目前不包含P3后报的044连续分段40927，不能假装已吸收未来版本。后续改动另冻结算法/实验，不在这90格运行期间修改其source_paths。
