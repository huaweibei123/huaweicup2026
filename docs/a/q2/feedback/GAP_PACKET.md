# 分叉汇合与资源空隙原型

本模块明确移植P3 session `s-3d9c78db26714786b88b987ca6f58e2b` 在固定提交 `a37eb931a22fb7df7e0d00d193538ce5289ae045` 的 `gap_list.py`、`dag_list.py` 与 `gap_calendar.py`。不把同账号另一专项的原创工作改称本会话独立发现。原始calendar代码逐字保留并增加来源注释；P2适配使用已有TensorIndex和容量窗口回退，显式拓扑排序收缩链。

只有原始eligible tensor/direct边恰好等于COPY收缩后的依赖、没有logical_tid别名、图中存在分叉与汇合，才进入新路线。TensorIndex继续拒绝多原始producer。否则回退到独立审计的容量窗口构造；回退标签不等于全部核有容量证书。

把内部入度/出度均为1的串行边收缩成链，以剩余链工作最长路径排序ready队列。一般链直接比较各核的模型完成时间；若它恰好释放唯一后继的汇合点，则只比较这对链的核对（最多k²），避免父链局部最早结束却把紧随的汇合推迟。资源日历采用持久AVL树，保留已预约区间，找不早于依赖释放的最早可容纳空隙，把独立工作插入未来预约前的空闲段。最后按模型开始时间与拓扑序平局规则导出每核priority，并调用既有官方结构派生验证。

这是直接贪心构造，非方案枚举、在线E0选优或穷举搜索。日历查询/插入O(log n)，每个普通链至多k次、配对链至多k²次算术评估，整体模型阶段O(k²(n+E)log n)的保守界，k≤5。原始图索引、COPY收缩、派生验证、输入输出和冷进程均仍计入未来solver端到端时间，不能仅以日历复杂度声称完整程序速度。

通信延迟只用冻结cross delay与两端COPY服务的静态估计，不模拟DDR竞争、L1/UB容量、spill或缓存。日历模型既不是官方Makespan也不是有效的通用下界，不声称改善、无spill、近似比或最优。只有后续独立未改E0能建立本P2适配的真实成绩。P3报告的069/k5等结果属于其固定算法与实测来源，不能复制成此原型的新成绩。

开发小例仅测试持久日历与独立占用区间oracle、汇合配对、覆盖性、参数与COPY/alias守卫、容量回退。未修改当前正在全核实测的construct.py、tensor_packet.py、measure.py或官方文件，也未运行本原型的官方图构造或E0。
