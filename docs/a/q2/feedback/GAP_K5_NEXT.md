## 从保存路线能支持的机制判断

1. **原本可完整分组的结构被拆开。** 095/008/084 旧 receipt 的 `selected=guarded_resource_word`，分别有 462/108/1,077 个弱分量，旧 extra DDR 与 spill 都为 0。静态读取其原图并调用 `TensorIndex.word_descriptor()`，三图均满足 word 结构；对三份**保存旧计划**的 `physical_frontier.certificate` 在官方容量 L1=524,288、UB=131,072 下均通过，最大 L1/UB 分别是 49,152/55,488、49,152/55,488、15,360/13,920 B。新 receipt 均走 `join_gap_packet`，保存计划把上述弱分量**全部跨核拆开**，五核均受到拆分；对应新增 partition 与 spill 见表。因此 F1 的“word 优先且物理证书通过才早退”**有结构覆盖资格**，但本报告未运行 F1，不能写成已测 F1 恢复成绩。
2. **非 word 图也发生普遍拆分。** 020/045 旧 receipt 走 `packet_eft`，分别有 288/68 个弱分量、旧 extra DDR 与 spill 为 0；静态 word 守卫失败。gap 保存计划分别拆开 271/288、68/68 个弱分量，并涉及所有五核。F1 的 word 早退不覆盖这两图；它对“完整分量同核”的保守容量重排也不能直接修补这五个带拆分分量的核。它们的 partition 增量约 14.21/4.98 MB，spill 又增约 11.68/0.47 MB。是否因此构成主要 M 延迟，仍须看保存时间线和针对性对照，而不能仅由字节量断言。
3. **求解墙钟风险独立存在。** 上表四图的新 solver 单次墙钟更长，045 略短。两套结果来自共享 Windows 工作站的不同时段，不能把该差值当同机独占环境的稳定加速结论，也不能从现有 receipt 定位为 AVL 或 COPY 计算耗时。任何下一版都须同时报告官方 M 与从读图到合法计划落盘的端到端墙钟。

## 唯一下一算法方向：弱分量保留的容量/DDR 准入门

对一般图先把完整弱分量作为宏放置单元，按 pipe 负载和输入引用做一次确定性核分配；**仅当某分量在某 pipe 的工作超过全图该 pipe 工作量除以核数的上取整，或所有整分量放置都不能得到本地容量证书时**，才允许把它展开为串行链。每个开放链最多考察 `k≤5` 个核，按实际新增 COPY 对逐条计算字节及 `max(1,ceil(bytes/bandwidth))` 独占服务量，并更新 per-core 物理 token 前沿；排除完整闭区间超容量的候选。剩余候选用固定的 compute/DDR 服务下界及合法依赖优先级作一次直接选择，最后保留现有完整计划校验与失败回退。这个门针对的是“轻分量被过度拆分”；**它不是**对保存五图逐例换旧方案，也不依赖在线 E0 或历史结果。

若有 `n` 个 eligible 操作、`m` 条关联边，预索引及初始宏分配约 `O(n+m+kJ)`（`J` 为弱分量数）；开放链逐次最多 `k` 个核的稀疏增量检查，保守上界 `O(k(n+m))`，再加每核有界窗口排序与官方结构派生的既有成本。具体实现若反复重算完整候选，会退化到更高复杂度，必须计入真实端到端墙钟。停止条件：每链只评一次每核、最多一个完整输出候选；无候选满足容量与合法性时使用已有确定性回退并标记无证书，不宣称全图无解或无 spill。容量证书只承诺其适用域内 Step2 零 spill；DDR 下界不证明 M 改善。

最小事前证伪：固定 095/008/084（三个 word/旧零 spill 结构）、020/045（非 word 拆分）及两份既有 gap 改善对照，再各跑同一新版一次，禁止逐图选择旧/新赢家。逐项记录固定源码/计划身份、分量拆分数、分区与 spill 字节、物理峰值证书、官方 M、端到端 solver 秒与外部 E0 秒。若仍产生本应被门挡住的大量轻分量拆分、声明认证却出现 spill、改善对照明显恶化，或完整墙钟显著上升，保留原件并停止推广该门；单次改善不能证明所有图或求解效率都改善。
