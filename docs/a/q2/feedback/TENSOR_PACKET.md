# 张量共享分组与串行块直接构造

入口：`src.q2.feedback.construct --strategy tensor_packet`。它读取原图和冻结配置，直接给出一个官方格式方案；不读取 case ID、历史成绩或赢家表，在线调用 E0/E1/E2 均为 0。构造时间必须包含此处全部图索引、分组、分核、优先级生成、官方结构校验及落盘。

## 来源及研究动机

044 的 P3 会话方法 [bb7a7e8](https://github.com/huaweibei123/huaweicup2026/blob/bb7a7e8702b636a0a9dda33d070daad5f4d7c212/src/q3_yuanzhifang/active_stages.py) 用计算负载与 COPY 服务量的直接比较选择活跃核数，在 requested4/active2 下报告 P2 44234。此处保留其同构共享链的守卫、公式和阶段顺序，作者为 `yuanzhifang30-sudo` 的 P3 会话，原件固定 `738e2c3b274140a7ceea08d83a365282238e84c7`，不把移植包装成本会话独立发明或独立重评分。

一般 DAG 的真实 tensor 输入/输出与 core-pair COPY 建模参考队长 [7f064bb 的 dag_direct](https://github.com/huaweibei123/huaweicup2026/blob/7f064bbc4663b6ab5a7c26343620bfa4f32a4921/src/q2_nikolastarx/dag_direct.py)。本实现不同点是将满足结构条件的串行链整块分核，显式将全局 DDR 服务工作纳入选择，再重新生成有界活跃块的计算优先级；不能因此预先宣布更优。

本会话 R3 的树 DP 在受限标量切分上最优，002 的真实结果仍落后已知队长值；只有 k 个连通块的限制会妨碍平衡。本方法允许同核执行多个小块。较多大图的共享输入只存在于局部分组，所有分量输入的总交集可能为空，因此增加共享张量位置签名分组。

## 四条结构路径

1. **资源词守卫**：原有同质 `M→V*→M` 且 `b≤2a` 条件通过时，完整保留既有资源词方案，避免 R2 中仅修改 M/V 并列顺序导致的反例。不是按 008/084/095 的 ID 路由。
2. **共同输入、主链位置兼容的串行链**：检查各链每一位置的 pipe、cycles、共同图输入张量 ID 完全一致，且相邻位置之间确有依赖。允许各链有不同的前向捷径边；这些边不改变主链拓扑顺序，此守卫不声称逐边严格同构。对 r=1…min(k,J) 只算负载与 COPY 服务：`max(max_core,pipe W, sum_transfer max(1,ceil(size/bw)))`，以该值、输入字节、r 的字典序选一个 r；随后才构造一个按位置分层的计划，并保留 requested k 个 core 条目。该比较不是官方评分，也没有试跑各 r 的时间线。
3. **多个共享输入组**：将全图至少被两个分量读取的外部输入作为共享张量；每个分量按拓扑位置的 `(pipe,cycles,前驱位置集合,共享输入ID)` 形成签名，没有共享输入的分量独立成组。相同签名给出明确的有序 DAG 同构，因此也允许同构分量内的分叉/汇合；没有要求所有图输入都共享。相同签名合组，按最大 pipe 工作降序放置。每组考虑最多 k 个活跃核数量，用当前每核计算负载及精确新增输入复制工作作相同资源比较。对已选核心上的同组作业按位置排序。每条分量内部仍严格沿其拓扑序，跨组不宣称全局最优，也未证明无 spill。
4. **一般图的串行块**：小弱分量保持整体；若某分量在任意 pipe 的总工作超过全图该 pipe 工作/k 的向上取整，则将它沿 `outdegree(u)=1, indegree(v)=1` 的边收缩成最大串行链。按块 DAG 的剩余串行关键路径降序取 ready 块。给每个候选核心模拟局部 pipe 时钟、真实端点/跨核 COPY 去重与输出写回，选择 `(max(估计收尾,累计DDR服务),估计收尾,新增字节,已有计算量,coreID)` 最小者。COPY 同时竞争 DDR、spill 和内存假依赖没有被这个时钟模型完整表示，估计不是下界或成绩。

原始 tensor 至多一个 producer 是入口守卫，包含被排除的 COPY producer；100 张冻结图均满足。不能只检查 eligible producer 数再把同一物理 tensor 的多来源语义省略。

## 串行块分核后的流水优先级

单纯把块串接会在每块内部等待另一个 pipe，失去流水。分核后按每核拓扑派发顺序开放一个有限前缀，窗口为 `min(块数,8,1+ceil(全部计算工作/瓶颈pipe工作))`。每个开放块只暴露下一个节点；其所有原 eligible 前驱必须已经排入坐标表。选理想可开始时刻最早者，同时时优先剩余工作较少的块。一个块收尾后才开放该核的下一个块。

这些时刻仅用于生成优先级。真实 COPY、固定跨核延迟、DDR 竞争、Step2 spill 和 Step3 内存依赖仍由独立 E0 决定。窗口大小不是物理存储可行性的定理。

拓扑性依据：原块派发是全局块 DAG 的拓扑序。取最早未完成块，其前驱块均已完成，因此不会出现所有窗口都被未开放前驱永久阻塞；它在所属核心的队列前缀内必已开放。块内原顺序也是拓扑序，因此至少有下一个可排节点。每次只添加前驱已排的节点，最终每核投影保持同核依赖。

## 复杂度、成本与首轮证伪

索引复用冻结 `_contract_excluded_copy_nodes`，其按每个 eligible 源分别遍历 COPY 路径；在任意图上可能重复遍历同一长 COPY 链，不能把它无条件算成线性边数。记这段实际遍历成本为 T_contract，官方校验开销为 T_validate；其余建立索引和拓扑排序为 O((n+e)log n)，其中 e 包含原始 incidence 与收缩后的邻接边。k≤5。块候选分核访问每块节点及相关 tensor incidence，合计 O(k(n+e))；开放窗口 W≤8 的扫描为 O(kWn+e)，前驱未完成计数与最大完成坐标随每条后继边只更新一次。共享组只对最多 k 个资源数量作直接算术比较，未调用模拟器，复杂度由共享输入 incidence 和 k 控制。端到端费用必须加 T_contract、T_validate 及序列化，不能隐藏继承函数的最坏情况。存储为图规模及最多 k 份复制记录。没有按候选分数反复扰动、无限重启或针对当前 case 的离线赢家查表。

已有小例覆盖共享输入按核复制、保留空核、无全局共同输入的两个共享组、COPY 工作计数、多 producer 拒绝、不均 DAG 的块收缩/窗口合法性，以及资源词路径与旧实现完全相同。随后用全部 100 图四核各做一次**零 E0 结构构造**，保存路由、计划哈希与源哈希；该内部遍历时间不能当冷启动 solver 成绩。
