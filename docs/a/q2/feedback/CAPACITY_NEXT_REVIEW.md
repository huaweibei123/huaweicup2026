# 容量窗口后的结构研发审查

本轮只读检查当前 `src/q2/feedback/capacity_window.py`、`tensor_packet.py`、已完成的 `full-coverage/all500/{summary.json,per-cell.csv}` 与两批容量试验的 `MEASUREMENT.md`。没有构造官方图、调用 solver/Step2/E0 或改动源码/测量结果。全量固定基础算法为 `e64723bdf99669c44f76d8e90ab0379a8578522e`；容量试验算法为 `384b6c2a7ff937ca44180dee09a9d4bcaea0c50d`。旧连续方案只作固定历史对照，不代表中央当前最好。

## 现有守卫实际能保证什么

最强且简单的**官方 Makespan 不退化**守卫是：图、配置、官方 E0 字节相同，输出的 `node_to_subgraph` 与各核 `core_schedules` 在语义上与旧方案完全相同。官方确定性执行会得到相同 M、DDR 与 spill。若仅有 JSON 空格不同，仍应比较规范化计划结构，不把哈希不同误判为新方案。对任何**实际改变优先序或分核**的容量窗口计划，当前 `S+W·P`、`bucket_footprint_bytes`、计算 pipe 模型和官方下界都不能保证 M≤旧 M；它们没有建模 Step3 的 DDR 争用、COPY 时序、跨核依赖和真实资源仲裁。若要对非相同计划给正式 M 不退化证书，必须增加覆盖这些机制的保守时序证明或直接用未修改 E0 比较，不能把离线旧成绩表写进在线 case 选择。

现有 `capacity_window` 分支有一个有用的**DDR 字节单调性命题**，范围比“全核都有证书”稍宽：

1. 基础路由是 `shared_stages`/`shared_cohorts`，未触发重分量 packet override 或 `logical_tid` 回退；原始 tensor producer 唯一，保持基础方案的每操作单子图映射和各操作所属核。
2. 对每个改变了顺序的核，完整新序列的闭区间 `footprint` 不超过 L1/UB 容量；未能认证的核保持原顺序。现实现正按此规则构造并在改变核上检查 `bucket_footprint_bytes`。
3. 在固定官方 P2 的 `_build_scene_b_tasks` 中，原图 COPY 与每个 tensor 所触及的核集合及直接跨核边决定预插 COPY 字节。上述共享组件路线完整弱分量同核，没有跨核中间 COPY；改变桶优先序只会改变端点 COPY 所附的子图位置，不改变这些 COPY 的数量和大小。因而 `partition_added_copy_bytes` 不变。

在这些条件下，改变核的容量证书经先分配、检查、执行、再释放的 Step2 语义推出 spill=0；未改变核的本地优先序与任务图相同，其 spill 保持原值。因此新方案总 `spill_added_copy_bytes`≤旧值，进而 `added_copy_bytes=partition_added_copy_bytes+spill_added_copy_bytes` 不增，`scheduled_copy_bytes` 也不增。这个命题只关于**字节**；原图 COPY 服务、DDR 排队及最终 Makespan 仍可变。若含重分量 packet override、改变分核、任一改变核无有效证书、或更改原始 tensor 别名语义，则不能引用它。`selected=capacity_window` 标签本身也不是逐核证书。

容量试验提供了有限的支持：预定10图在1核与4核各10次官方E0均成功，025/007/036两种核数都从大量 spill 降为零且 M 降低；四核 061/050/066/068 实际走 `heavy_component_packet_override`，它们的无 spill 与收益是 E0 观测，**不受上述容量证明覆盖**。037 保持原计划和相同 M。没有证据证明这10图的收益可推至全100或全部核数。

## 仍未覆盖的退化类型

全量旧 `tensor_packet` 相对旧连续方案，1–5核退化分别24/9/11/6/8图。单核24图中21图 spill>0，另3图 035/037/061 无 spill；其中4图走 `packet_eft`，不进入容量窗口。三核11个退化中只有5个 spill>0；无 spill 的 011/029/070/093/094/096 表明容量消溢出不会覆盖所有退化。四核无 spill 的 023 (`shared_cohorts`，分区额外280,704 B) 与 037 (`packet_eft`，614,400 B)，五核无 spill 的 037 (942,080 B) 与 081 (`packet_eft`，0 B)，进一步分离了通信和优先序问题。025/036/007在1–5核的大幅损失都伴随spill，但当前容量试验仅覆盖1核和4核；3核/5核不能借用那两批的官方成绩。

即使容量守卫能保证额外DDR字节不增，也不能保证与**旧连续方案**相比 M 不退化；单核容量试验的037走原样回退，其 M 仍等于旧 `tensor_packet` 且慢于旧连续，正是两种对照不同的例子。对 `packet_eft` 的跨核搬运退化，需另审其分核与传输规则；对无 spill 且无额外搬运的优先序退化，需研究真实资源顺序，容量窗口不是充分机制。

## 可直接构造的下一步：共享输入生命周期分组

当前 `memory_window` 把被多个作业消费的每个共享图输入从整核开始到结束都保守预留为 S，然后用 `S+W·P` 限制 W。这容易把互不重叠的输入使用阶段视作同时常驻，使可安全并行的窗口过窄。建议在**保持原分核与 singleton 映射**的共享路线内，把作业按其共享输入签名建立连续组；组内维持作业原拓扑序，仍用直接的有界 pipe 优先规则交错至多 W 个作业。优先完成当前共享输入组，再开启下一组，使当前输入在最后一个消费者桶后可按实际闭区间释放。完成整个候选顺序后，用已有 `footprint(index, full_sequence)` 对 L1/UB 两池作**完整静态证书**；任一核越界就保持该核旧顺序，不能靠更乐观的 S 估计放行。此处按输入结构排序，不按 case ID 或历史赢家挑选，也不调用在线 E0。

候选的可证伪命题是：对输入组可以连续处理、且当前 S 长时间覆盖多个相互分离使用区间的图，释放后的真实共享 tensor 闭区间可让 W 高于现有全程预留上界，同时不增加官方额外 DDR 字节；但 M 可能因组间串行、COPY 时刻改变而升高。其正面验证应记录每核新旧 `W`、`S`、完整闭区间峰值、实际E0 spill/M和 solver端到端墙钟；反例若 W 不增、spill不减、M退化或求解显著变慢，原样保留。先在合成相交/不相交共享输入小图证伪闭区间证明，再对事前固定的少量结构代表图做官方E0，不能只挑已改善项。

实现可先采用确定性的签名排序：一次扫描外部输入引用 O(I)，构建和比较作业签名/分组保守计 O(I log J)，仍只生成一个顺序；`pipe_window` 对每操作最多 W≤8 个活动作业作直接比较，O(Wn)，最终闭区间检查 O(n+I)。这是**增量层**的估计；基础 TensorIndex、COPY 收缩、构造、结构派生与进程启动仍需计入端到端时间。若改用对所有剩余作业逐轮扫描的动态收益排名，最坏会到 O(J²+I)，不应在大图上未测即替换当前规则。生命周期分组只给 DDR 不增的候选守卫，不能宣称完成 Makespan 优化；下一轮应沿质量—墙钟 Pareto 前沿同时比较。

一个更保守的研发切分是先仅改变每核作业优先序、固定分核和每操作子图，检查上面的字节命题；重分量 packet 和一般 DAG 通信规则另作为独立机制评测。这样一旦 M 退化，能判断是同映射下的顺序/DDR时刻问题，而不会把新跨核搬运混入容量因果分析。
