# 固定单尾次序的计算 FIFO 必要界

`tail_fifo_bound.py` 单独重算 `wave_tail` 固定的守卫、容量包络、两遍分段 DP 与每核计算次序。它不调用提交构造器、derive、Step 或 E0，不生成官方两字段计划；但确实执行一次针对当前图的候选计算次序分析，成本必须另报。不得复用这些中间量绕开未来冷求解计时。整个分析包含 `O(kL²)` 分段；已有次序上的最长路本身为 `O(V+E)`。

对每个 eligible M/V 操作建立顶点，以其正整数计算周期为权重；保留原计算依赖（含原 COPY 节点收缩后仍需满足的先后），再加入每核每条 M/V 管线投影中相邻操作的完成依赖。忽略一切 COPY 执行、跨核 500 周期、DDR、Cache、spill 与内存复用约束。若合图无环，其最长加权路径是**这个固定候选**的必要 Makespan 下界；加入的同管线边也给出每核管线总工作量界。若有环则该次序无法由此模型调度，入口报错，不输出虚构时间。

依据冻结官方源码：P3 `_prioritize_task_seq` 按提交子图顺序稳定分桶。canonical singleton 保证计算操作投影就是候选次序；Step2 的 `seq_ext` 只在原 `seq` 前后插入 COPY，原计算顺序保持；Step3 从 `seq_ext` 投影出固定 pipe orders，P3 `queue_if_ready` / `advance_pipe` 只启动队首。原依赖在插入/重接 COPY 后仍为必要的生产者先于消费者，忽略正的搬运与等待只会放松。因此任何合法官方执行都满足上述各条边；沿路径累加顶点周期即证下界。这里不额外加入未经逐边审计的通信时延。

最长路低于 incumbent 不证明存在同时间的真实执行。只有确认原图、配置、官方代码与同核数 P3 incumbent 身份一致，且下界已不低于 incumbent，才足以证明这个固定候选无法改善其 Makespan；不能排除别的尾段次序、切点或 DDR/冷墙钟价值。

两项独立合成检查：三条 M10→V10→M10 作业的单尾布局，工作量峰值30而零额外通信的 FIFO/DAG 下界40；小型三顶点整数起点穷举验证全部满足必要界且松弛界可达。合成结果不冒充官方图或 E0 成绩。
