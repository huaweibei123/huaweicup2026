# 任意合法方案的必要界限，不是已达最优证明

补充适用域与追溯状态见BOUND_SCOPE_REVIEW.md：新增原tensor至多一个producer守卫；已复用固定结构审计核对100/100原图满足此条件，SHA与既有分析逐图一致。旧原件保留，没有新增图扫描或评分；适用条件核验不等于最优性证明。

源码 `lower_bounds.py`。论证限定本库冻结官方P3：每个非COPY_IN/COPY_OUT的原操作恰好运行一次、普通操作时长max(1,cycles)、每核每Pipe一个槽，DDR和CACHE_READ各自分享固定总服务率，Cache初始空。原计算依赖保留；不知道分核时不向任何边擅自加500。源码来源为官方schedule_step3.py的_op_duration、PIPE_SLOTS及multicore_cut_evaluate_problem_3.py的任务构造/issue/retire，未改动。

1. **管线工作**：对任一Pipe p，原操作总时长W_p必须由k个单槽资源执行，故T≥ceil(W_p/k)。复制和等待只会增加占用或停顿，不能消除原操作工作。
2. **计算依赖路径**：只取官方构造直接保留的非COPY操作间边（直接op→op与有eligible生产/消费的tensor边），丢掉全部COPY、通信和额外容量边。每条路径操作顺序必须成立，故T不小于其最长时长。这里不收缩未知原COPY路径，以免向官方并未保留的依赖作额外推断。
3. **首次输入与最终输出**：当原tensor没有自带logical_tid别名时，每个图输入至少有一份第一次COPY_IN miss，且最早完成不早于ceil(size/DDR带宽)。别核命中必须等这次冷填充完成后才可能开始，所以每个消费者的最早开始也不小于此值。每个官方必须写出的图输出在其生产者结束后仍需至少ceil(size/DDR带宽)的服务。把这些理想最小入口/出口长度接入计算路径仍是下界，忽略了实际竞争与容量。零大小按官方最少1cycle。
4. **必需DDR服务总量**：原Cache key无别名的守卫下，每个输入至少一次上述miss，每个输出至少一次DDR写出，共享DDR池不能同时免费完成这些工作。将各份最小服务时长相加得到另一必要界。输入复制、spill或跨核搬运不计入，因它们依赖方案；有logical_tid时本实现禁用这两类IO界，不作外推。

取各界最大值。对于固定单核基线B，B/LB是单例方案加速比的上界；100图均值上界是mean_i(B_i/LB_i)，不能使用总时间相除。界与合法官方结果若矛盾，首先停用并调查该界，而非宣称评估器错误。只证明这几条必要条件，并不证明能同时达到；差距大时要补强松弛或改算法，不能宣布无法继续逼近。

这是原始图/配置上的零评分分析，所有分析墙钟及输入SHA单列；不能把它放到当前用例外预计算后隐去在线求解成本。已生成100图×1–5核必要界，独立结构扫描与中央500格原身份/基准配对核对均通过，见 STRUCTURE_INVENTORY.md。中央eligible不等于本机重新复评所有原件；LB≤T的一致性也不是全局最优性证明。
