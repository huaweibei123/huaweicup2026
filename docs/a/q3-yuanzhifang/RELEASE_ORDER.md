# 保留计算FIFO，调整跨pipe优先次序

既有069的官方MTE2曾把已释放COPY排在另一个晚释放COPY后等待9699周期，见TRACE_FEEDBACK.md。不是所有这类等待都能通过两个允许字段消除，也不能直接修改官方COPY队列。这里检验一个更窄的自由度：保留分核和每条M/V管线的原操作次序，只换M与V操作在核内优先序中的交错。

先运行固定join_list直接构造，仍没有在线E0。对其真实原计算依赖加逐核逐pipe FIFO边，跨核计算边取固定500延迟，求每个原操作的最早开始。将每核singleton优先序稳定排序为最早开始递增；同时间保留原优先。官方COPY分桶依目标/源subgraph次序，跨pipe交错改变后可能生成较早就绪的MTE2序。原操作、tensor、分核、M/V序均不变。

可证明的不变性：每条原依赖与每条既有同pipe FIFO边u→v都满足start(v)≥start(u)+w(u)+delay，w(u)≥1。因此依start排序是增强计算DAG的线性扩张，保留所有原依赖；同pipe次序严格不变。输出的同pipe FIFO边集和原依赖/跨核边集均不变，所以固定计算L0、L500完全相同。额外排序O(V log V)、图处理O(V+E)，只输出一个方案。

此结论只保住计算约束，**不保证官方Makespan不退化**：COPY顺序、Cache轨迹、Step2驻留及Step3容量门控可能改变。也没有把计算最早开始当可提交时间，实际仍仅两字段。原计算须M/V、singleton，真实eligible依赖与收缩图一致，其他结构保留既有fallback。

第七独立首证伪（尚未执行）：仅069/k5，1cold、同plan P2/P3各1E0，共1/2；与ef80a88固定join结果P2=16742/P3=15221比较，不重跑控制。如果生成的plan与已有join字节或完整语义相同，记录相同并复用原件，不启动E0。1worker、单调用30s、整批120s/90s后停派、首失败停、0retry/E1/E2/云；源码和runner先冻结，并等P2当前已排批释放。该机制验证不替代交给成绩台owner的规模/跨平台包。
