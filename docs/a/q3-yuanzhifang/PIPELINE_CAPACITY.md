# 给cold-setup分段添加共享驻留约束

动机来自固定第十二批f14e8f0a的反例：044/k4新切分的一段共同输入为663552B，超过L1的524288B，实测spill1622016B、P3=41738，差于原40927。这里修正抽象模型适用性的缺口，不把更高Cache命中率当目标。

仍要求正整数M/V同构串行作业、相同共同输入签名、每共同输入唯一消费位置、作业数≥核数、长度≤512。对阶段[h,i)及每个存储空间r∈{L1,UB}，设共同输入字节为A_r[h,i)，另取该段各作业任一操作的非共同输入/输出邻接tensor字节最大值W_r[h,i)。只接受 `A_r[h,i)+W_r[h,i) ≤ capacity_r` 的连续段。

沿用cold-setup模型的精确目标：sum(p)+max_s((J−1)p_s+prefix(q)_s)。原O(kL²)分段DP仅删去不满足驻留约束的转移，其最优子结构不变，故仍精确求解这个**带静态约束的抽象问题**。从固定end向前扫描start时共同输入和单操作最大值单调不减，第一次超容量后即可停止；存储空间只有两个，时间O(kL²)，DP空间O(kL)，字节前缀与位置数组O(L)。没有可行分段时明确回退原pipeline_stages，不尝试评分搜索或增加核数。

约束只排除明显不能把全部共同权重与一次操作临时工作集同时驻留的分段。其他tensor长生命周期、并行作业激活、预取、COPY输出排队与官方具体分配策略均可能继续造成spill，因此不是零spill证明，也不是E0 Makespan界。对共同权重总量大于k倍容量的家族，纯驻留分段可能根本不可行；后续应考虑共享权重分批访问，而不是任意放宽该约束。

合成检查包括150个随机小问题的所有连续分割枚举与独立串行事件表、恰好等容量/少1字节边界、不可行后的原方案精确回退及完整singleton覆盖。仅数学/构造开发检查，0E0。当前没有真实图成绩，不加入已冻结统一入口；最小官方证伪需另冻runner与有限预算。

## DDR端点守卫勘误（2026-09-25）

原实现把所有非L1/UB tensor都判为不支持，因而会拒绝官方合法的原始DDR COPY端点。冻结官方 `evaluation_validation.validate_graph` 明确允许DDR/L1/UB；P2构造任务时，原始DDR tensor若接入计算核，会转换为局部UB tensor，并为图输入插入COPY_IN、为图输出保留COPY_OUT。现在只对未知空间拒绝；原始DDR COPY端点的字节不计入L1/UB驻留式。若DDR tensor本身是多个作业的共同计算输入，则局部UB物化会影响驻留，当前抽象没有准确表示，明确以 `shared_ddr_input_requires_ub_materialization_model` 守卫回退，不将它当作零片上字节。非共同DDR端点引发的临时物化、预取和重叠生命周期仍属模型外；可行分段依旧不是零spill证明或E0界。新增含原始DDR COPY_IN/COPY_OUT端点的合成构造，以及共同DDR、未知空间回退检查；未运行官方图或E0。
