# 共享输入burst条件界的补充审阅

来源为Pro首轮§4.5与冻结E0：`multicore_cut_evaluate_problem_3.py`的COPY锚点/桶优先序、`schedule_step2.py`的当前操作保护、最远下一次使用驱逐及事后spill展开。此次是源码与纸面逻辑复核，0原图构造/Step/E0，没有新增实测反例。

Sol medium提出“full超过bmax，故无法用每权重每wave一次的界”。父会话未采纳此推断：Pro该引理的前提是单操作必要输入输出可容纳，不是整个wave满足W+A+(b−1)F。Step2上成为驱逐候选也不表示一定被逐出；还必须比较其他驻留项的下一次使用。full不满足静态wave包络，只能说明它不满足该包络条件，不能单凭此否定独立的读取次数引理。

需证明的序列条件可以收紧为：完整独立作业单核；同一位置每作业使用共同输入一次；singleton优先序按wave/位置/作业；内部位置没有外部输入COPY，私有输入仅用于入口，输出COPY紧邻其生产者桶；单操作输入和输出总量在对应空间内可容纳。P3会删除原COPY并按compute端点重建，因此证明对象必须是重建后的优先序S，而非原图COPY列表。

在这些条件下的证明框架：共同输入相邻两次compute使用之间，只可能出现上一compute的输出COPY和下一compute的输入COPY。输出COPY不分配新的片上结果；下一个compute的新输入COPY只增加该compute必要足迹的一部分。如果发生容量压力，不属于该足迹且仍驻留的项，其下一次使用晚于即将发生的compute；Belady会先逐出这些项。当仅剩该compute所需片上数据时，单操作容量条件排除继续驱逐共同权重的必要。compute本身又保护全部当前输入输出。对连续consumer归纳，可得到每次wave起始至多一次加载；跨wave可重新加载，故总共享读取上界为W乘各核wave数之和。Step2脏spill操作是在这轮原序列生命周期模拟之后展开，不能把扩展COPY再作为另一轮驱逐操作重复模拟。

这仍是条件证明框架，尚非对当前guard全部可接受输入的形式化证明：private分支允许较宽的原始COPY端点/内部输出形式，需要逐项证明上述生成序列性质或进一步收紧guard。当前原型保持固定，不用此框架跳过官方合法性或实测读取审计。仅对已审计的具体结果可说读取量符合界；不能由其成立推断零私有spill、最佳wave宽度、Makespan优胜或全局最优。

算法取舍：full各核一个wave有更少共享权重加载机会，但私有激活驻留量较大；capacity将波次拆小，允许增加共享权重读取以减少激活压力。bmax是静态容量包络的直接构造参数，不是最优Makespan定理。固定full/capacity对照的目的就是区分这个取舍，不在线扫描宽度或事后把两次构造合称一次求解。
