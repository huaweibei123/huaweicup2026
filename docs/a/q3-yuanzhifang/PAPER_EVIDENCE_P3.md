# P3 可供正式论文整合的证据段落

本文为成员草稿。队长单写正式 `problem3.tex` 等正文；下述内容区分证明、开发例实测、原件复核和未验证假设，不以成员草稿替代最终算法全量验收。

## 模型与指标

可提交决策包括原计算操作到子图的映射、子图的核心归属和每核执行顺序，提交文件仅含 `node_to_subgraph` 与 `core_schedules`。最终目标首先是未修改官方 E0 给出的 Makespan，另列额外搬运量和 Cache 按字节命中率；同计划 P2/P3 比值隔离无 L2 与只读 Cache 的硬件语义差异。求解程序端到端墙钟从进程启动至合法计划落盘计量，包含在线候选构造、评分和选择；独立外部复评另列。5–10 分钟是题目效率建议，不是固定硬件下的600秒淘汰线。

## 两种不同范围的必要界

**完整作业界。** 在067中，原图分成71个计算连通分量，每个分量的M管线工作量为829792周期。若每个分量完整放在一个核心，则5核中至少一核包含15个分量，因此Makespan至少为12446880。这个论证不要求分量连续执行，不受Cache或COPY加速影响，但只约束完整分量归核的方案族。已有固定合法方案12237901低于此界，故要继续改善主指标必须离开该方案族，不能只调整完整作业的波宽。图分量证书与代码固定在09191c18，见 `WHOLE_JOB_BOUND.md`。

**固定计算次序的FIFO界。** 对通过结构守卫的singleton计划，将原计算依赖与各核同管线相邻操作的先后边合并，给操作顶点赋其正整数计算周期。在这个图上取最长加权路径，得到忽略COPY、容量等待和额外跨核延迟的必要界。该界只约束所选计算次序；更低的界表示旧等待障碍被放松，不能证明新方案会达到此界或获得官方改善。067旧末波单尾次序的界为12218400，而工作量峰值仅11791696，表明单纯均衡工作量漏掉了FIFO路径瓶颈。

Pro R2 提出的首波容量阶梯采用相同切点，把尾操作放在各自首波且优先于同位置完整作业；每核首波完整作业数由逐位置容量代理直接取 `n_c=h+c`，不做E0参数扫描。候选源码68fbe66e、静态证据789cabfd得到 `n=[2,3,4,5,6]`、FIFO界11856672，关键路径854个操作；一次静态分析完整进程0.801024秒。它仍非官方实测结果，W/A/F足迹尚不是Step2零spill证明。067/k5的余量与全100平均贡献详见 `results/a/q3-yuanzhifang/stair-global-value-20260925/`：其余99例不变时，即使达到此固定次序界，平均加速比也至多增加0.001677158。

## 为什么命中率不能替代 Makespan

在一个更简化的精确算术模型中，若操作DAG、所有资源串行先后边和每个操作的服务时长均已固定，最早完成时间满足 `F_v=d_v+max_{u→v} F_u`（空前驱最大值取0）。按拓扑序归纳可知，同时缩短任意一组非负 `d_v` 不会增加任何 `F_v`，也不会增加最终Makespan。这个单调性命题的关键是**同一组先后约束和可逐项比较的固定服务时长**。

冻结官方P3实现不满足上述固定服务时长条件。`multicore_cut_evaluate_problem_3.py` 的 `advance_pool_work/reschedule_pool`（约352–393行）随当前活跃COPY集合均分池服务；约543–580行在操作启动时按Cache状态选择DDR或CACHE_READ池，再重算结束时刻。因而加速一个读操作可能改变随后COPY的开始、重叠和池负载；不能仅从命中率提高推出每个COPY的实际历时都不增加。该源码事实说明简化单调性定理不能直接用于官方P3剪枝，**本身不是某个反例的完整因果证明**。实现还有浮点事件容差，本文不将精确算术定理包装成机器实现的误差保证。

同计划021/k3负收益的证据页为 `CACHE_NONMONOTONE_021.md`。它用于反驳“开启Cache必不变慢”的无条件命题；具体操作时序比较只按已取得的两端原件记录，不能把一条COPY变慢直接解释成末端差异的全部来源。任何为提高CacheGain而主动劣化P2分母的做法均不属于优化P3官方Makespan。

该例P2/P3为2140720/2140863周期；两端8881个操作的身份、各核每pipe次序、3814次COPY_IN、1147次COPY_OUT和五项官方搬运字节均一致。最早完成时间变化是一次命中读取的207→17周期加快，随后大量操作交错变化；另一同起点DDR读取从69变成138周期。这提供“同计划、同搬运量而Makespan变差”的真实观察，仍不声称这一个后续慢读完整解释终点的143周期差异。两端原件SHA与小审计脚本均已保留，不新增评分。

## 实测开发例与适用限制

本线容量DP在044/k4的独立开发例把官方P2=P3的Makespan从40927降至37581，改善8.1755%；extra DDR从135168降至121088 B，spill和字节命中率均为0。这说明该例改进可以在没有Cache命中的条件下发生，不能统一归因于Cache；原件固定7edacdd9。一次冷构造2.724028秒，外部P2/P3复评分别2.584837/9.150610秒；在共享Windows主机上的单次观察不能证明相对队长Mac整体求解器的速度优势。

本线尚未完成同一冻结入口的100图×1–5核新全量实验。既有33cold/56外部E0、失败与负结果全部保留；静态分析、合成测试和未启动的1cold/2E0候选预算分别记账。论文主表只能使用实际覆盖且身份一致的固定算法结果，不能将上述不同方法、不同核数的开发最好值拼成新算法均值。
