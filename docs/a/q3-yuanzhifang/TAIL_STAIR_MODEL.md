# 首波容量阶梯与尾操作优先：只读计算模型

`tail_stair_model.analyze` 是按 Pro R2 主路线实现的**纯计算次序模型**。它不生成或写官方 plan，不调用 `build`、`derive`、Step 或 E0；R2 中的 067 数字是作者报告，并非本模块的本机成绩。本模块未读取或运行真实 067。与旧 `tail_phase_model` 先做 c 个完整作业再放尾波不同，本构造把尾段统一放在**首波**，且在该波自己的位置上先排尾操作、后排完整作业操作。

先复用 `wave_capacity.structure/model` 严格同构守卫和 `wave_tail.partition_tail` 两遍 DP 切点。仅处理 `J=qk+1`、`k≥2`、`L≥k`。按每位置、每空间的代理足迹 `Φ_r(p,b)=W_r(p)+A_r(p)+(b−1)max(F_r[p],F_r[p+1])` 求可容许最大宽度 `β[p]`，上限截至 `q+1`；全局后续波宽 `B=min_p β[p]`。核 c 的首波完整作业数上限 `U_c=min(q,min_p(β[p]−1{p在核c尾段}))`。直接取 `h=min_c(U_c−c)`、`n_c=h+c`；`h<1` 则本模型不适用，不调整容量也不搜索别的阶梯。首波完整作业按固定 round-robin 归核的前 `n_c` 个；余下完整作业用最少数量、较大波在前的均衡波次，每波宽不超过 B。尾段各位置只在自己的首波出现一次，且排在同位置完整作业之前。

模型核对 eligible compute 恰覆盖一次、每个原 DAG 的核内边顺序正确、跨核尾部依赖向更高核前进，再调用已有 `tail_fifo_bound.longest_path` 计算原 compute DAG 加各核 M/V FIFO 相邻边的**零额外跨核 lag 必要界**。输出 `β/U/h/n_c`、每核波宽、切点、关键路径及边账、工作量峰值和模型限制。它不包括 COPY、spill、Cache、跨核真实传输延迟或官方资源调度；`W/A/F` 容量是代理，不是 Step2 零 spill 证书。即使必要界低于已有成绩，也不证明该界可达。

R2 的理想单管线说明是有限范围命题：单作业位置工作量 `d_p`、前缀 `P(p)=Σ_{j<p}d_j`，核 c 首波 `n_c` 个完整作业并对尾操作优先；若 `n_{c+1}≥n_c+1`，下一段的本地首尾操作时刻不早于前段完成时刻。合成测试使用独立整数事件模拟逐例核对该公式。M/V 双管线和原始 COPY 插入不继承这个无等待结论，仍须看上述 FIFO 必要界及未来独立官方评估。

所有当前计算都是合成验证：覆盖、原 DAG 拓扑、尾操作优先、容量阶梯不适用守卫和单管线公式。若以后用于当前图的在线求解，索引、守卫、切点、`β/U/h`、次序检查和落盘都必须计入冷 solver 墙钟；本独立模型成本不能在冷调用之外预计算复用。
