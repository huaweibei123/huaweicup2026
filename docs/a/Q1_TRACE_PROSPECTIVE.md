## 对算法研发的决定

1. `profile_refine.py` 默认路径保持现有生成和评价逻辑；入口提前量排序停留在可复核的可选实验模块。
2. 保留 051 的事后机制解释和旧池调用次序观察；其证据等级不因本次无收益而被抹掉，也不升级为通用收益定理。
3. 当前瓶颈之一是候选覆盖：先生成的两个 split 恰好都无提前量，只对这两个重排无法找出池外的合适切点。本次未实现、更未验证扩大候选或直接按远端入口生成候选的方案。
4. merge 排序仍未解决。边界字节节约、零 spill 都不能替代 makespan 精确评价；不因本轮负结果改用它们硬剪枝。
