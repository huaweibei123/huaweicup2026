# Q1：固定分区下的合法 Task 移动区间

2026-09-24。上一轮有预算搜索在普通开发例中花在候选生成上的时间超过精确评价。这里实现一个可证明的局部邻域：直接求出移动一个 Task 时允许插入的位置，再由固定版本精确 evaluator 计算实际 makespan。数学规则只覆盖 Task-order 合法性，不假设跨 Task 片上复用，也不把零 spill、搬运量或局部工期当成真实目标的替代。

## 区间规则与适用条件

固定合法分区及当前计划。令 D 为全部 Task 数据依赖边，C 为各核 Task 顺序的相邻边；要求增广图 (V,D∪C) 无环。选择移动 Task t。

先从每条核序列移除 t，并将原核心上 t 的前后 Task 接起来；保留 t 顶点及它的数据边。由 D 和这些缩短后的核序列构造基图 B。B 仍无环：新增的前后连接只是旧图中经过 t 的路径的快捷边。这里没有把 t 的数据依赖从图中删除。

在 B 中求 t 的传递祖先 A(t) 与传递后继 Z(t)。设目标核移除 t 后的序列为 q[0…m−1]，插入槽位 k 表示排在 q[k] 前面，k=m 表示末尾。合法槽位恰好是整数区间：

```
L = 1 + max({i : q[i] ∈ A(t)} ∪ {−1})
U = min({i : q[i] ∈ Z(t)} ∪ {m})
L ≤ k ≤ U
```

必要性：若祖先落在 t 后面，核链与该祖先到 t 的路径闭合；若后继落在 t 前面，t 到该后继的路径与核链闭合。

充分性：槽位内部只新增前邻 p→t 和 t→后邻 s。只经过其中一条新边的环，分别要求 p 是 t 的后继或 s 是 t 的祖先，已被区间排除。经过两条新边的环则要求 B 中存在 s→p 的路径，但目标核已有 p→s，因此与 B 无环矛盾。实际插入会删去旧 p→s；在证明图中保留它只是增加一条由 p→t→s 蕴含的快捷边，不改变无环性。首尾槽位省略相应新边，同理成立。

`src/q1/neighborhood.py` 的 `TaskOrderIndex` 实现上述规则。初始化用冻结官方代码导出并校验 Task 图；每个被选中的 Task 的传递集合按需计算并缓存。单个 Task 首次计算为 O(|V|+|D|+|C|)，目标序列扫描为 O(m)；缓存最坏可达 O(|V|²)，目前只在一次有提议上限的邻域生成中保留。实现为求清晰与可检验，仍会为首次选择的 Task 构造基图，尚未实现动态传递闭包。

缓存只适用于该固定 incumbent。一旦接受移动、改变任一核序列或分区，就必须重新建索引。计划始终保留 `node_to_subgraph` 的插入顺序；区间合法不保证内存、FIFO 展开或最终事件执行成功，所有候选仍交精确 evaluator 检查与计分。

## 可证伪检查

`tests/q1/test_neighborhood.py` 枚举四节点的 64 个前向 DAG、16 种双核分配、每个移动 Task、每个目标核及每个槽位，共 20,480 个位置判断。每个位置都与冻结官方 `derive_multicore_plan` + `validate_task_order` 双向比较，既检查漏放也检查误放。全部相符，Q1 整套八项测试通过。

这个有限测试不等同于穷举所有规模、分区或可合法核序；一般性依据是上面的图论证明。它也不是执行耗时模型的验证。

## 预先记录的有限对照

共 180 次精确评价均成功；四次 seed E0 和八次最终 E0 均成功，最终 makespan 与精确接口的选中值逐一一致。两方法总时间列不含共享的 seed E0、外层读图和归档，不能将它作为实验从启动到结束的完整墙钟。`generation_wall_seconds` 包括生成子进程启动与计划写出。

本轮选定计划相对输入 incumbent 的变化为：002 从 90582 到 88636；051 从 339956 到 338698；014 从 4543652 到 4537232；044 的 116227 未改善且仍有 76800 bytes spill。这些是公开正式 case 的本机开发成绩，不是合成机制反例，也不是封存集验收或全局最优值。

结论的具体范围：

- 051 的随机方法撞上 128 次提议上限，仅得到三个新合法方案；区间方法完成 31 个。本轮相同的是预算上限，实际评价次数不同，不能归因为每次评价的搜索质量更高。区间方法在该例总搜索时间反而更长，但生成时间更少、可评价候选更多。
- 014 两方法均找到相同最佳值；生成时间降低没有转化为本次端到端加速。精确事件模拟占据主要时间，16 MiB 缓存对过大的编译产物执行 bypass，不能据此声称所有规模都受益。
- 044 区间方法出现 87 次重复，说明消除非法槽位后仍会浪费抽样；这轮既没有新质量改善，也没有解决分区与内存问题。
- 两方法均使用批量生成子进程。与旧搜索器逐次启动提议进程的计时直接相比，会混入编排差异。本实验只支持当前两方法的有限对照，不支持完整自适应求解器的普遍加速倍数。
- 本批只对每方法最后方案做 E0 确认；180 次中间评价没有全部重复 full JSON 差分。之前 30 个候选的全量集成差分范围不扩大。

## 交付与复跑

核心代码为 `src/q1/neighborhood.py`，对照入口为 `src/q1/move_experiment.py`。候选、生成记录及未归一化的 E0 result/trace/log 按字节放在每例 `execution-evidence.tar.xz`，对应 manifest 逐项校验原文件 SHA-256。摘要、seed、最佳计划和实际运行源码快照直接可读。新目录的 `artifact_manifest.json` 校验提交产物；源快照及输入、配置、依赖锁文件哈希随摘要保存。

```sh
uv sync --locked
uv run python -B -m unittest discover -s tests/q1 -v
uv run python -B src/q1/move_experiment.py --output results/a/new-guided-moves --evaluator-root ../q1-exact-checkout
```

复跑 evaluator checkout 必须干净且处于上述固定提交。该入口会重新运行四例；输出目录必须不存在。当前仍是有用的固定邻域原型，尚未接入自适应搜索的每一步，也未完成多 seed、全 100 图或公平强基线验收。

任务六字段：目标为减少 A 的非法移动提议；输入为官方冻结图/配置、前轮已确认计划和固定批量 evaluator；输出为区间算法、证明、测试、四例配对结果和可提交计划；限制为固定分区/固定 incumbent/公开开发例；验收为位置判定有限穷举相符及八个最终计划 E0 确认；节点为可复用邻域交付，后续应结合重复抽样与大图事件模拟瓶颈决定怎样接入自适应搜索。本轮未修改 Q2 或 `src/eval_exact`。
