# 按 Pipe 的通用释放/尾部窗口下界

实现 `src/q1_yuanzhifang/window_bound.py`，来自本账号Pro最终回答§3.1的
已独立审阅公式。这里自行实现线段树，没有运行或复制Pro附件代码。

对同一种Pipe的操作i，令d为工作周期，r为开始时刻的通用下界，q为
**完成以后**仍必需的尾部时间下界。任意阈值a、b定义非空集合
S={i:r_i>=a且q_i>=b}。若整个合法方案结束于T，则这些操作的全部
执行均落在[a,T-b]，k核此Pipe容量最多k(T-a-b)，所以

`T >= a + b + ceil(sum(d_i for i in S)/k)`。

这不需要允许抢占；把非抢占排程放松只会削弱下界。r、q取忽略COPY、
等待、容量的保留计算DAG最长路径；q不含自身d，r也不含自身d。
去除COPY端点后**不跨COPY收缩**。不同Pipe分别求界后取max，不能把
工作相加再除k。不得用某个候选计划的gate预测冒充通用r或q。

只需枚举实际r、q坐标：阈值往上移动至最近的集合边界前，S不变且
右端单调不减。按r降序成组激活，维护q升序坐标上的 `k*b+W(b)`。
加入尾长q、时长d的操作时，q坐标前缀全加d；前缀最大值用带懒标记
线段树维护。查询仅到**已激活的最大q坐标**，否则空集的裸k*b可能
伪造过大的下界。每个操作一次前缀加、每个r组一次查询，O(n log n)
时间和O(n)空间；各Pipe规模合计n不超过V。

返回最佳a、b、集合操作数和工作量作为可直接重算的证据。这个资源
窗口允许工作在k槽分流，单独不必强于不可抢占的原始关键路径。
使用时与已证明的关键路径、屏障、DDR界**取最大值而非相加**；无
可达性、无实际方案输出、无E0预测或算法成绩声明。

初次验证是120个固定种子小实例与独立非空矩形直接枚举的完全相等
检查，并包括空窗口、COPY桥、不同Pipe和集中释放/尾部的反例。
本实现尚未进行全100图实证对照；没有新增solver/E0/E1/E2调用。
