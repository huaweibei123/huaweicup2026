# 分叉阶段与树前沿构造

Stage C由用户持续优化授权推进，参照队长Issue98评论5816591744的051具体结构提示，自行实现通用构造；不按case编号识别。队长正在做多sink独占后缀，本实现使用fork分段，写区独立。

## 构造

1. 使用官方收缩COPY路径后的计算DAG。给操作v定义阶段r(v)=max前驱u的(r(u)+[outdegree(u)>1])，源点为0。每条边阶段不降；若源为fork则严格增加。
2. 每阶段诱导图出度≤1，故为朝向sink的树森林。阶段内部收缩单入单出的串行链，保留原子链包；不是声称该收缩不损失性能。跨阶段依赖仍完整保留。
3. 自各树根维护前沿。若子树最大Pipe总工作量高于阶段最大Pipe工作量/(4k)，且有子链包，则把根链包加入共享尾部，暴露其子树；否则保留该子树。叶链包无论多大都不进一步切开。每个链包最多展开一次，没有计划空间搜索或评价选优。
4. 剩下的两两独立子树按最大Pipe工作量降序装入至多k个Task，按已有数据依赖释放和核序等待估算完成时刻，重复输入字节只破平局。尾部所有轻/重归约链包合为一个后置Task，分给估算最早完成的核。阶段与阶段内部两阶段按序投影到核链。

常数grain=4在评分前固定，来自在保留原子链的条件下提供装箱颗粒度；不扫描参数。这一阈值并非容量证明。估算不含DDR/实际FIFO，也不被当官方分数。输入tensor集合不会跨Task假定共享驻留。CLI为`python src/q1_yuanzhifang/fork_frontier.py GRAPH PLAN --cores K --grain 4 --config CONFIG --diagnostics JSON`。

## 结构论证与限制

如果同阶段的一个顶点有两个后继，原图出度至少2，则按定义后继阶段应严格增加，矛盾；因此每阶段出度≤1。DAG且出度≤1的底层无向图是森林，否则任意无向环会要求有向环或出度≥2。串行链收缩保持该性质。

根展开保留互不相交的完整子树，移走的节点构成每棵树朝向sink的上闭尾部。子树间无边，子树到尾部的边单向，尾部不会指向前沿子树。每个顶点恰好覆盖一次。所有跨Task边严格增加(阶段, 前沿/尾部)字典序，各核链也同样增加，因此联合Task图无环。官方derive与validator再检查覆盖与核序。

这仅证明结构，不证明内存可行、零spill、速度或质量。大尾部、阶段错齐、多Pipe队首、重复输入均可能退化。COPY桥只用于构造官方Task间依赖；不能据此给重建Task内部关键路径添加不存在的边。完整E0是最终合法/性能依据。

原子邻接形成后，阶段、森林与子树工作量线性扫描，堆展开与装箱排序O(p log p)，k≤5。缓存箱的释放时刻，避免每装一个包重新扫描整个箱；分箱约O(k(p+关联针数+包边数))，加最终官方validator成本。原始tensor生产者×消费者展开和COPY路径收缩另计，不把整个原始输入过程笼统称为线性。

## Stage D：前沿子树单独成Task的消融

C已证实重链+整体归约尾减少门控，但051大输入反复读取，且五核的较低门控被剩余运行开销抵消。D只改变前沿的Task颗粒度：`--frontier-tasks unit`令每个独立子树包单独成Task，并即时按计算+gate最早完成分核；归约尾仍每stage一个Task，链仍不切。默认`core`保持C构造。单包Task有望改变DDR就绪请求与内存依赖，但增加同核100周期门控；两种影响谁占优必须实测，不能据零评分时间线宣称已因果定位。

单包Task模式的跨Task数据边仍严格增加(stage, phase)，核序仅非递减：同一phase可以有多个前沿Task，它们之间不存在数据路径，仅各自核链有边。若有联合环，严格增加的边不能处在环上；剩下只能是同phase的单核链，也无环。这推广C的结构证明，但不建立性能/容量保证。

15项单测通过；新增64个四节点前向DAG×5核=320个单包模式联合传递闭包检查，重复fork-join夹具检查三轮共15Task、链不切与3个归约尾。没有增加官方调用。
