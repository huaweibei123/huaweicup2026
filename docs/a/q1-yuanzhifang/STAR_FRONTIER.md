# P1 结构守卫下的切链星式构造

算法 `q1-guarded-split-chain-star / twelve-four-fixed-tail-v1` 位于
`src/q1_yuanzhifang/star_frontier.py`。Stage F已以一次真实E0证伪其
在051/k5上改善Stage C的假说；负结果和构造仍保留。Stage E选择器未改。

## 来源、适用结构与自由度

构造来自本账号 Pro 会话最终消息 `4f80a045-b997-4521-8a49-8711b78c94a5`
的 §4.2，完整原件保存在 `AI chats/P1-fork-join-yuanzhifang/`。
证明由另一个已暴露研发上下文的会话审阅，不自称盲审；审阅固定提交
`bf297de872e6d1f8f420307ab13b332c31280938`。没有运行 Pro 的附件脚本。

五核构造仅在实际原图满足结构守卫时启用：串联 fork/join 轮次，每轮
12 条各4个同耗时 PIPE_V 操作的链，之后11个同耗时 PIPE_V 操作构成
完整二叉归约；前轮根恰好释放下一轮12条链。检查所有保留依赖、链内
前驱/后继、根边界、跨轮一致时长，以及去除 COPY 后的依赖与 COPY
收缩依赖是否完全相等。算法不读取文件名、case编号或既有成绩。
不满足守卫或核数不是5时，调用已冻结思路的 Stage C fork 构造。

首轮切两条链为2+2；后续轮切四条链为3+1、3+1、1+3、1+3。
固定核2承载独立归约尾，按轮次和阶段发出 Task。全部真实数据边和
核顺序边必须严格增加 `(stage, phase)`，另由未修改官方函数
`derive_multicore_plan` 与 `validate_task_order` 检查联合无环性。
最终输出只有官方允许的 `node_to_subgraph` 与 `core_schedules`。

## 理论值、复杂度与待证伪假说

模型 R 忽略 COPY/DDR/FIFO/容量，但保留所有重计算、归约和100/1000
Task等待。p=524、a=13、24轮时，构造首轮6483，后续每轮6959，
共166540周期、263个Task、94条重链内部切割边。
独立审阅支持全 R 下界163420；在“每轮11个归约全放一个不含重计算
的独立尾Task”的族 F 内，166540为精确最优。允许归约与重计算融合
的全 R 仍有3120缺口；这些数字均不是官方 E0 成绩。

构造只做一遍固定模板，无候选搜索。结构识别复用 Stage C 的线性图
扫描和确定性拓扑堆，时间 O((V+E) log V)、空间 O(V+E)；94个切口是
当前真实图的输出数量，不是枚举预算。程序自身仍需报告启动、读取、
构造、官方结构校验、诊断、合法方案写出及退出的完整墙钟。

真实051结构守卫已通过：24轮，重524、归约13；原图 SHA-256 为
`884e8b12ac1f7a9b569958909680e8c2f6055966a59c9f929ffd5cee48aae43b`。
证据见 `results/a/q1-yuanzhifang/analysis-20260924/star-guard-051.json`，
该次仅调用守卫，0完整solver/0E0。合成平衡树和梳状树1/2/24轮、节点
重编号、错误Pipe与额外依赖检查通过；合成图不是正式性能证据。

可证伪假说：更小的计算/等待时间能否抵消新增重链张量切口带来的
COPY和全局DDR队列成本。旧 Stage C 在051/k5的实测253856周期与约9MB
额外DDR作为已有比较原件；不重跑这个基线。新候选有可能退化，必须
保留失败/负结果，不能凭R的166540就上传为官方成绩。拟先冻结单个
051/k5的1冷solver+1外部E0预算。实际共享资源执行记录见下文。
