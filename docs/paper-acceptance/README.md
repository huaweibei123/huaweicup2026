# 论文验收台

将论文原文、2025参考样本、具体通过条件、作者交稿与独立复核放在同一页面。默认深色，支持浅色并记住手动选择。它与方案成绩台分别维护，不写算法、benchmark中央账本或作者稿件。

## 启动

从本分支仓库根目录执行，Python 3.10+，不需要新增Python依赖：

```sh
python3 -m src.paper_acceptance serve --port 8879
```

打开 <http://127.0.0.1:8879/>；语言定位在 `/?view=language&item=L01`。本地状态默认 `output/paper-acceptance/`，包含SQLite审阅记录、PDF页缓存和本机文件路径，不能提交到Git。可用全局参数 `--state` 指向仓库外目录。`gh` 用于本人GitHub身份与同步；已有Poppler的 `pdftoppm` 用于PDF预览。缺工具时明确显示错误，不假装页面已读。

当前检查点由 `catalogue.json` 中的完整提交与PDF SHA-256冻结。本机缺PDF时服务尝试从已取得的固定Git对象读取。可先取回作者分支，或注册本人持有的原件：

```sh
python3 -m src.paper_acceptance register current /path/to/anonymous-paper-v1.pdf
python3 -m src.paper_acceptance register ref1 /path/to/reference-1.pdf
```

参考论文依次为用户提供的“通用神经网络处理器下的核内调度问题”1、2，“NPU核内调度算法设计与优化研究”，“面向Davinci架构的NPU核内调度算法研究”。路径、页数和哈希见目录文件。没有重新公开分发参考PDF；每位成员使用本人已有原件，哈希不一致则拒绝登记。页码为PDF物理页码，参考样本奖项未独立核验。

## 页面

- **逐项验收**：26条结构、模型、实验、版式与交付要求，13条用户语言与句段标准（共54项，另含15项图件要求）。每条有当前问题、参考页码和更严格的通过条件。
- **人工实例 → 全文同类**：17个真实批注事件提炼为11类要求，显示原话、共同缺陷、避免误报的例子、具体发现与尚未检查的范围。页面与`/api/v1/annotation-workflow`同源。
- **新稿分章标注**：固定94dae源文的331块初审与谓宾专项，60条意见中8条不采用、52条待处理或解释；不把源文块数当通过句数。
- **旧稿全文逐句**：语言页默认显示源稿全部376条句子，可按章节和类型筛选。另列标题、表格、公式、实际图注、图内文字检查任务与不入正文的图稿说明，合计747个不同类型的检查单元。每项链接固定原件，全部从未审开始；枚举不等于已逐句检查或已找全错误。
- **语言逐处检查**：基于检查点01全部35页提取文本的610个候选位置，其中219处优先审改、391处术语待核。提供原片段、实际匹配位置、页码、处理要求与英文核查线索。候选数不是最终错误数；不是全文无遗漏的证明。栅格图内文字仍待逐图检查。
- **句子与段落**：语言页内可切换，22处原句/原段、语法与论证问题、具体改写要求。不是仅将中文简称扩成较长名词；每句须展开对象、关系、动作及条件。当前全文语言未通过。
- **原文对照**：两份真实PDF预览，独立翻页并可选择四份参考。支持直接打开原件。
- **图件审阅**：15项检查点一的论文页面保留原验收条目；画廊另登记Fang、farmer、LYX与验收台提交的56个PNG文件，归为32幅逻辑图。Fang明确选优或重画的版本排在最前；Fang新确认的图5-1和图6-1 A版与图4-2 A版置于优先序列，新制的第二、三问三图随后，标明“待Fang比选”；farmer原图5-1、5-2、6-1、6-2保留各自逐图审查状态；其中5-1与6-1已有Fang明确选定的美化版，仍待独立审核。统一以“图 4.1-1”式“章.节-序号”显示，改版与版面预览共用逻辑图号并另标版本。编号仅供画廊定位，论文最终图号由合稿核定；提交分支不等于逐图作者署名，图件仍待语言、数据、版本和版面审查。Fang图4-1对应旧v4算法，不能因显示在网页中便视为论文已采用。 v5整稿暂选四张图（第二问局部割、三方案、张量生命周期，第三问决策），先入稿供用户批注；v5已回填正式页码与PDF哈希；v6已发布固定PDF；v7已发布固定PDF，仅重写摘要，五处图页继续沿用；Fang新选的两张A版仍未入稿，科学验收另行核查。

队友图件清单在 [`team-figures.json`](team-figures.json)，Agent 可读接口为 `GET /api/v1/team-figures`。每条登记固定提交、原路径、Git blob SHA-1、文件大小及审阅状态；`GET /team-figures/<id>.png` 首次从固定提交取回原图，校验字节后缓存并以同站地址展示。源文件缺失或哈希不一致时不展示替代图。原文件名与来源链接保留，不重命名队友仓库文件。

v7全图与AI使用声明审阅以独立的[验收台导入副本](figure-review-v7.json)展示，Agent读取 `GET /api/v1/figure-review-v7`。副本记录20幅图、22份图件哈希和用户第28页批注的原话、两张截图哈希、无精确坐标状态及整理出的排版理解。原始审阅报告仍在论文组织任务本机写区，尚未以v7 PDF的固定提交发布；验收台副本的发布也不代表原报告已发布或意见已获人工接受。

- **团队与监督**：明确区分本机草稿、已发布共享记录、冲突、作者接手、新稿交付和验收。

## 多人同步

每位成员运行自己的本地页面和 `gh` 登录，通过 [Issue 217](https://github.com/huaweibei123/huaweicup2026/issues/217)交换结构化审阅。不是同一个公网网页，也不是无延迟协同编辑。每次点击“同步审阅”完整读取全部评论页；保存是本地草稿，点击“发布此条”才产生本人Issue评论。发布前还会重新同步，冲突后必须读新状态再追加意见，不覆盖别人记录。

接收者身份取GitHub实际评论作者。正文中的名字不能代签。标准允许的成员见 `catalogue.json`。通过必须有完整提交链接与逐项检查：作者 `ready` → 另一账号 `verified` → 队长 `accepted`。同账号的不同任务不冒充独立复核。编辑或删除已知原评论会使其失效，需追加更正。GitHub评论仍可被其权限持有人删除；这不是不可删除的永久审计存储。

变更论文或标准时，旧记录保留但不能承接旧验收。未知发送结果先按原ID回读，不盲目重发。服务只监听127.0.0.1，写请求校验Host、Origin和专用请求头；不开放外网账户服务，不提交凭据。

## 作者报告与后续监督

已收到的作者基线是完整SHA `e509c998ea5a3a0a8ceeb0ec59153c0b297ca133`，262条全部open。包含正文与不入PDF的图稿说明，按每条scope区分；只有确实定位者有pdf_page。导入：

```sh

```

命令直接读取固定Git对象，存原件哈希和自报记录，不运行作者代码，不改变验收。检查点02已冻结供批注；当前Antigravity负责人提交后续新稿时，验收维护者先读源文与PDF哈希，另建新检查点和旧新逐处映射；本轮界面不会用关键词消失代替语义复核。

用户补充标准 → 维护者更新条目和 `STANDARD_HISTORY.md` → 向当前论文组织任务发送具体要求 → 记接手与固定交付 → 对新稿逐条回读 → 把未解决项退回。验收台负责网站和候选图件；当前论文组织任务监督Antigravity执行语言标准，并负责图件的科学核查、选版和入稿决定，见[双向协议](COLLABORATION_PROTOCOL.md)。`handoffs.json`记录事实。页面自身不会调用Codex去控制写作任务，也没有未声明的后台轮询；实际沟通由本验收任务负责。
