# Stage C 轨迹与边界搬运复核（零评分）

输入固定于 `88e95e28f6b6fdfe7e4d0b91a7b124740dc5006a` 的 Stage C feed、plan、完整 result/trace/run；24 条记录的全部引用原件均逐字节比对该 Git 对象并核验 feed SHA-256，gzip 原始字节再次核对 run 中的 raw SHA-256。重点分析 051 k4/k5 新法，以及 008/071 k4 新法与 bounded 对照，共 6 个已有成功计划。016 超时记录只核原件身份，不推造结果。

分析代码固定 `7fe56bd2a1e8a86c5274762b45350097c019d446`，脚本 `src/q1_yuanzhifang/trace_c.py`。实际分析耗时约 1.80 秒，串行；0 solver、0 E0/E1/E2、0 Task compiler。没有导入算法或官方调度器，只有 JSON 读取、边界 COPY 元数据复原、区间统计和固定 Task 图最长路。原始实验与此分析的 CPU/时间成本分别保留。

## 核对方法与口径

- 官方 P1 源码 `_build_scene_a_tasks` 的边界判定及 ID 分配规则用于静态复原 `(Task, COPY op) → 原 tensor/方向/字节`，不运行 Step1/2/3。6 个计划的官方 spill 均为 0；复原 COPY ID 集合与 `ddr_contention_log` 的 issued 集合逐项相等，字节总量、原始 COPY 字节和 partition-added 均与官方原结果相等。
- result 的每个 op 起止、核、Task 与 trace 的对应事件全部一致。原始 compute op 的实际 duration 与 `max(1, cycles)` 相等。
- Task release 按 `max(前核链 Task end + 100, 各跨核前驱 end + 1000, 各前驱完成)` 重建；没有同核前项时对应项为 0。前驱数量不产生等待求和。6 个计划的所有 Task 均精确满足 `start == release`，没有另加无法解释的 Task 激活延迟。
- `tasks.csv` 和逐计划 JSON 的 `tasks` 给出每 Task 的 release、绑定约束、核间空闲、纯 V 工作、各 Pipe 工作、官方 local_makespan 和实际 duration。JSON 的 `stages` 保留每阶段的全部 frontier/tail 起止与时长。071 的相邻阶段可能重叠，不把 stage 编号当全局 barrier。
- 用同一个固定 Task/核链图分别代入三种 duration：各 Task 最大 Pipe 纯计算工作、原件内 official local_makespan、原件实际 duration。最后一种逐 Task 复现实际时间线；前两种是描述性时间模型，不是重新评分，也不自动是官方结果的上下界。

## 051：201344 为什么变成 254308

固定 k4 计划的计算量模型精确复现构造器 diagnostics 的 201344：实际最长 Task 路径上，纯 V 工作 154344，加 gate 47000。将这条路径的实际 Task duration 拆成已有数值，得到恒等式：

`254308 = 154344 + 47000 + 14399 + 38565`。

其中 14399 是该路径 `Σ(local_makespan − 纯 V 工作)`，38565 是 `Σ(实际 duration − local_makespan)`。本例三个 duration 模型的最大值差也恰为 14399 和 38565。这是固定路径/固定模型的加法核对，不能把 14399 唯一称为边界开销，或把 38565 唯一称为 DDR 竞争因果效应。

24 个阶段中，k4 每阶段 4 个 frontier Task，每个纯 V 工作 6288；尾 Task 纯 V 143，local/实际均 146。

| k4 阶段 | frontier 起点 | frontier 实际 duration | 尾部 start / end | 阶段进展 |
|---|---|---|---|---:|
| 0 | 全部 0 | 全部 8672（local 6884） | 9672 / 9818 | 9818 |
| 1–23，每阶段相对上一尾 end | 核0 +100，核1–3 +1000 | 核0 6837，核1–3 8484（local 全部 6885） | +10484 / +10630 | 10630 |

所以 `9818 + 23 × 10630 = 254308`。长期步长 `10630 = 1000 + 8484 + 1000 + 146`；它明确包含远端重启动、较晚 frontier 完成、归约入门和归约实际执行。逐阶段绝对时刻在 JSON 中，不从 trace 猜操作 readiness。

静态原图+计划揭示最主要搬运来源：12 个 32768-byte 原输入 tensor，每个恰好进入 24 个不同 Task。外部输入共 `12 × 24 × 32768 = 9437184` B；相对每个只装载一次的重复量为 **9043968 B**。k4 额外分区总量 9045350 B 中，仅剩 1382 B 是其他边界净增量；spill 为 0。另有 2-byte 计算产生 tensor 在消费者 Task 间重复输入 138 B。这里“重复”是静态边界出现次数，不表示 P1 可以在相邻 Task 间直接复用私有缓存。

## 051：k5 为什么几乎没有继续加速

每阶段仍有 12 条不可再切开的 2096-cycle 原子分支。k4 为 `3/3/3/3`，k5 为 `3/3/2/2/2`，最重 Task 纯 V 仍是 6288。因此第五核没有降低阶段的最大原子包计算负担。

k5 的实际最长路径仍累计纯 V 154344、local-minus-compute 14399；gate 从 47000 降至 26300（少 20700），但 actual-minus-local 从 38565 增至 58813（多 20248），净减少 **452 cycles**。

| 项目 | k4 | k5 |
|---|---:|---:|
| 第一阶段 end | 9818 | 10815 |
| 后续每阶段进展 | 10630 | 10567 |
| 最大 frontier 实际 duration（后续阶段） | 8484 | 9321 |
| 后续主路径 gate 合计/阶段 | 2000 | 1100 |
| 全局 DDR busy | 158228 | 158251 |
| 全部 COPY elapsed 求和（有重叠） | 508162 | 621767 |

k5 第一阶段慢 997，随后 23 阶段各快 63，故 `−997 + 23 × 63 = 452`。后续归约核交替为两个重载核，使关键路径 gate 每阶段少 900；同期晚启动的重 frontier duration 多 837。DDR 服务工作量几乎没变，但请求并发形态变了，实际 duration 的增长由轨迹直接可见。仅凭这些起止事件，不能唯一分离 FIFO、局部依赖、全局 DDR 与释放偏移各自的反事实贡献。

## 008：主要不是 1000-cycle 门控，也不是重复权重

新法 3 个阶段共 12 Tasks，实际关键路径只有两条同核 100-cycle 门，合计 **200**；没有把多个远端门累加的情况。外部输入总量仍是 1990872 B，所有输入 tensor 的“多 Task 重复载入量”均为 **0**。

新增搬运来自 **216 个 18432-byte 中间 tensor 各做一次 COPY_OUT + 一次 COPY_IN**，即 `216 × 18432 × 2 = 7962624` B。完整组件被阶段切开，原本 Task 内部的中间值变为 DDR 边界。

新计划 DDR 服务需求 177660 cycles，占实际 Makespan 179018 的 **99.2414%**；基线为 44604 / 123060（36.2457%）。按照官方单共享 DDR 服务池，固定新计划仅这批边界 COPY 的服务工作量就超过基线 Makespan。因此，保持这套分区且不减少这些 COPY 时，即使计算完全不成为瓶颈，也无法赢 123060；需要改变分区，而非只调 Task 启动次序。这个约束针对固定计划，不能推广到任意 008 算法。

另一个同步损失信号是计算量模型从 62532 升至 86546：阶段分别限制不同 Pipe 的工作窗口，最大 Pipe 工作之和增长。但 new local 模型反而从 122133 降至 94757；最终全局实际却从 123060 增至 179018。这足以否定仅按 local 编译时长选方案的通用保证，不能把全部差额归给单一因素。

## 071：细阶段收益不足以支付边界与等待

bounded 是 1 Task，实际 18919；新法是 12 阶段、45 Tasks，实际 20194。新法实际最长路径上，最大 Pipe 计算工作 6531，门控 6700，local-minus-compute 4113，actual-minus-local 2850，合为 20194。门控与路径计算量同量级。

总 COPY 从 121446 增至 725242 B，DDR busy 从 2045 增至 12438 cycles；新增全部来自 partition，spill 仍为 0。外部输入重复 53876 B，计算产生输入在多个 Task 重复 119008 B。其余增加来自中间值出入 Task 的边界存取，而非每一字节都是“同一 tensor 反复读”。这些数量描述新分区付出的代价；未做消融重跑，不能断言其中某项单独造成 1275-cycle 回退。

**local_makespan 不是这里可用的实际时长下界。** bounded 的单 Task local=23716，但全局实际 duration=18919，差 **−4797**；没有其他 Task 可被归因为跨核竞争。051 k4 核0的稳态 frontier 也为 local 6885、实际 6837（−48）。因此 actual-minus-local 有正有负；分析保留原值，不裁成 0，也不称其为纯竞争开销。具体内部调度语义差需要另做源码级核查，不能由本轨迹唯一解释。

## 对下一构造的具体反馈

1. 为阶段划分加入静态边界 COPY 字节和 `Σceil(bytes/60)` 服务需求，特别保留同一中间 tensor 跨 Task 的出入对；008 已给出固定分区无法赢基线的直接约束。组件完整性与 Pipe 混合窗口值得保留。
2. 051 不能把理想 `总工作/k` 当可实现阶段时间：原子链打包的最大负载及共享 DDR 服务没有随着 k5 下降。下一方案应明确改变最重原子包、释放/归约位置或边界重载中的至少一项，而不是机械多开一个核。
3. 051 的大额重复原输入与 071 的细粒度门控提供合并/更粗分解的动机，但 P1 的 Task 整体释放、容量和联合无环仍须满足；不能假设跨 Task 的输入缓存自然复用。本分析不给未实现候选保证收益。
