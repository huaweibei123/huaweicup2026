## 已核对的正确性

- `dominant_percent` 排除 bool/float/越界值，80% 使用整数交叉乘法。补充
  witnesses 确认恰好80%激活、79%回退；零 cycles 使用 max(1,cycles)。
- 组件按官方 COPY 收缩计算 DAG 的无向连通分量计算；跨 COPY 路径未丢失。
  fallback 的嵌套诊断路径与当前 sink→bounded→frontier→component 结构一致。
- 单核、组件不足、无主导组件、无可用后缀并行、剥离预算失败时完整返回
  旧 plan，没有半成品分区。80%不是收益证明，源码/文档未把它写成收益保证。
- 后缀分包给每条跨包依赖严格递增波号；其余**完整弱组件**没有与重组件或
  彼此的计算边。并入末波不会使内部路径跨 Task；不同 Task 的核序也严格
  增加波号。因此增广 Task DAG 无环；实际逐边断言与官方结构验证一致。
- 每波负载归零用于局部贪心，不参与合法性证明。共享输入可跨组件，弱连接
  为空不表示 DDR 访问独立。
- 文档的整体 O(n log n + Kn + R(n+e))（R≤64，位宽≤64）覆盖主要新工作；
  现有 fallback 和官方 COPY 收缩/验证重复开销已另列，没有虚称整个求解器
  为线性。末波可有多于64个完整组件包：64限制的是重组件剥离的 sink宽度，
  不是整个最后一波包数；这不违反正确性或最终≤KR个Task的界。

## 可证伪质量盲点：其余组件可能在另一 Pipe 很重

位置：`heavy_suffix.py:61–68`、`:85`、`:96–101`。

默认守卫只约束全图最大工作 Pipe 的份额。一个组件垄断 V，不代表其余组件
在 M 上很轻。“minor components”是“其余组件”，不应被解释成小工作量保证。
另一方面，每波 `loads` 重新清零，末波首包倾向 core0，忽略 core0 已执行的
长前缀与其他核是否从未占用。

合成图（4核）：

- 重组件：`V10000 → {V40000, V40000}`；两条边各经64 B UB tensor。
- 其余三个独立组件：`M89000`、`M1`、`M1`。
- V总工作90000，大于M总工作89002。重组件拥有100%的V工作，因此合法触发。
- 实际构造把V10000单独放core0前波，然后把M89000放core0末波；两V后缀去
  core1/2，两个M1去core3。源 plan 已保存。
- 因同核 Task 等待固定100，当前合成 plan 的官方必要时长下界为
  `10000 + 100 + 89000 = 99100`；root边界COPY只会进一步延长这个下界。
- 另一份结构合法 plan 把三个独立M节点放core3第一Task，root在core0、两V
  后缀各在core1/2。独立M工作即可与重组件前缀重叠。

**89002 不是这里证明或测得的官方 Makespan 上界。** 它只是替代资源序在
compute-only 简化模型中的完成值。P1实际还有跨核1000等待和两条边的边界
COPY_OUT/COPY_IN；虽然字节很小，本轮没有 Task 编译或逐事件验证，不将
其省略成精确官方U。JSON的 alternative_official_makespan 与 upper_bound
均为 null。该例确认可避免的资源串行关系，不声称已测官方性能反例。

最小后续改进建议（不在本轮修改）：

1. 先把文案改为“其余组件”，诊断保留它们的完整Pipe向量，不把dominance
   当作其余工作总量小的证书。
2. 针对“无前驱的其余整包”，优先考虑此前未使用的核，或一个独立早期Task；
   更一般可把累计前缀工作加入选核代理。保留旧候选与完整E0比较，因为该
   代理仍不是官方时间预测，而且新Task可能增加等待/复制。
3. 如果将其余包并入重组件的早期Task，必须另评估是否延迟远端输出；本例
   的备选是独立Task，不能以该例证明任意早合并都安全且有益。

这不要求热改正在运行的049/088两格。两图其余组件是否形成实际尾部、以及
新增DDR/FIFO代价，依赖该冻结run的真实原件，不能由合成小图替代。
