`component_envelope` 以整个组件为分核单位，`direct.Index.assignment` 首先分配巨型组件。2–5 核时，其余组件的总量远小于巨型组件，因此巨型组件留在 core 0，其他组件进入剩余核；`_merge_heads` 对单个组件原样返回其自然拓扑顺序。增加核数不能拆开这条主计算 FIFO。

可证伪机制：检查既有 2–5 核结果中巨型组件的 owner 与 M/V 计算序列，预期一致。额外核只加速小组件，且它们的 COPY 可与主核共享 DDR 服务，导致总 Makespan 略变甚至略差。这是**当前固定构造**的结果，不能推出“增加核预算使全局最优值变差”。精确重现 1.094–1.095 倍平台需要既有官方结果/timeline 对照，本目录没有重新评分或把静态推断当成实测归因。

### 不是已经证明的带宽或 spill 极限

外部输入加最终输出仅 221,600 B；除以 60 B/cycle 为约 3,693.3 cycles，按每条 COPY 单独向上取整的理想服务量合计 3,872 cycles。作为比较，5 核的纯 V 工作量界为 49,191 cycles，而巨型组件固定 FIFO 已需要至少 253,026 cycles。该数量级不支持“不可避免边界流量解释当前平台”。这里的服务量是理想诊断，未将浮点事件器的服务量换算提升为严格官方 Makespan 定理。

巨型组件整个生命期触及 L1 1,512,224 B、UB 3,712,692 B；**总触及量不是峰值**。其现有自然顺序的 original touch 峰值实际只有 L1 39,008 B（op 249）、UB 73,744 B（op 7646），均低于配置 524,288 / 131,072 B。

这些区间从原计算第一次触及到最后一次触及，遗漏插入 COPY 的生命周期与运行时跨 Pipe 重叠，**不是 runtime 容量证书或零 spill 保证**。同样，统一算法中 `component_envelope` 路线的整体 spill 总量不能直接归因到 056，需查看 056 本身的归档结果。

## 结构建议：完整 attention row 分核，保留跨阶段归属

既有静态解剖显示，巨型组件主体是 6 段重复的 9-token 结构，可从 Q/K/V 的 tensor incidence 识别：每段 9 条 row，每条有前置归一化、3 次 QKV 投影、注意力归约与逐 token 后处理。每阶段为 9×134+6=1,212 个计算；6 个额外操作是 14-cycle 条件投影。最终标量归约与其他小尾部另行保留依赖。

| 每阶段 row 类型 | 数量 | M work | V work | 单 row 原 touch L1 / UB |
|---|---:|---:|---:|---:|
| 较大 token | 6 | 2,720 | 4,774 | 10,752 / 17,474 B |
| 较小 token | 3 | 1,504 | 3,066 | 5,632 / 8,738 B |

具体证据：首 row 的 norm 为 ops 38–47，QKV 为 128–130，attention 为 155–258，post 为 1091–1107；第二 row 分别为 48–57、131–133、259–362、1108–1124。QKV 的输出如 `1000000158/159/160`，分别有 9 个消费点。上述 ID 范围只用于核查本次结构解剖，**不得写成求解器里的 case ID 或操作 ID 分支**。通用解析脚本不自动宣称识别了这一特定模板。

输入复用发生在这些 row 内部与 row 之间，而不是 19 个组件之间。每阶段 18 个 K/V 向量共 15,360 B（12×1024+6×512）；QKV 三套合计 23,040 B。另有阶段权重、跨阶段残差和少量全局标量。单 row 的 touch 峰值仍包含它触及的 K/V 输入，并非已扣除共享输入的纯 private 峰值。

建议的直接构造规则是：

1. 从真实 tensor 生产/消费与重复结构识别 row、K/V 共享组、阶段和残差归属；保守拒绝不符合的结构，返回统一算法既有路径。
2. 按每 row 的 M/V 工作量作确定性的负载分配，完整 row 固定在一个核，跨 6 阶段沿用归属，使残差保留本核。
3. 每核优先生产自己所有 row 的本阶段 norm/QKV，再以完整 row 的优先顺序处理 attention 与 post。只分发跨核复用的 K/V，以及必要的小共享量，避免细粒度任意切边。
4. 保留末端真实 scalar DAG 与小组件的依赖，用统一方法处理，不删除、重算或合并官方原操作。

若 m 个核都处理 query row，且每个 K/V 必须服务所有这些核，则 K/V 跨核 COPY 字节为每阶段 `2(m−1)×15,360`，6 阶段 m=5 时为 **737,280 B**。这已明确引入额外 DDR；还需另计权重重复输入、条件量、尾部及 spill。按 COPY 向上取整的理想 K/V 服务量每阶段为 `540(m−1)` cycles，即 m=5 时 2,160 cycles。500-cycle 延迟可并行重叠，不能简单按每条边相加成 Makespan，也不能预先宣称其被完全隐藏。

### 必须通过的约束与尚未验证项

- 每个原计算恰好保留一次且只有一个 owner；共享输入只能复用/复制，不能偷偷增加重算来改变工作量。
- 局部生产先于消费。每核先完成 owned QKV 的优先安排，用于避免各核先等待外部 K/V、却把自己的 K/V 生产排在后面的 FIFO 环；完整 COPY 与 memory 图仍需审查。
- 容量核查必须包含整套保留 K/V、阶段权重、跨阶段残差、可能重叠的 row scratch、插入 COPY 输出及 spill incarnation。原 touch 小于容量只能说明值得尝试，不能保证 runtime 可行。
- “完整 row 优先处理”不是用户可提交的强制运行屏障；P2 接口只有切分、分核、每核子图顺序，各 Pipe 仍可能并行。
- 尚未实现识别器、生成候选、检验跨核合法性、复现性能或证明改善。这里不主张最优，也不承诺固定加速倍数。

## 成绩认定与下一步边界

用户只认**固定统一算法在完整用例/核数矩阵上的成绩**。建议若被实现，必须通过输入结构识别进入统一算法，使用相同规则处理全部图及 1–5 核；保留确定性的非适用回退，冻结新源码后再按统一协议全量验收。不能按 056 的 case ID 手选分支，不能用这一张图的定制结果替换统一算法的某一格，也不能用理论诊断当性能数据发布。

根会话负责是否开展有界机制核验、实验来源注册及后续全量验收；本目录没有新增实验预算或运行任何评价。归档脚本的汇总已与此前静态诊断的关键计数、峰值、输入共享和 FIFO 数值逐项核对一致。
