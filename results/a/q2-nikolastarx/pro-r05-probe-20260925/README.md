# R05 第一项真实图机制验证（003，2 核）

固定源码 `1ff472bc60db45069c588280bef52826ed1e0385`；修复测试入口后的 runner `ab26bd4fd`（完整 SHA 见 protocol-v2.json）。输入、官方源码、seed/witness 与求解源码均按哈希核验。没有修改官方代码。

一次构造处理 11,123 个 packet、5,585 个 ready 批次，802 个 packet 改变位置。未返回的重构方案 COPY 字节代理从 6,351,422 降至 5,207,554（约 -18.0%）；同一静态时序代理从 230,838 增至 241,374（约 +4.56%）。默认全局代理保护返回 seed，`verification.json` 已核对返回方案与 seed 结构完全相等。因此本实验不构成官方 Makespan 改善；代理拒绝也不证明原候选的官方成绩必然变差。

构造本身 1.458 秒；进程端到端墙钟 2.464 秒，包含监控器的观测峰值 RSS 171,229,184 字节。预算 30 秒 / 512 MiB / 一次构造，无 E0、E1、E2 调用。性能值只覆盖本次机制测试，不是完整在线求解时间。

`process/` 保留第一次入口导入失败：错误地从 direct 导入 read_evaluation_config，0 构造、0 评分。修复入口并先做仅导入检查后，使用新目录 process-v2 与 run-v2 完成第一次实际构造；未覆盖失败日志。protocol.json 与 protocol-v2.json 分别记录来源和预算，constructor-started.json 记录实际调用边界。

当前返回的是受保护 seed；未返回方案仅有构造元数据，其原始方案未保存。后续若验证被静态代理拒绝的方案，应使用显式实验入口并独立冻结，不降低默认保护、不把代理当官方证书。R05 未合入主线 c665 的全量 solver。
