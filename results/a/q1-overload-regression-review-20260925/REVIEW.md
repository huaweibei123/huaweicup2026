# overload18 封存结果的静态退化审计

**结论：没有找到可证明保证改善的通用 guard；下一项最小机制实验应只分离 retained 合包的“就绪优先级”和“执行时长估计”。** 031/077 有直接的整包优先级膨胀证据，032/057 的小幅退化涉及新增 gate 与 COPY，068 则是末段 Task 串行化；不能用一个“初始占满核”标签解释全部退化。

本报告不是新成绩。constructor、Task compiler、E0、E1、E2 调用均为 **0**；不运行或导入求解程序。所有 M、Task 时刻、spill 均取自既有封存原件。新的计算只有原图静态求和、固定计划 Task 边界重建和 DAG 最长路径。

## 1. 哪些量是下界

冻结源码出处均相对 `data/raw/a/official/`，读取字节亦在收据中：

- `code/schedule_step3.py:29–33`：四个 Pipe，每核每 Pipe 一个在飞操作；`:74–92`：普通操作 `max(1, cycles)`，COPY 按大小取整且只有 DDR 端点进入共享带宽池。
- `code/multicore_cut_evaluate_problem_1.py:111–159`：**每个 Task 的全部输入/输出边界** 插入 COPY；同核跨 Task 同样有边界。输入为本 Task 有消费者且无生产者；输出为本 Task 有生产者且存在原 COPY_OUT、无 compute 消费者或存在 Task 外 compute 消费者。不能只求跨核边权，更不能无条件求原图所有 COPY 的总和。
- 同文件 `:240–280`：全部核共享 DDR 服务；`:318–329`：Task 必须等全部数据前驱完成；前一同核 Task 结束后加 100，远端数据前驱完成后加 1000，同核数据前驱没有额外的 1000。

令 `w(t)=max_p sum_{u in t, pipe(u)=p} max(1,cycles(u))`。本批 compute 只有 M/V，且确认 COPY 收缩没有新增 compute-to-compute 桥边。原始 compute CP 仅沿保留下来的直接 compute 依赖算，不把 COPY 收缩路径冒充操作级完成依赖。

固定方案的 Task 增广 DAG 包括数据边和相邻 core 序边。数据边 lag 为远端 1000、同核 0；相邻 core 序边 lag 为 100；重复边取较大 lag。

- **G**：该 DAG 以 `w(t)` 为节点权的最长路径。是**固定切分、分核、核内序**的必要下界，不是所有合法方案的全局最优下界。
- **D**：逐 Task 枚举上述完整边界，每次 COPY 服务 `max(1,ceil(bytes/60))` 的总和。共享 DDR 总服务率不超过 1，所以 D 是该切分的必要下界。逐次向上取整，不能把总字节一次除 60 替代它。这里不计新增 spill；因此也不假定当前 spill 可消除。
- **F**：每 Task 权重改为 `max(w(t), Task内原computeCP, Task边界COPY服务)` 得到的最长路径，再与全局 D 取 max。F 是同样固定方案的稍强下界。
- **max(G,D)** 合法，**G+D 不是下界**。计算、DDR 可重叠，相加只是一项经验代理。
- 用**实测 Task duration** 替换节点权，最长路径可精确重建本批所有 Task start 与 Makespan。这是对已经发生的运行的分解；换序、换核、合包会改变 duration，不能冻结它们推演新的官方成绩。

边界字节求和 18/18 等于官方 `original_graph_copy_bytes + partition_added_copy_bytes`。这验证本批重建的字节身份，不把该等式本身当成一般性正确性证明。

### 031：次要 Pipe 触发拆分，保留组件合包抢占全部核

全图 M 工作 1334492、V 工作 221025。唯一拆分组件 anchor 3624 的 M=54972、V=57584，只在 V 上超过均分阈值；它被拆成 8 波、35 个 Task。其余 106 个组件合成 5 个 Task，单组件最大 Pipe 工作仅 17160，但整包权重为 253972–257400。

拆分部分 data-only compute tail 只有 19258。当前 ready list 按整包 tail 排序，前 5 次 placement 全是 retained 包。五核从 0 全部执行 retained，结束范围 258776–286726；最早 split Task 到 260325 才启动。实测最长链是 `36(retained) → 0 → 1 → 4 → 5 → 9 → 12 → 14 → 18 → 22 → 27 → 31`，其中 Task 36 自身持续 286726，随后还有 6500 gate。

相对旧最坏链，新链 Task span 和增加 12546，gate 增加 6500，两者合计恰为退化 19046。这是描述性恒等式，不是声称重新安排能消除全部 19046。spill 反而少 328704 字节，说明“spill 减少”不能单独保护质量。

### 032/057：微小计算收益不能覆盖 Task 边界

032 拆 anchor 398 成 2 波、8 Task；其余 24 组件装成 5 包。其中单 sink 的 anchor 1346 有 V=9510，保留整组件已给固定 floor 9510。新最坏链 `9(retained,6674) → 1(892) → 3(1040) → 4(1133)` 加 gate 1200 得 10939；相比旧链 Task span 和反而少 676，gate 增加 1200，净退化 524。

057 拆 anchor 64 成 2 波、8 Task；其余 20 组件装 5 包，保留单 sink anchor 1489 的 M=10080。新最坏链 `11(retained,10178) → 0(1406) → 1(1406) → 4(2546)` 加 1200 gate；Task span 和少 1002，净退化 198。G 仅改善 200，完整边界 DDR 服务却增加 1980。不能从两数相加推因果，但足以说明 compute 代理的收益很薄。

这两图的新前 5 Task 也全是 retained，不过它们包内单组件本来就比 split tail 大：032 split tail 1881、包内最大值 2474–9510；057 split tail 3155、包内最大值 4260–10080。下文仅消除合包优先级膨胀的候选可能不解决它们。

### 077：同类初始阻塞，加上更长边界路径

拆 anchor 10，2096 个 compute，M=82458、V=52446，仅 V 超载，形成 8 波、33 Task。40 个 retained 组件成 5 包，前三类大包权重到 72100，而最大单组件为 28840。拆分部分 tail=20602；5 个 retained 包的单组件最大值分别 28840、27327、14420、14420、14420。

最早 split Task 到 87536 才启动；新最坏链从 retained Task 37（span=87436）出发，后续 gate 合计 7500。Task span 和增加 11913，加 gate 7500，恰为退化 19413。新增完整边界 1077514 字节，无 spill。这支持针对 ready 优先级的独立消融，不足以证明延后 retained 必然更快。

## 3. Guard 的样本内反例

以下全部以真实 fallback 为基准；本样本共 13 改善、5 退化。它不是留出的泛化验证集。

|拟拒绝信号|抓到的退化|漏掉的退化|会误拒的改善|
|---|---|---|---|
|初始 5 核全是 retained|031/032/057/077|068|053/087|
|G 不下降|031/032/068/077|057|040/087/088|
|max(G,D) 不下降|031/032/077|057/068|040/087/088|

`G+D` 在此表接受的 9 项恰好都改善，只能作为下一轮的经验信号：它同时丢掉 4 项有效改善，不是定理，也不能据这 18 项宣称泛化正确。

- **040**：保留单 sink 组件给 G=94057，新旧不变；D 从 16555 增至 32052，但 M 从 110337 降至 94410。强保留组件 floor 并不意味着其他组件没有优化空间。
- **053/087**：初始同样全是 retained，仍分别 492699→417165、886373→869315。初始占核不是充分退化条件。
- **087**：G 从 722700 增至 741475，D 从 215819 增至 419028，M 仍改善 17058；spill 从 6566400 降至 4866048 字节。该事实否定只看 G/D 的保证，但不能未经反事实实验把全部改善归因于 spill。
- **068**：D 恰是 max 代理的主项，降低 11 使 max 代理略改善，官方 M 却增加 2190；aggregate bottleneck 忽略时序交叠。

## 4. 下一项最小机制假设：只改 retained 的 ready 优先级

候选定义，不在本次实现或评分：

1. 保留当前 Task 分割及成员、两字段输出合同、固定 gate、预算与失败 fallback。
2. 现有 split Task 的 ready priority 继续使用 data-DAG compute tail。
3. 对由完整独立弱组件组成、无外部 compute 数据前驱/后继的纯 retained bundle，ready priority 改为 **包内最大单组件 Pipe floor**。单组件包因此不变。
4. **择核 EFT 的 duration 仍用原整个 Task 的 max Pipe 工作**。不得把 priority 值当成时长，否则只是隐瞒负载。
5. 仍只从 ready 集合取 Task，追加到核序；所有 data/core 边沿同一严格递增 placement rank，原联合无环证明继续成立。输出边界 COPY 集不变，Task 映射到核及服务时序可变；固定流量并不保证相同 spill。

这项变化直接检验 031 的 `19258 > 17160` 与 077 中三包的 `20602 > 14420` 是否能让重组件分支更早启动。它没有改变资源总工作，也没有给任何核永久保留名额。新增部分只需一次组件工作聚合和 retained 元数据，O(V+E)，不改变现有构造的渐近复杂度；ready heap 为 O(T log T)，EFT 择核连同每核检查前驱为 O(K(T+E_T))，其中 E_T 为 Task 数据边数，另有既有确定性遍历排序的成本。

如获独立实验授权，建议仅一个固定候选，031/077 为目标、053/087 为必要的正例保护，记录首 split 开始时刻、G/F、完整边界校验、spill 与官方 M；不因代理变好扩批。若首 split 提早而 M 不改善，便否定“只需解决启动优先级”的充分性。032/057 预计不具同样的优先级翻转，068 属另一尾部机制，均不宣称这项候选能一并解决。

### 暂不应尝试的简单修法

- **无条件为 split 永久保留一核**：031 retained 的 M 工作是 `1334492−54972=1279520`。若它们始终限于剩余 4 核，则仅该资源下界便达 `1279520/4=319880`，已高于旧 M=306213；这种限制直接排除了击败旧方案的可能。暂时先排一个 split Task 与永久专用核不是一回事。
- **每个 retained 组件都单建 Task**：031 从 5 包变 106 Task，仅完整输入复用损失就静态增加 6845952 字节边界、115093 服务周期；087 则增加 17556480 字节、293370 周期。此处只算边界差，没有生成新计划。为提早一个分支而放弃全部输入复用，代价可能远大于 gate。
- **直接以 G+D 做“保证不退化”开关**：上表有四个既有反例，且其本身不是下界。
- **把差额称为 DDR contention**：`actual duration − local duration` 混合了 FIFO、时序、数据与内存门控等因素；本报告未用这种残差作因果归因。

## 证明范围和未做事项

已证明的是固定 Task 图的下界、priority-only 改动继续满足增广 DAG 的结构合同，以及永久四核限制在 031 上无法超过旧成绩。已核对的是封存原件身份、18 项全部边界字节、代理 G、Task 最长路径和五项 trace 的原 compute 时长。未证明的是新优先级收益、任意 guard 的泛化正确性、最优性、无 spill 或容量可行；未执行新构造、编译或评价，不新增方案成绩台实验记录。
