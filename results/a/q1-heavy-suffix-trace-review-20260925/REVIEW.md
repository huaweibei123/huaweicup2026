### 下界构造与证明

对 Task `t`：`P_t` 是各 compute Pipe 总 `max(1,cycles)` 的最大值；`D_t` 是该 Task 所有边界 COPY 的 `max(1,ceil(bytes/60))` 之和；`C_t` 是本地原始 compute 依赖与边界 COPY 依赖构成 DAG 的最长路，普通 op 权重同上，COPY 用独占服务。设 `b_t=max(P_t,D_t,C_t)`。

`P_t` 因每核每 Pipe 一槽必需；`D_t` 因全局 DDR 总服务率为 1，且该 Task 的 COPY 全部在其 Task span 内执行而必需；`C_t` 只删减了内存依赖等附加约束，因而是放松下界。两格 spill 为 0，并逐 ID 核对重建 COPY 集合恰好等于 trace 和 DDR issued 集合，字节和等于官方 scheduled COPY bytes。没有调用 Step1/2/3。

在宏 Task DAG 中加入官方数据依赖与每核相邻 Task 边：跨核数据依赖 lag=1000，同核数据依赖 lag=0，核链边 lag=100，多条同向边取最大 lag。`max(sum_t D_t, longest_path(b_t))` 是固定分区/映射/顺序下界。

进一步从 trace 恢复各 Task 的各 Pipe 执行顺序，在本地 DAG 上加入相邻同 Pipe 边，得到 `F_t`；用 `max(b_t,F_t)` 替换 `b_t` 得到固定 FIFO 下界。官方运行时只推进既定 `pipe_ops` 的 cursor，不按 DDR 竞争改变 Pipe 队列，所以 trace 序列可作为该固定编译结果的顺序证据。**此约束不可移植到重新切 Task、改 ID 或重编译后的计划。** 未在 trace 中出现的额外跨 Pipe 内存依赖没有猜造加入。

精确源码（均来自上述封存提交；本地字节已逐一比对）：

- `data/raw/a/official/code/schedule_step3.py:27–30`：`PIPE_SLOTS=1`；`:74–92`：duration 与 DDR 端点条件。
- `data/raw/a/official/code/multicore_cut_evaluate_problem_1.py:86–164`：ID 分配、Task 边界条件及 COPY；`:238–279`：共享 DDR 服务推进；`:281–316`：固定 Pipe FIFO；`:318–329`：Task release；`:390–408`：发射与 DDR 原始工作。

用各 Task **实际持续时间** 替换 `b_t` 后，宏 DAG 重建每个 Task 的 start，逐一恰好相等，并重建最终 Makespan。因此未发现 Task 已满足全部 release 条件却额外迟启动的问题。这个模型是原运行的描述，不是固定实际 duration 下预测新映射的合法方法。

两格 trace DDR 区间并集分别等于 13,184 / 65,146，恰好等于独占服务和；并发 COPY 的 elapsed 求和会重复计数。两格分别有 **20 / 13 个 Task 的 actual duration 小于 local_makespan**；`actual−local` 不能命名为竞争损失。spill=0 也不等于没有内存约束：官方分别记录 1,173 / 1,226 条 memory dependency。

## 唯一优先候选：其余组件 bundle 提前插入核链

保留重组件 Task 的 compute 成员、core 与先后次序。把末波每个 Task 内的“其余完整弱连通组件集合”视为一个 bundle，保留 bundle 内原有组合；选择少量 bundle 从末波抽出，成为一个独立 Task，插在某核现有相邻重组件 Task 之间。选择位置依据原图 compute Pipe 向量、边界 COPY 服务和轻量 Task release 模型的预计空档；这些是排序代理，不能当容量证明或官方 duration 预测。最小机制试验先只移动一个 bundle，避免同时改映射、重分包和粗合波后失去归因。

**合法性证明：**这些 bundle 由整个独立 compute 弱组件组成（组件定义已跨原 COPY 收缩），没有与其他 Task 的数据依赖。若原核链有 `A→B`，插入仅把该边细分为 `A→R→B`，其中 R 无其他入出 Task 数据边，不能在原 DAG 上产生环。开头/末尾插入同理。原混合末波 Task 抽走独立组件不会新增数据边；若原 Task 被抽空，删除该 Task 后按原核序连接前后，相当于压缩已有路径，也不会产生环。此证明只保证 Task-order 合法，容量、FIFO、spill 与最终收益仍待官方验证。

**保持 bundle 的原因：**两图重组件与其余组件没有共享外部输入，抽离保持 bundle 时不会引入两者间的新 boundary COPY。保持其余组件原有 bundle 还可保留它们当前的共享输入去重。原图两图的现有 bundle 边界 COPY 字节/独占服务如下：

## 本轮不应优先尝试的方向

1. **只重新安排 COPY 同时发射，保留所有 Task 与 FIFO。** 049 的有效固定 FIFO 下界离实测仅1512周期；这不是主要结构空间。两格 current spill=0，不能用“继续消除 spill”解释目标。
2. **只按当前波的 Pipe 工作重新做 LPT 映射。** 可能改变 gates，但无法减少固定分区 COPY 总服务；088 当前 partition 的65146服务地板仍在。它还不能解释末波独立组件为何此前未利用空核。应先分离这项结构变化，之后再比较累计前缀负载的映射。
3. **把9,000 gates全当可消除收益并一次粗合多波。** 049 42/42、088 35/38 个核链相邻对是单独可无环收缩的 cover edges；所以不是“不允许合波”。但088 core4 的 (10,19)、(19,28)、(28,37) 有穿过中间重波的替代路径，合并各自就成环。单个合并合法也不保证一批同时合并合法，必须对最终 quotient DAG 再证明。合法合并还会让原早结束的 producer 必须等整个合并 Task 结束才释放远端消费者，增大门控关键路，不能用减少 Task 数替代质量论证。

分析复杂度：元数据重建采用保守的 `O(T·(#tensor+#edge))` 扫描，两格不足50 Tasks；后续各局部/宏 DAG 最长路为线性规模加 heap 排序。该脚本是有界的离线审查工具，不进入求解器端到端时间，不代表未来构造复杂度或求解耗时。
