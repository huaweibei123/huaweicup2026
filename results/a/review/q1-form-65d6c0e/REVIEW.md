## R3：F-TASK-006 的无条件 spill 规则不成立（需修订）

`formal/rules.jsonl` 的第 33 行，以“发生了一次 spill”为前提，写成总会新建
DDR backing、COPY_OUT/COPY_IN 对以及 `version=1` 的 UB 化身。
冻结 `schedule_step2.py:315–359` 实际有三处分支/状态：

- 已有 DDR backing 时复用它，`spill_out_id=None`，仅新增 COPY_IN。
- 同一逻辑 tensor 每次换入递增 `incarnation_version`，不恒为 1。
- 新化身使用 `sp['pos']`，可以是 L1，不能恒写 UB。

本轮独立合成图使用冻结配置、8 个算子、9 个 tensor、两个核槽位。
输入全部走官方 Q1 CLI，且未改官方字节。原 COPY_IN 的 L1 tensor `10002`
在同一 Task 中两次换入：版本 `[1,2]`，两次 `spill_out_id=null`、
`spill_out_copies_data=false`，复用同一个原 COPY_IN backing；两次新化身均为 L1。
所以这不是只从底层函数人工拼出来、无法到达情况 A 的反例。

`probes-v2/spill.step2.json` 分别保留原始图 Step2 与 Q1 构图之后的 Step2
观察，二者不混同。用 Python profile return hook 只读观察；随后关闭 hook，
完整函数结果相同；再运行未插桩的官方 CLI，所有函数结果字段与 CLI 对应值相同。
Q1 makespan 为 **43728 cycles**。完整输入、spill 记录与输出均随报告保存。

影响：若据该规则推导 spill 代价或重写评估器，会多算写回、弄错 L1/UB 容量，
或错误关联多次换入的 tensor。此问题不说明成员其他公式或现有 E1 已有同样错误。
F-METRIC-001 的条件搬运公式应保留，F-LOCAL-005 的 SPILL_OUT 插入描述须注明
“仅在实际生成 COPY_OUT 时”。建议成员修改规则文字并接入本反例，无需重写评估器。

## 补充：固定 FIFO 的队首阻塞见证

三算子无 tensor 的函数边界合成图，明确不当作正式数据分布：
V1 耗时 100；M2 依赖 V1，耗时 1；M3 无数据前驱，耗时 1。
Step3 固定 M FIFO 为 `[M2,M3]`。官方时刻为 V1 `[0,100]`、
M2 `[100,101]`、M3 `[101,102]`。M3 虽然数据就绪，仍不能绕过队首。
这补充了成员已披露的“只有同 Pipe 串行证据、没有队首可越过性探针”的有限缺口。
只宣称这个小例及相关源码分支，不把单例提升为全实现证明。

## 情况 A 值得保留的数学抽象

设计变量是非 COPY 算子上的划分 π、子图到核的归属 c，以及各核子图顺序 σ。
目标是最小化官方执行后的 `max_T f_T`。同一个划分也有多个归属和顺序可选。

1. 商图必须无环；再加入各核相邻 Task 顺序边后仍须无环。这是候选生成器
   可以直接检查的结构约束。来源：`derive_multicore_plan`、`validate_task_order`。
2. 情况 A 的 Task 边界与是否跨核分开：同核不同 Task 也重新构造边界 COPY。
   不能用“跨核 cut bytes”代替全部 Task 边界搬运。来源：`_build_scene_a_tasks`。
3. 所有真实前驱完成后，Task 的最早释放时刻为
   `max(0, f_prev+100（有同核前项时）, max_{异核前驱 U}(f_U+1000))`。
   多个前驱取最大值，不把等待费用相加。来源：`task_release_time`。
4. 每个 Task 内的执行图由边界 COPY、Step1、Step2、Step3 确定；数据依赖、
   内存复用依赖和 Pipe FIFO 一起约束执行。选手没有任意逐操作排程自由。
5. Task 耗时不能普遍固定成一个独立权重：共享 DDR 的在飞集合改变传输时间，
   划分又会改变边界、spill 和内部 FIFO。精确结果仍调用冻结官方程序。

这些抽象能指导合法候选、同核合并/拆分、关键出口保护、资源负载与内存风险
的筛选，但尚不是一个强求解算法或完整等价性证明。若要成为数学贡献，需要
进一步得到可证的安全变换、下界、可求解子问题，或用同预算实验证明构造有效。
把官方循环换成公式、再将所有复杂性藏到 E(G,P) 黑箱里，本身收益很有限。
