# 008 / k4：返程切口候选的只读静态初审

本记录只读原 ZIP、既有独立接口审计及 Pro 源码，以整数算术推导参数和风险。
**没有调用构造函数，没有生成新 plan，没有运行 solver/E0/E1/E2，也没有参数扫描。**
此处模型式、下界和作者候选参数均不是新的官方成绩。候选只作一个预先固定的
官方对照，不以保守包络拒绝当成算法无效的证据。

## 材料身份

- 输入 ZIP：`data/raw/a/official-cases.zip` 中 `data/case_008.json`。
- 本次只读原图字节 SHA-256：`c93bb7ab5deec5112aff0cc001fbd76d001d3de5ea7463fba59b1f1ff2ba3e1d`，与独立审计相同。
- 已有接口审计：`008-independent-interfaces.json`，记录 108 条同构真链、完整切口及条件下界。
- 参数来源：归档 Pro `p1_phase_cut.py` 的 `choose_and_construct`、`encode`、`model_plan`；沿用先前 FIFO 条件初审。
- 固定配置：L1 524288B、UB 131072B、DDR 60B/cycle、同核 Task 门控 100 cycles；k=4。

每条链是 M1158→六段 V（总2196）→M1158，总计算长度 4512。
原图首条计算链为 `[4,6,7,8,9,10,11,12]`。每核分配 27 条。
完整链必要外部读服务为 `3*103+1=310`，外部写为 103，合计 413；
全图必要 DDR 服务 `108*413=44604`。最后 V→返回 M 的完整切口是
18432B、每次 COPY 服务 308，额外一写一读为 616。该切口达到当前最小切口服务。

## 源码会选出的唯一参数

按原 tensor 的使用集合、将原 DDR 位置映射到 UB 后，单条链的 footprint 为：

| 集合 | L1 字节 | UB 字节 |
|---|---:|---:|
| 新 prefix（最后 M 之前） | 30720 | 74114 |
| 旧 return（最后 M） | 12288 | 18432 |
| 一新 prefix 加一旧 return | 43008 | 92546 |
| 一条完整链 | 43008 | 74114 |

这里的 prefix 与 return 属于不同链，混合包必须把两者相加。noMEM 证书使用
全部不同本地 tensor 总量而非峰值，因此：

`q_capacity = min(floor(524288/43008), floor(131072/92546)) = 1`

`whole_packet = min(floor(524288/43008), floor(131072/74114)) = 1`。

解析尺度 `floor(sqrt(27*(1158+100)/1158))=5`，被容量证书截成 **q=1**。
这不证明 q>1 会 spill 或无效，只证明该保守 noMEM 证书不能覆盖它。

q=1 时理想混合计算响应为 `Fq=max(2316,3354)=3354`，代理每切链节省
`4512-3354-100=1058`。代理交点为：

`s*=(108*4512-4*44604)/(1058+4*616)=308880/3522≈87.70`。

源码只比较四个解析候选 `s∈{0,84,88,108}`，代理值分别为
121824、99606、98812、111132，故固定选择 **s=88**。
round-robin 分核后每核 **22 条切链、5 条完整链**，切在最后 V 与返回 M 之间。

每核 Task 序列：5 个单完整链 Task，然后
`P0, P1+R0, ..., P21+R20, R21`，共 28 个 Task；四核共 **112 个 Task**。
每核 27 次同核门控，共 2700 cycles。原 ID 不改；同链片段留在同核，数据边及
核内 Task 顺序都向前，因此没有新增跨核交接。

仅按理想计算响应加完整释放门控，每核是
`5*4512 + 22*3354 + 1158 + 27*100 = 100206`。
候选必要 DDR 服务是 `44604+88*616=98812`。这两个数只说明两个约束的尺度，
不能取 max 后当作实际 Makespan，更不保证低于原官方 123060。

## 2K COPY 包络必然拒绝，但拒绝不能淘汰此候选

无需运行中层模型即可证明包络无法通过。每核全部读 COPY 的独占服务为
`27*310+22*308=15146`，读 COPY 数为 `27*4+22=130`。

采用每条 COPY `8*d+1` 的包络，仅 MTE2 的总时间就是
`8*15146+130=121298`。Task 在同核串行，加门控得：

**`Uenv >= 121298+2700 = 123998 > 121824`**。

这还没有计入 M/V 或写回。因而 Pro 的保守采用门禁会回退，无法把此候选送到
实际评分。此事实只说明统一最坏 2K 请求延迟的包络太宽，不能推出实际候选更慢。
准备的单一 E0 对照必须明确直接评估该固定候选，不把默认包装器的 fallback
输出错认成返程错位实验；方案身份及 112 Task 数需要核对。

## 可能获益的机制与主要失败风险

最值得检验的收益是：混合 Task 先发新 prefix 的 M，随后让旧 return 的 M
覆盖新 prefix 的 V。相比保持完整链的 M→V→M 固定 FIFO，这才可能消除部分
必然的 M 阻塞；仅重排完整组件不可能越过其 121824 条件下界。拆链普适下界
85590 仅说明还有理论空间，不保证这一个候选达到它。

008 prefix 有六段 V，终端深度严格超过单旧 return；先前“首 M 无输入且只含
一个 V”的深度平局反例不直接适用。仍须在编译产物中核对真实 M FIFO。

两个主要风险：

1. **MTE3 与完整 Task 释放抵消计算重叠。** 混合 Task 的 Step1 会先访问深的
   新 prefix。因此 MTE3 FIFO 为新 prefix 的 18432B 写回（308 服务）在前、
   旧 return 的 6144B 最终写回（103 服务）在后。旧 return 即使早算完，其输出
   COPY 也可能被新 prefix 的晚写回挡住；同相四核同时争 DDR，Task 完整释放
   门控会将这个等待继续传给下一包。旧 return 的切口读也可能延迟它进入 M。
2. **whole_packet=1 使未切链失去跨链读预取。** 每核 5 条未切链被拆为 5 个
   Task，必须等上一链全部写回再读下一链；旧完整 bundle 允许在同 Task 内按
   MTE2 FIFO 预取下一链。仅把这 5 条完整链并成一个 Task，可少 4 个门控，即
   400 cycles/核，但会失去当前 noMEM 充分证书。官方内存补边、共享 DDR 可能
   改变时序，所以尚不宣称 whole_packet=5 严格支配原候选。

当前 q=1 的每种 Task footprint 均满足总量证书，预期没有 SPILL 或
MEMORY_REUSE；实际 E0 必须回读确认。不能把“证书通过”代替真实编译一致性。

## 最小验证与后续边界

保持首个且唯一候选 **k4/q1/s88/whole_packet1/return-cut**，不扩展参数批次。
核对合法两键 plan、27 条链/核、22 切+5 整/核、112 Task、616 服务/切链；
回读真实 M FIFO、MTE3 FIFO、SPILL/MEMORY_REUSE 数、DDR 流量及门控时间。
将总 Makespan、求解端到端时间与原固定方案分别比较，并检查局部 M/V 重叠
是否最终缩短了 Task 完成时间。任何中层预言都与官方结果分开记录。

若唯一对照显示同相 DDR 是主要损失，可下一步研究把每核固定 5 条完整链安排
成不同长度的头／尾，改变四核进入返程错位段的相位，同时保持每核总链数和
切链数。这个方向尚无优越性证明，**本次不实现、不搜索、不追加评分**。
