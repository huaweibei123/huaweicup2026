## 每种 Task 的实测相位

下面的次数是每核次数，时刻为相对该 Task 开始，单位 cycles。

| Task 类型 | 次数/核 | 独占 COPY 延迟松弛模型 | 官方持续时间 | 每次差额 |
|---|---:|---:|---:|---:|
| 一条完整链 | 5 | 4821 | 5748 | 927 |
| 初始 prefix | 1 | 3868 | 5410 | 1542 |
| 一新 prefix + 一旧 return | 21 | 3971 | 5822 | 1851 |
| 最后 return | 1 | 1672 | 3214 | 1542 |

表中“模型”具体是 diagnostics 的独立 COPY 延迟松弛，**没有模拟实际共享 DDR**。
每核再有 27 次 100-cycle Task 门控，因此：

`5*5748 + 5410 + 21*5822 + 3214 + 27*100 = 162326`。

模型为 115736，与官方的 46590 差额精确为：

`5*927 + 2*1542 + 21*1851 = 46590`。

一个代表性混合 Task 的官方时间线：

| Pipe / 动作 | 起止 |
|---|---|
| MTE2：新 A 第一输入 6144B | 0–412 |
| MTE2：新 A 第二输入 6144B | 412–824 |
| MTE2：新 prefix 的 2B 标量 | 824–828 |
| MTE2：旧 return 的 6144B 输入 | 828–1240 |
| MTE2：旧 return 的 18432B 切口读 | 1240–2472 |
| M：新 A | 824–1982 |
| V：新 prefix 六段 V | 1982–4178 |
| M：旧 return | 2472–3630 |
| MTE3：新 prefix 的 18432B 切口写 | 4178–5410 |
| MTE3：旧 return 的 6144B 最终写 | 5410–5822 |

旧 return 的 M 完整覆盖了 1158 cycles 的新 V，但其最后写回直到 5410 才开始。
它在 3630 算完后等待 **1780 cycles**，由新 V 剩余 548 与前面的切口写 1232
组成。随后还要完成自己的 412 写回，整个 Task 才能结束并进入下一个 100 门控。

混合 Task 对模型多出的 1851，精确对应新 A 前的两次读增加 618，以及末尾两次
写增加 1233；旧 return 的读也变慢，使 M 队首在 1982–2472 等待 490，但其 M
仍落在 V 区间内，因此没有进一步抬高本 Task 最后完成时刻。这是该条实际
时间线的路径解释，不是对其它计划的通用加性公式。

## 重叠没有消失，收益被 I/O 启动与排空抵消

将每核 M 和 V 区间求并集，再比较非计算时间，可得到完整账：

| 每核时间分类 | 旧完整链方案 | 新 return-cut |
|---|---:|---:|
| M 与 V 区间并集 | 121824 | 97506 |
| 其中 M/V 重叠 | 0 | 24318 |
| 没有 M/V、只有 DDR 的时间 | 1236 | 62120 |
| Task 之间的门控 | 0 | 2700 |
| Makespan | 123060 | 162326 |

新方案确实省下每核 24318 个计算占用时钟，四核重叠总和为 97272，和模型一致。
但纯 DDR 等待时间增加了 60884，再新增 2700 门控：

**`60884 + 2700 - 24318 = 39266`**。

这里是两个已观测时间线的精确区间分解，不应称为“关掉某机制”的消融实验。
门控只有 2700，不能把全部退化归咎于门控；更大的问题是每个细 Task 反复付出
输入启动和输出排空，而且 Task 必须等完最后 COPY 才释放。

## DDR 的实际忙闲与并发

按最终 COPY 的 `[start,end)` 区间扫事件；同一时刻增减一起处理，不把 issue
循环内短暂的 1、2、3 路状态当作有持续时间的并发。

| DDR 活跃 COPY 数 | 旧持续时间 | 新持续时间 |
|---|---:|---:|
| 0 | 78456 | 63514 |
| 4 | 44604 | 98812 |
| 1、2、3、5、6、7、8 | 0 | 0 |

四核始终同相，每一轮相同 COPY 在四核一起搬。DDR 忙时因此恰好等于必要服务量，
新利用率为 **98812/162326 = 60.872565%**。大量空闲仍然存在，却无法在同一个
小 Task 内转移到前后的必要 COPY：FIFO 与完整释放限制了其位置。

另一份闭合账是：

`新增 DDR 忙时 54208 - 减少 DDR 闲时 14942 = Makespan 增加 39266`。

其中 `54208=88*616` 正是 88 条链切口的一写一读必要服务，并非模拟器额外凭空
加了传输。新每核 MTE2、MTE3 的占用分别为 60584、38228，二者没有时间重叠。

`conditional_exact_model=false`、`DDRdisjoint=false` 已明确标注；Uenv=224551
覆盖实际 162326。因此本次不是条件定理反例，也不能把115736当成有效官方预言。

## 一个无需参数扫描的下一提案：q=2，保持其它选择

建议只研究 **q=2、s=88、whole_packet=1、仍在最后 V 后切口、仍每核22切+5整**。
不重新跑代理选 s；这样下一对照只改变包宽，隔离“每 Task 有第二个 prefix 可以
预取、可覆盖前一个写回”这一机制。每核由 28 Task 降为 17，四核共 68；同核
门控由 2700 降为 1600，必要 DDR 总服务仍为 98812、额外字节仍为 3244032。
这不是最优性或改善保证，目前未实现、未编译、未评分。

选择2的理由是它是最小的多 prefix 包，并且可给一个待官方编译产物核验的局部
内存论证，而不是在 q 上遍历：

1. 两个新 prefix 加两个旧 return 的 L1 总量为 86016，仍小于 524288，L1 无需
   复用额度。UB 总量为 185092，超过 virgin 额度 54020，因此原 noMEM 证书不再
   适用；**不能谎称 q2 无 MEMORY_REUSE**。
2. 第一个新 prefix 的 UB 总量为 74114；去掉最终 18432B 切口输出，其余 UB
   中间 tensor 共 **55682B**，全部最后消费者都在第一条 prefix 的 V 链内。
   `55682 > 54020`，足以覆盖整个混合 Task 超出 virgin 的额度需求。
3. Step1 的 V FIFO 先走第一个新 prefix 的全部 V，再走第二个。因而第一个
   prefix 的这些非最终中间 tensor 全部释放，早于第二个 prefix 的任何 UB
   消费者释放。结合官方 VIRGIN 优先、回收额度 FIFO 的规则，足够的最早回收
   额度来自第一条 prefix，不必使用其最终 COPY_OUT 或第二条 prefix 的额度。
   因此预期新增 WAR 的阻塞来源止于第一条 prefix 的 V；旧 return 的 M 仍有
   机会覆盖第二条 prefix 的 V。
4. Step2 的序列中，每个私人 prefix/return 分量被完整访问、结束 COPY 后释放；
   单 prefix 瞬态 UB 上界 37056、L1 30720，均在容量内。该序列层面的不 spill
   论证不等于实际 Step3 FIFO/MEM 证书，必须检查真正新增边的端点和峰值。

这份推导需要验证的具体断言是：重建出的混合 Task 中，所有 UB 回收来源都在
第一条新 prefix 的非最终中间 tensor 集合；没有把旧 return 额外锁到第二条
prefix 的尾部；实际 M FIFO 为两个新 A 后接两个旧 C。即使断言成立，共享 DDR
可能使收益消失，最终仍由一个固定官方对照裁决。

先前提出的不同整链头/尾长度仍可保留为后续问题，但不应假设它自动实现均匀
错相：本次一条整链加门控周期为 5848，混合周期为 5922，相差仅74；以当前周期
作近似，仅改变整链头数可能仍接近同相。这不是新方案的反证，只是选择更宽包
作为下一单一机制检验的理由。本次不实施任何头尾或包宽变体，不追加评分。
