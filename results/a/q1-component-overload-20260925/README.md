# P1：任一 Pipe 超载组件的 sink-peel 覆盖审计

结论：把“主导 Pipe 的 80%”改为“某组件在任一 Pipe 的工作超过该 Pipe 的五核平均份额”，能覆盖一组被漏掉的混合 Pipe/中等重组件。但这个条件只是完整组件负载不均的信号，不能自动推出值得拆分。首轮最小证伪建议 **054/K5 与 050/K5**；066 留给多组件同时拆分与 ready-list 的后续证伪。

## 通用判据与其证明边界

第一层条件 `W(C,p)>B_p` 是“若C始终完整放在一个核，该Pipe不可能在每核B_p之内装完”的充分证据：该核仅服务C就需超过B_p。它不是“该组件必须拆”的结论，因为其他 Pipe、DDR、CP 或 gates 可能才控制 Makespan。

也不能从“没有这个超载条件”推出已可完美装箱。例如K=5时有6个工作量为2的组件，总量12、平均向上取整为3，每个组件都≤3，但完整装箱至少一个核要接两个组件、负载4；多Pipe联合装箱还有其他离散限制。反过来，拆成更多Task也会付出远超小工作量的等待，因此装箱差距不代表真实收益。

建议以结构层级组织候选：

1. 记录全部Pipe的超载，而非调低一个全局百分比阈值。
2. 对组件做固定64/64 sink-peel。预算失败或没有独立包则保留整个组件，不提交部分剥离。
3. 检查与全图 compute floor、保留组件、最大 packet、packet依赖链的关系，识别真正可能减少串行压力的组件；不要把它们的差额当可实现收益。
4. 明确记录输入重复、内部物化、Task数和门控风险。其余组件从原依赖所允许的开始时刻即ready；不因“未选中”就推到末波。
5. 选中的多个组件形成有向 packet/Task 商图，按真实依赖与合法核序调度；不把同一波号强加为全图同步屏障。最终仍需官方结构验证与E0。

sink-exclusive包的合法性来自：同波不同包无计算依赖，跨波边严格前向；不同弱组件之间无计算边。对每个组件可保留独立的波号势函数，但多组件 ready-list 及核序加入后的完整无环仍应由实际构造证明和检查。本审计没有替父会话的新调度器出具实现验收。

## 应保留或降低优先级的实际反例

- **单 sink 不等于没有图内并行。** 组件数≥5的17个超载组件只有单包，例如006、010、012、015、019、026、032(anchor1346)、040(anchor5969)、042、055、057(anchor1489)、061、070、096两个组件、098、100。此 sink-peel 机制无法拆它们，应保留；002/016/024/051等组件稀少图也有大汇聚结构，但不属于新入口覆盖，不能借本审计擅自扩大它们的研究批次。
- **较安静Pipe超均值。** 031/anchor3624 最大Pipe工作57584，远低于全图compute floor266899；077为82458≤83082；087的两个组件分别542640/448920，均≤718656。它们可以剥离，但剥离并不直接解除该静态全图瓶颈。保留它们作为负例/审慎组，不声称永远无法通过别的机制改善。
- **未拆的组件仍更重。** 032可剥组件最大工作7617，另一个不可剥整组件9510；040分别72600与94057。因此新路线若仍保留后者，前者本身不再是主要计算限制。057的保留组件10080把静态余量从3436压到2869，额外等待和复制可能轻易抵消。
- **预算反例（推理，未运行构造）**：一个连通前缀分叉到65个活动sink，固定max_sinks=64立即拒绝；深度导致超过64轮亦拒绝。本100图被选组件没有触发，不表示可删预算或在其他图上一定完成。
- **高共享输入或内部高扇出**：独立计算包仍会共享同一个大输入，或者同一中间tensor在多个后继包出现。更多packet不必减少Makespan；此前Fang的051重复输入和008内部边界证据是这一风险的既有实测背景，不能自动移用其具体数值到本组三图。

## 两个优先新样本与验收点

只建议 **054/K5、050/K5**，不是追加实验授权。二者各有一个被旧80%遗漏的强候选，便于把守卫覆盖和调度效果隔离；066涉及两个不同Pipe超载组件及更大输入，适合作为第二步多组件反例。

- 054检验：选择V重、但全图主导M份额不足80%的组件后，能否降低原518133 cycles；其余M工作能否早启动；新增复制与等待是否抵消收益。
- 050检验：71.76%的中等重V组件在10波内能否减轻原108160 cycles的单核负担；是否用粗Task合并控制131个packet的重复输入和gate成本。

复用旧reference，不重跑基线。正式run需新冻结算法/runner和独立预算，保留每格原件、负例和失败；同时报告官方Makespan、partition/spill/总额外DDR、Task数/实际拆分组件、solver端到端墙钟和外部E0墙钟。旧成绩、静态代理、后续本机复现分开记录。

## 复杂度与静态检查

在已有收缩DAG上，组件/工作量/CP为O(N+E)，每个选中组件的剥离在R≤64、sink位宽≤64时为O(R(N_C+E_C))。各组件互不重叠；按每个Pipe严格超1/K平均的组件至多K−1个，因而筛选组件数亦受Pipe数×(K−1)约束。官方图构建/收缩成本另计；张量关联按所选组件扫描有相应常数倍，packet统计与JSON输出另计。脚本不生成分核或每核顺序。
