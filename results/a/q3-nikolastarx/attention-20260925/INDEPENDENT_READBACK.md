## 082 的 FFN 真实传输与等待

**纠正资源混用：331776 B 是先前未评分 k5 计划的静态内部远端需求。本批实际 k4 是 282624 B。** 两者虽然都是 19/21 FFN split，但归属不同，不能替换。

按原图独立发现 21 个闭合 FFN diamond，将每个内部原 tensor 的源/目标核逐一匹配 cross_core_transfers，再通过 COPY ID 回到官方 timeline：

- 19 个被切分，映射到 36 次实际跨核传输，单向载荷 **282624 B**；是全图实际跨核载荷 1491520 B 的 **18.949%**。
- 这 36 对 COPY 的调度字节合计 **565248 B**，占全部新增调度搬运 3557904 B 的 **15.887%**。这是 COPY 操作字节，不是物理 DDR 访问计数。
- 对应接收 COPY_IN 的命中载荷 **24576 B**、未命中载荷 **258048 B**；来自对应 COPY 的 memory_path/cache_hit。不能只用静态张量大小推 Cache 命中。
- 所有 36 条及全图所有 transfer 均核对 `COPY_IN release = COPY_OUT end + 500`，且实际 COPY_IN start 不早于 release。

强制 release 延迟另为每条 500 周期。**上述逐条和有并行重叠，不能相加当作关键路径或可消除的 Makespan。** 搬运后到消费算子的间隙也可能受其他输入、FIFO 或内存边约束，不等于单独由该 transfer 导致的停顿。
