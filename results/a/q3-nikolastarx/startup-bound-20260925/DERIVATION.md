# 原 051 / 五核：包含冷启动和最终写回的全局必要下界

结论：所提的 **`150196 + 547 + 1 = 150744` 成立**。进一步利用十二路不同初始输入共享 DDR 的必要服务工作，可以严格加强为：

\[
\boxed{M_{051,5}\ge8699+23\times6279+1=153117.}
\]

范围是固定原 051、五个声明核、冻结官方 P3 配置下，**任意合法切图、原操作分核及执行顺序的成功执行**，并不限于当前 single-cut、singleton 或某个 FIFO 模板。不声称 153117 可达或 tight；不是新增成绩，也没有证明某个已有方案最优。

本次 0 E0 / E1 / E2、0 solver、0 官方 Task 构造。只读取源码、原始 JSON 和既有审计报告，独立提取原图阶段结构并计算少量整数容量证书。生产代码及结果原件未修改。机器可核对的输入身份、原阶段与数字在同目录 `proof.json`。

## 2. 子图分组不取消这些物理义务

`stub_multicore_cut_and_schedule.py:114–186` 要求方案完整覆盖所有原非 COPY 操作，每个子图仅分配一个核。P3 `_build_scene_b_tasks` 在 `multicore_cut_evaluate_problem_3.py:69–94` 将每核全部子图合为一个 Task，并逐个复制原操作；分组不融合、不复制、不删除计算。

同文件 `157–174` 重建每个原张量与本核计算的边，对无 eligible producer 的图输入在每个实际消费核添加 COPY_IN。选手虽不提交原 COPY_IN 的分核，官方仍会重新生成必要输入读入，不能把原 COPY 被排除于 plan mapping 理解为“输入免费驻留”。`176–187` 对原图输出重建最终 COPY_OUT。子图优先序只改变顺序，且仍须通过拓扑检查（`51–67`）。

Step2 保留原操作和 producer 边，将消费者重接到同尺寸的 incarnation；新 incarnation 的 `logical_tid` 等于原 tensor ID，size 和 pos 保留（`schedule_step2.py:290–352,409–438,473–486`）。内部计算值若 spill，写出/重载链仍保留其生产因果。

**已有 DDR backing 是需要单独解释的情况：** reload 不一定有“原 COPY_IN→reload”的显式数据边，不能仅靠数据边传递性作证明。但原 COPY_IN 在原 seq 中先于其后续使用；reload 在 `seq_ext` 中插入后续使用前，因此固定 MTE2 投影中的原 COPY_IN 仍在 reload 前（`schedule_step2.py:177–200,443–453`）。Step3 使用该固定管线投影（`schedule_step3.py:281–287`），P3 必须在前一个操作完成后才推进 pipe cursor（`multicore_cut_evaluate_problem_3.py:443–474`）。所以缓存命中或重载不能跳过原输入/跨核 COPY_IN 的完成屏障。

容量分配、内存复用补边只增加约束，不能使受限操作更早执行。即使不使用 singleton，原依赖因果、每核 V 单槽互斥、原时长仍成立；本证明不使用提交 singleton 顺序这一更窄前提。

## 3. 较弱的启动 547 加最终 1 确实可以整体相加

Cache 每次 E0 都由空 `OrderedDict()` 开始（P3 `328–335`）。只有 COPY_IN 在**完成**时插入 Cache（`487–510`），命中判断发生在发射时（`539–549`）。原 051 的任何首个计算都需要一份 32768 B 输入。该 logical key 的首次读入不可能命中尚未插入的自己，至少需要

\[
D=\left\lceil32768/60\right\rceil=547.
\]

`schedule_step3.py:74–81` 按 tensor 大小计算 COPY 服务时长，原 COPY 的 `cycles=0` 不会令读入免费；P3 的共享服务只会延长这份工作。所有大计算以及它们之后的 ADD 均不能在 547 之前开始。

因此把任何实际计算执行的时间坐标统一减 547，仍是一个起点非负、保留计算时长/互斥/原跨核 ≥500 的放松模型执行。其 24 阶段计算界 150196 可整体加一次 547；不是对每阶段另加 547。

最终 2 B COPY_OUT 必须在最终 root 的数据可用后执行；它不查询只读 Cache，COPY 时长至少 `max(1,ceil(2/60))=1`。P3 makespan 是所有操作结束时刻的最大值（`multicore_cut_evaluate_problem_3.py:683–688`），包括输出 COPY。因此 `M≥150744`。

## 4. 更强的首阶段界：8699

令 `τ_i` 是第 i 个原 immutable logical key 在整个多核执行中**首次完成 COPY_IN**的时刻。每个第一阶段 head 必执行，故十二个 `τ_i` 都存在。

每个 key 的这次首次完成必来自 DDR miss：若该 COPY_IN 命中，则此前已存在同 key 的一次 COPY_IN 完成和 Cache 插入，与“首次”矛盾。本图原 key 唯一且未设置 logical alias；spill incarnation 保留对应原 key 和 32768 B 大小，所以不存在其他 2 B 或更小张量借同 key 提前填充的捷径。

重要的是官方先对**每次** COPY 计算 `ceil(bytes/bandwidth)`，再将其作为 `float(duration)` 加入共享 DDR 工作池（P3 `547–549,575–581`）。共享池每次将 elapsed 按活跃数均分，总归一服务率不超过 1（`352–372`）。因此十二次必需的首次 miss 至少累计需要

\[
12D=12\times547=6564
\]

个 DDR 归一服务周期，故 `τ=max_i τ_i≥6564`。这是冻结模拟器的逐操作舍入口径；若只用总物理字节除带宽，`ceil(12×32768/60)=6554`，不能据此写出 6564。

取达到 τ 的那个 input。它的第一阶段 head 不可能在 τ 前开始，否则其输入 COPY_IN 必已更早完成，违反 τ 的定义。首次读入在其他核、不同 incarnation，或其他阶段的预取也不影响此论证：任意 head 的合法读入完成都不能早于该 key 的全局首次完成。

该 head 到首阶段 root 仍必须完成原四个 524 周期操作，以及至少三个 13 周期 ADD。忽略所有其他并行计算、所有通信、内存和管线阻塞，只保留这条原始因果路径，仍有

\[
R_1\ge τ+4\times524+3\times13\ge6564+2135=8699.
\]

这个证明不要求十二路 COPY 同时开始，也不要求固定 lane 归属或固定归约 collector。其他 DDR 流量、重复 miss、容量阻塞只会使必要服务完成更晚。

## 5. 后续每阶段 ≥6279 对任意 owner 与合法顺序成立

令前一根完成为时刻 0、owner 为 a，当前根完成为 T、owner 为 b。任意本阶段大操作 v 的 owner 为 c。

- 从前一根到 v 的原始依赖路径：若 c≠a，至少跨核一次，故 v 的开始至少为 `500[c≠a]`。
- 从 v 到当前根的原始路径：至少包含 3 个 ADD；若 c≠b，至少跨核一次，故 v 的结束至多为 `T−39−500[c≠b]`。

跨核因果中的 500 来自 source COPY_OUT 完成后的 external release，与是否命中 Cache 无关（P3 `189–214,436–460`）；前文 MTE2 FIFO 说明了 Step2 重载不能绕过它。丢弃链上其他非负时长只会放宽约束。

核 c 上所有 524 周期大操作必须完整位于同一个必要窗口。V 单槽意味着：

\[
48\le\sum_{c=0}^{4}\max\left(0,\left\lfloor
\frac{T-39-500[c\ne a]-500[c\ne b]}{524}
\right\rfloor\right).
\]

在整数 T=6278，a=b 的容量为 `[11,9,9,9,9]`，a≠b 为 `[10,10,9,9,9]`，总数均 47，不足 48；更小 T 不会增加容量。因此 T≥6279。首阶段取消左侧广播项时，T=5778 的容量 `[10,9,9,9,9]` 也不足 48，得到先前计算首段界 5779；本次使用更强的 8699。

所有下一阶段计算都在前一根之后，而当前阶段所有计算都是当前根祖先，所以后续 23 个阶段间隔可相加。COPY 预取可跨阶段重叠，这里没有把被忽略服务逐阶段相加。

最终：

\boxed{M\ge R_1+23\times6279+1\ge153117.}

不得再在此式上额外加 547：8699 已从全局时间零点包含初始 DDR 服务，重复添加会重复计数。

## 6. 对当前结果的含义与边界

既有官方 single-cut 为 157299，距此全局必要界为 **4182 cycles**，即当前值的 **2.658631%**；当前值/下界为 **1.02731244**。这是已测可行值与已证必要界之间的范围，不意味着一定能实现这段改善，也不证明当前构造是 2.66% 近似算法的一般结果。

该界可用于描述此固定实例的剩余空间，不能仅凭下界决定一份新候选会不会优于当前方案。single-cut 增加 DDR 的取舍仍保留：本报告没有更改其正式成绩、搬运量或 Cache 指标。

适用 guard：固定原图及数据端口、十二个不同 32768 B 冷输入、原四操作链与 8+4 ADD 树、24 阶段 root 广播屏障、五核单 V 槽、原操作不可拆分/复制/重结合、冻结 COPY/Cache/共享 DDR/跨核配置、成功完成官方执行。暖 Cache、预置 logical alias、删改输入依赖、其他时长或核数不在本结论内。

没有证明 tight、没有构造 153117 的可行计划、没有审计任意自定义输入上的全部模拟器漏洞。也没有在此声称“每条跨核边至少 502”或把全部 COPY 服务与全部计算串行相加。

验证复杂度：原图端口/因果及固定 12-lane 阶段识别为 `O(V+E)` 时间和空间；两种根 owner 等价类的容量检查为 `O(k)`，k=5。无搜索、无计划构造、无调度模拟。独立子审查同样只读源码/JSON，核对了冷输入、共享池、spill 重载 FIFO 及末输出义务。
