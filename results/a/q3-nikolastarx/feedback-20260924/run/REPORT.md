## 机制解释及下一步

旧构造将一个弱分量整核分配，使 002/062/063 没有利用多核。本算法在 COPY 收缩后的归约树上
做至多 k−1 次平衡切边，按全局 DFS 后序投影各核，产生一个候选，再以官方 Makespan 严格选优。
计算依赖及核内计算顺序的无环性有构造论证；完整内存/插入 COPY/FIFO 可行性由 E0 确认。

三棵树的各核数最终 Cache 命中和 spill 均为 0；新增调度 COPY 字节为二核 3072、四核 9216、
五核 12288。不能将本轮增益归因于 Cache。构造联合改变核归属和顺序，没有分离二者的因果贡献。
044/080 仍保留旧 seed，分别含 1,388,544/229,376 spill bytes；不假称新树策略改进了它们。

四核到五核的收益较小：002 为 86922→85129，063 为 338130→336337。
算法反复二分只得到“当前切边选择下的较平衡块”，**并不保证 k 核全局均衡**；例如 063 五核
最重块仍 353280 compute cycles，而另一些块约 177000。下一轮优先比较容量阈值树分解/多块打包
与现构造的质量和求解成本，避免直接扩大候选数。异构作业交错与 Cache 阶段另按结构制定命题，
先与 Fang 在途方向互通。用户指出的 008/084/095 高分诊断见同级 `highgain-20260924/REPORT.md`。
