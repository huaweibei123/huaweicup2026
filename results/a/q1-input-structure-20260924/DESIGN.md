# 共享输入、工作量与 Task 窗口的通用构造提案

这是设计稿，不是实现或成绩。优先实现“有效核数 + 原 Task 内细化”，二维流水留作后续具体瓶颈再考虑。它与父会话正在处理的零 spill、单个组件占据绝大多数 Pipe 工作的路线互补。

## 1. 结构选择，不按 case ID 路由

计算 COPY 收缩后的计算 DAG、弱组件、组件的逐 Pipe 工作向量以及外部输入集合。外部输入的识别继续使用“没有直接计算生产者”的代理，语义异常时不能假称它覆盖所有搬运。只有有足够独立组件且输入重复具有实际量级时考虑本构造。组件不足核数或单个重组件独占工作量的情形交给既有路线。

在硬件允许的有效核数 `a ∈ {1,…,K}` 内做一次有限的资源分配决策。该范围来自可用核数（本题 K≤5），不是连续阈值的网格搜索，也不调用 E0/E1/E2。所有分配/预处理时间仍计入求解器端到端墙钟。

对一般图，按组件主 Pipe 工作降序装箱，比较放置后的最大逐核 Pipe 工作，并以输入新增字节打破相同负载的选择；保留确定性 ID 次序。按既有 bounded 原则形成组件块，**禁止跨旧块重新合并**。对每个资源配置统计实际拟定 Task 的外部输入重复，而不是只统计 core 输入并集；根据 Task 的工作量、输入/边界搬运代理和 gate 成本得到资源配置的静态成本。最终只输出选中的一个方案；不保证代理最小就是 E0 最好。

一个可落地的起点为 `H(a) = max(PipeLoad(a), CopyProxy(a)/60) + GateProxy(a)`。这里 PipeLoad 是各核各 Pipe 工作之和的最大值；CopyProxy 需按拟定 Task 的张量使用集合计算；GateProxy 使用官方 100/1000 cycles，不能借用 Q2/Q3 的排序接口或传输延迟。三项只是工程代理，不构成可行性/性能证书。有限资源配置枚举的成本与内部候选数量须如实计入求解成本。

### 本组三图的透明代数简化

若有 n 个等工作组件，每个主 Pipe 工作为 w，所有公共输入总量 I 被全部组件读取，且各组件的其他输入私有，则不需要实际输出新分区即可列出：

`PipeProxy(a) = ceil(n/a) × w`

`CopyProxy(a) = 原图 COPY 字节 + (a−1)I + 2 × 跨窗 tensor payload`

最后一项仅是“一次输出/一次读取”代理，未覆盖一般多消费者、backing 复用、incarnation 与 spill。此简化不包含 gates；它的用途是显示资源取舍，不是给出预测 E0。当前三图窗口的外部输入在窗口间没有重复；这一事实不能推广为所有图。

## 2. 窗口同时考虑输入共享与计算负载

最小实现可先保留当前输入预算 B=262144 bytes，但在**每个基底 Task 内**独立进行，避免全局 `(core,window)` 重组合：

1. 计算完整 DAG 的拓扑深度。旧 Task 内按递增深度处理，保持同深度节点完整；每个局部窗口累计外部输入集合。
2. 输入增量使集合超过 B 时，切窗。保留跨窗仍需使用的输入及内部 tensor 的字节统计，不把输入预算解释成容量上界。单层超 B 明确标记；不通过改变配置强行适配。
3. 可用共享输入生命周期进一步改进边界：对 Task 中一个输入首次/末次使用深度求区间，边界重复负担就是跨该边界的共享输入字节，加上内部 tensor 物化代理。避免切在高重复字节边界。若要最优区间分割，可对按深度排序的候选边界做区间 DP，区间代价以局部工作、输入搬运和 gate 为同周期单位的代理；不能声称该 DP 优化了真实 Makespan。
4. 工作量限制应防止连续很多轻窗口、或者单个重窗口吞掉并行收益。可以只在“本已必须切”的候选邻域中，确定性地选输入/边界代价较低且 Pipe 工作均衡的边界。先验证单纯 Task 内输入窗与有效核数，再增加这一机制，避免一次小样混入过多未经证实的参数。

第一轮建议采用步骤 1–2 及透明的工作量资源配置；步骤 3–4 是通用加强方向，尚未固定参数或实现，不能宣称已存在完整优化器。所有窗口保留在基底 Task 的原 core 顺序位置。

## 3. 增广 DAG 合法性

令已有合法基底 Task 增广 DAG 为 A（包含原图依赖与每核相邻 Task 序边）。把每个 Task T 替换成链 `T_1→…→T_r`，链按完整 DAG 的递增深度窗口排列，仍放在原 core 顺序的 T 位置。

- 同一旧 Task 内原图依赖严格增加深度，所以不会从后窗口指向前窗口；窗口内仍属于一个 Task。
- 不同旧 Task 的每条新依赖边，在把链缩回 T 后仍是原 A 的一条边；新的 core 相邻序边同样保持原块序。
- 若新图存在环，若环涉及不同旧 Task，缩回后会在 A 中形成有向闭合游走，矛盾；若只在同一旧 Task 内，链及原依赖都严格前向，亦不可能。

因此任何这种细化均保留 Task-order 无环。此证明不宣称 Step2 容量成功、不宣称零 spill、更不宣称 Makespan 改善。

若有效核数选择导致完整组件重新装箱，各组件之间本来没有计算依赖；把组件块按固定顺序放到核上，形成的新基底也是合法的。跨组件外部张量共享是公共输入，不产生组件之间的计算依赖。随后应用上述细化证明。官方 derive/validate 仍应在实现中检查输出结构。

## 4. 复杂度与边界

设 N/E 是收缩计算图节点/边，F 是外部输入的消费者关联数，C 是组件数，D 是深度数。组件/深度分析 O(N+E+F)，组件排序 O(C log C)。每个 a 的确定性装箱若逐个测试 a 个核并增量计算输入新增量，整体资源选择可在 O(K²(N+E+F)+K C log C) 的保守界内完成；K≤5。一次只保存当前最优元数据，内存不需要保留 K 份完整图。

局部贪心窗口用输入集合增量更新可近线性；当前实现反复求 union 大小则最坏含 D×T 项。不得用理论近线性描述未经实现的优化。可选区间 DP 的朴素 O(D²) 个区间另乘集合统计成本，需要深度规模阈值或退回贪心，且目前未实现。最大的输出 Task 不超过其基底 Task，保留 bounded 的原有软保护；原先不可分的大组件仍是例外。

## 5. 必须保留的失败反例

- 大 union、小 peak：输入先后使用且释放，旧方案零 spill。分窗只增加 gates/激活搬运；当前激活的 19 张零 spill 图是实际风险样本。
- 单层同时需要大输入：一个不可分深度层已经超过预算。按深度切窗不能解决；7 张 spill 未激活图提示这一覆盖缺口。
- UB/内部 tensor 主导：外部输入很小，但巨大中间结果造成压力。按输入 union 触发会漏报。
- 少核使私有输入集中：降低共享输入重复的同时，每 Task 装入更多组件私有输入，可能新生 spill；静态无 spill 曲线会失真。
- 负载与 DDR 已经充分重叠：max 型代理可能漏掉依赖链、gates、启动/收尾以及 Step3 交叠，代理降低不保证真实 Makespan 降低。
- 输入只在一小部分组件共享：简单 `(a−1)I` 失效，必须按 Task 实际共享关系统计。
- 高扇出内部 tensor：同一 payload 跨多个目标 Task，`2×payload` 低估；已有 backing 又可能减少输出。必须保留代理标记，以 E0 流量分解验证。

## 6. 暂不优先的二维流水

若少核窗口仍被计算链制约，可把同构组件分成 G 组、深度分成阶段，Task 为 `(阶段,组件组)`，阶段分配给核，核序按这对编号的统一全序。原依赖只在同组前向跨阶段，core 序同样递增，故增广 DAG 无环。理论上共享输入重复可按 G 而非 K 控制，并使不同组件组流水。

代价是 cross-core 1000-cycle wait、更多激活搬运、fill/drain 与阶段工作失衡；090 的多个轻中段和重首尾尤其危险。它的阶段编排必须通过 Q1 的 Task 分核/顺序实现，不能借用 Q2/Q3 控制自由度。本次不实现，也不把它列为首轮三格中的额外候选。
