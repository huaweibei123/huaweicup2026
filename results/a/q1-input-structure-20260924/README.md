# P1 外部输入窗口与共享输入结构审计（静态研究）

结论：下一步值得尝试“共享输入与计算负载共同选择有效核数，再按 Task 切窗”。044、046、090 的静态代数代理分别偏向在 K=5 的合法输出中使用 2、4、5 个核。这不是新成绩，尚未生成或评价任何新方案。

## 直接证据

| K=5 原 bounded 图 | 044 | 046 | 090 |
|---|---:|---:|---:|
| 原 K=5 E0 Makespan / cycles | 132892 | 131039 | 542638 |
| 官方单核基线 / cycles | 154407 | 276455 | 1178363 |
| 原 spill / bytes | 2474432 | 1292064 | 13130784 |
| 原 partition-added DDR / bytes | 3721600 | 3721600 | 8593920 |
| 独立计算组件数 | 11 | 8 | 13 |
| 所有组件共同读取的外部输入 / bytes | 930400 | 930400 | 2148480 |
| 每组件 PIPE_M 工作 / cycles | 6764 | 26156 | 64656 |
| 现窗口规则的窗口数 | 5 | 5 | 12 |
| 全部跨窗 tensor payload（各计一次）/ bytes | 60544 | 155648 | 117312 |

这三个图的组件 Pipe 工作向量分别完全一致，共享输入均被全部组件读取。044 的全图外部输入 952928 bytes，但五核输入并集之和为 4674528 bytes；相差 3721600 bytes，恰等于旧 E0 报告的 partition-added DDR。046、090 同样满足 `(5-1) × 共享输入字节 = 旧 partition-added DDR`。这些等式是本组三图及其既有方案的事实，不是任意图的分区流量定理。

保持现有核分配的 input_windows 无法消除这项跨核重复。044 即便把原 spill 全部删去，余下 DDR 为 4697056 bytes；固定 60 bytes/cycle 下仅服务时间就至少 78285 cycles。相比其单核基线 154407，条件加速上限约 1.972。此上限约束的是“保留该分区搬运、只消 spill”的路线；改变分区后不能继续套用。（同组结构审计的分母核对结论与本报告相互核对。）

## 现有窗口代理的适用范围与缺口

100 图中 45 图按现规则激活，其中 19 图旧方案为零 spill。激活不能解释为容量违规或必有改进。另有 7 张旧方案有 spill 的图不激活：021、030、039、041、058、079、097 都只能形成一个全局深度窗。

主要问题是：

1. **全图输入并集与 Task 容量不同。** 许多输入生命周期不相交；UB、中间结果、DDR backing/incarnation、局部顺序与 FIFO 均不在该数里。阶段输入并集也不是实际峰值。
2. **复用单位是 Task。** 同核不同 Task 不自动共享 Step2 的本地输入驻留状态；仅估计 core 并集可能漏掉重复读取。只有本组三图原来恰为每核一个 Task，这个简化才一致。
3. **重新合并破坏尺寸保护。** 旧实现以 `(core, 全局窗)` 重建 Task，丢弃旧 bounded 边界。静态几何表明 014/076/091 的最大旧 Task 为 1024 ops，会分别变成 4184/5403/4404 ops。不能据较少 Task 宣称更快。
4. **深度不等于工作量。** 044 五窗全图 PIPE_M 工作为 33132、4950、4950、17754、13618 cycles。单按输入量切的窗口很不均匀；090 同样有重首尾和多个很轻的中段。
5. **边界有真实成本。** 输入在跨窗重复出现、内部激活物化、same-core 100-cycle gates、若重新分配阶段还有 cross-core 1000-cycle waits，均可能抵消 spill 收益。原来的 union 规则也允许单层本身超过预算。

## 最小可证伪候选（尚未授权/执行新评分）

只建议以下三个 K=5 格，复用本次核验的历史基线及既有单核分母。由父会话/成绩台维护者决定固定实现、预算和执行资源，本报告不分配 benchmark。

| 格 | 同一通用构造的预期选择 | 首要待证伪命题 |
|---|---|---|
| 044/K5 | 有效核数 2，再局部切窗 | 降低共享输入重复所省 DDR 能覆盖并行度损失，且不新增更大 spill |
| 046/K5 | 有效核数 4，再局部切窗 | 相对 5 核保留足够计算并行度，同时少复制一份共享权重 |
| 090/K5 | 有效核数 5，再局部切窗 | 高计算量保留全部核；窗口减少 spill 的收益超过 Task/gate/边界代价 |

必须记录官方 Makespan、总额外/partition/spill DDR、真实 peak、实际 Task/窗口/有效核数、完整求解墙钟及外部 E0 墙钟。所有失败和退化都保留。仅出现代理下降、Task 变少或 spill 变少均不足以验收。实现若采用更细的 Task 流量代理，最终有效核数可能变化，需按实际输出如实报告，不能硬写 case→2/4/5。
