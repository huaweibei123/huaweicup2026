# 给工程实现者的交接

## 决策

优先工程化“官方局部编译 → 不可变划分程序 → 精确原生重放”，保留当前 E1 回退。专项 Pro 给出的 C++ 路线已接通正式数据，不必先引入新的近似模型。Rust 仍可作为实现选择，但换语言不是本轮继续探索的瓶颈；不要先全量重写 Step1–3。

依据：三张正式图 9 个计划的首次对照通过；另一个图 003 的 64 个不同候选全池 E0 核对通过。64 候选在明确的内部评分口径下计入准备成本约 33.7×新 E1；只跑 3 个候选时约 0.43–1.95×，说明高复用边界是真实条件。源码、输入、全结果和计时见上述两个 `results/a/native-replay-*` 目录。全部为本会话实现者实验，不是独立终验。

## 可复用内容与修复

- `src/replay.cpp` 原样采用 Pro r01 内核；保留 binary64 表达式顺序、全局事件切点、同刻退休顺序和 Task/Pipe FIFO。编译必须关闭 fast-math 和 FMA contraction。
- `replay_api.py` 负责紧凑数组打包和调用。已修复 NumPy uint8 求和导致的审计缓存容量溢出；原错误在正式图 002 出现，不应回退到原附件版本。
- 首先复现 `probe.py` 的 9 个计划，再复现 `batch_probe.py` 的 64 个不同计划。保存不同输出目录，不覆盖原始记录。

## 建议实施范围

1. 设计稳定的内部图/划分准备句柄，图验证与局部编译一次完成，明确不可变生命周期和有界缓存。图记录/边/属性/顺序、划分、带宽或容量变化必须失效；新的调度仍校验覆盖、重复、类型及依赖边加核顺序的联合环。不要绕过官方合法性校验。
2. 搜索评分接口返回需要的精确指标；完整官方 JSON 与审计模式继续可请求。局部内存/搬运统计来自真实官方编译结果；不得把纯数字缓冲区大小宣称为 RSS。
3. 原生数值/核数边界、加载失败、max_iter、deadlock 等明确走 E1，保留官方结果或异常分类。原型 `Unsupported` 不是官方 invalid，当前没有生产回退实现。
4. 在已有并行接口内做可控资源集成，禁止外层实验和内层 worker 双重占满 CPU。核对总 RSS（父进程+各 worker、共享页口径）、冷启动/IPC、超时/崩溃、取消清理、固定与变化划分混合、长跑。可评估只向 worker 传不可变紧凑程序，避免各进程都持有多套完整 Python 图。
5. 拓展正式 spill/DDR backing/L1 重复 incarnation、非整数等待回退、错误域与独立多图候选池。保留 E0 最终确认。每处时刻/日志差异都留最小输入并停止该输入域的精确声明。

不以本轮单图热路径替代完整发布门槛；不改冻结原件、契约、既有 E1 的默认可用路径。具体写范围由调度分配，避免与原 E1/E2 队友同时修改生产目录。
