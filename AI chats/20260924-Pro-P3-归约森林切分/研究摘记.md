# 本轮数学构造审阅（归档时静态阅读）

最有用的新内容是 **封闭二叉子树的 LOCAL／SEQ／PAR 团队复用 DP**。它将兄弟子树的归约完成时间纳入决策，避免只按工作量或各自最早完成时间把短子树散到远端核。给定子树时间 A、B，远程延迟 δ，父节点跟随较晚完成孩子，join 成本是 `max(max(A,B), min(A,B)+δ)+w_v`。LOCAL 使用固定 DFS 词的精确多 pipe max-plus 签名，不以总工作量代替时间；SEQ 允许同一核组先后服务不同封闭子树；PAR 使用不相交核组。首版理论复杂度 O(nk²+nP³)，适用真实计算入度≤2、出度≤1的单棵归约树。

关键可检验契约是 **输出方案的增强 DAG 最长路 Lδ ≤ 模板见证 H**；在已证明的官方依赖 guard 下又有 Lδ ≤ 官方 Makespan。这两条不等式不建立 H 与官方 Makespan 的一般大小关系。DP 的证明结构合理；本次只静态读代码，没有执行作者测试，也没有证明它优于现有构造。下载原型自身以独立增强 DAG 计算检查前一个不等式。

同权、单 pipe 完全二叉树且 q=2^d 时，作者给出零通信全局最优构造，加入固定延迟后的加性损失至多 dδ。其工作量截止时刻证明可直接复核；不能将四核结论扩展为五核最优，也不能移植到多 pipe、COPY、容量和 Cache 场景。作者同时给了明确反例：11 节点二核零通信，受限 DP 为 7，异步借核方案为 6；反相 M/V 片段不交错还可能损失接近一倍时间。

内存有用部分是 **同版、同图、同 seq 的 pre-Step2 闭区间峰值**：每个非 DDR tensor 在首次到末次 use（含 producer／COPY）之间闭区间计数，峰值不超对应 L1／UB 容量可证该 Step2 不触发 spill。已对照冻结 schedule_step2.py 的首次分配→容量检查→末次释放逻辑；但原型 checker 信任调用方提供完整合法 Task/seq，不能脱离适配器当正式证书。它不保证 Step3 没有容量门控、额外内存依赖或时序损失，更不等于官方内存峰值由模板时间线精确预测。

**对下一步研发的作用**：062/k5 是最直接的证伪点，先做合法计划和 `L500≤H` 零 E0 检查，若有效下界已超过已知官方 incumbent 可剪枝。是否新增 E0 由主线程预算决定。051／024／016 的全图是多阶段归约后广播，计算根有多消费者，不能直接用本原型的单树模型；应继续固定 lane 亲和的阶段构造，仅参考 join 定价与归约子树闭包。080 的反例还说明计算下界更低不足以接受新方案，必须保留 COPY／Cache 相位与原有好 seed。
