A4. 第一优先构造：完整链源核错峰
做法
假设提前释放核 s 原来有多条完整链。把它分为：
P_s=\text{少量完整链},\qquad
Q_s=\text{其余完整链},同核顺序为 P_s\to Q_s。其他核暂时仍各一个前沿 Task，最终保留独立尾。
首 Task 加载完自己的输入之后，MTE2 自然停止继续预取；只有首 Task 完成、再经过同核 100，第二 Task 才激活。这个空档来自合法 Task 边界，不是手动延迟 COPY，也不是添加空 Task。
切分位置位于完整链之间，其跨 Task 输出是归约所需的小张量，不是链内 32KiB 张量。
为什么这里“多一次 100”可能反而更快
在等长等输入的小模型中，令：
w=547,\quad L=2096,\quad g=100,\quad \tau=1000.源核先做一条完整链，则第二 Task 释放于
h=2g+w+L=2843.若
g+w<\tau,\qquad
h\ge\tau+(k-1)w,其他核的首批输入就能在源核重新加入竞争之前完成。再假定未切 Task 时源核输入流在这一批期间持续在飞，则远端首输入从
\tau+kw提前到
\tau+(k-1)w,恰好提前一个 w。
对当前参数，静默窗口条件化为
1296\ge(k-2)\times547.它在 k3、k4 成立，k5 不成立。不过，这只证明首输入提前，不证明总 makespan 改善。
总收益必须通过门控余量判定
设尾仍放在源核，原源核前沿结束为 E_s，异核尾门控为
Z=\max_{c\ne s}(E_c+\tau),且原来 Z\ge E_s+g。定义源核的可容忍余量
S=Z-(E_s+g).错峰后，源核慢了 d，异核门控提前 \Delta，尾持续不变。那么在该模型中：
\boxed{T-T'=\min\{\Delta,\ S-d\}.}若尾持续额外增加 \varepsilon，收益再减去 \varepsilon。
这比“DDR 更早到达所以一定更快”严格得多：即使 \Delta>0，只要 d>S，源核就会变成更坏的新瓶颈。

B2. 装箱规则不再写死链数
每条链至少保留以下信息：
(\text{实际节点与 Pipe},\ P_i,\ \text{输入张量身份及大小},
\ \text{末端输出},\ \text{归约树位置},\ \text{官方 FIFO 优先序信息}).不能只保存 P_i 和总字节；相同字节总量、不同输入位置，会有不同暴露等待。
建议只生成两个装箱种子，不迭代搜索全计划：
**计算平衡种子。**按计算量降序，一遍分配到预计计算结束较早的核，稳定图结构键打破平手。

然后，对源核 bin，只考察：
不错峰；
最短的完整链前缀，使预计输入静默窗口覆盖远端首批输入；
与该边界相邻的一个前缀。
这里的“前缀”来自该 packet 的确定 FIFO／结构次序，不是任意子集枚举。首轮另外枚举实际使用核数 2,\ldots,k，从而自动发现“少开一个输入流更好”的情况，不写死首轮四核。
这是有限的一遍生成过程。实际归约树闭包在 packet 确定后执行，再重新计入小 COPY 和尾成本。
B3. 什么状态才充分
对于完整编译后的小事件模型，充分状态至少包括：
\begin{gathered}

\text{计算完成时刻、每个 COPY 的剩余 work、未满足依赖计数},\\

这给出一个规模有限的事件内核，但它仍需要真实 packet FIFO／依赖描述。粗模型缺少这些信息时，只能作为启发式选择器，不能因为状态变量写全了就声称精确对应 E0。
外层 DP 为什么可以只记上一尾核
若每轮都终止于一个独立尾 Task，且它完成时本轮其他 Task 全部完成，则所有 DDR 请求也已经清空。其他核的旧 previous.end+100 被下一轮的根依赖 gate 支配；剩下需要记住的是上一尾核 s。
对固定有限模板集合 \Theta_j：
F_j(e)=
\min_{s,\theta\in\Theta_j}
\left\{F_{j-1}(s)+\delta_j(s,e,\theta)\right\}.相同末态中，较早到达支配较晚到达；makespan 相同时以额外 DDR 作第二键。
**这是所用 profile 语义、有限模板集合内的精确 DP，不是任意 Task 分区最优。**用本轮 D_0 作为 \delta，精确性也只属于 D_0。浮点事件实现的逐位形式化问题仍保留。
跨轮 Task 融合会破坏“清空状态”，届时必须携带未完成 Task、FIFO 和 DDR 状态，不能继续只记一个尾核。

结构解析为 O(|V|+|E|)。逐链装箱为
O(m\log m+km\,C_{\rm profile}).外层固定模板 DP 至多进行
