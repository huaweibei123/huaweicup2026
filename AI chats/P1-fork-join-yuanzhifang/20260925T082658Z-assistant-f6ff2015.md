## 二、“理论上界”应怎样定义

固定图 \(G_i\)、配置和官方程序身份，定义

\[
\mathcal F_{iK}^{E0}
=
\left\{
P:
\begin{array}{l}
P\text{只提交规定的两字段，满足覆盖和联合依赖校验，}\\
\text{且经固定官方编译与E0成功执行}
\end{array}
\right\}.
\]

它**不是所有满足原始计算依赖的 op 级时间表**。官方生成的 COPY、FIFO、spill、MEM 依赖都属于目标函数的组成部分。

\[
OPT_{iK}^{E0}=\min_{P\in\mathcal F_{iK}^{E0}}M_{E0}(P),
\qquad
L_{iK}\le OPT_{iK}^{E0}\le U_{iK}.
\]

这里 \(U\) 是已验证方案的可行上界；需要证明的是 makespan 下界 \(L\)，才能得到加速比上界：

\[
\frac{B_i}{U_{iK}}
\le
\frac{B_i}{OPT_{iK}^{E0}}
\le
\frac{B_i}{L_{iK}}.
\]

官方单核入口将所有非 COPY op 合入一个 Task，并不求单核最优。因此，**不能无条件把 \(K\) 当作相对固定分母 \(B_i\) 的加速比上限**。正式单核曲线仍固定为1，重分区单核的1.0020968只能单列。:chatgpt-content-reference{index="7"}[官方单核入口](sandbox:/mnt/data/p1_r4_evidence/data/raw/a/official/code/singlecore_evaluate.py)

另一个必须明确的量词规则是：

> 若全域被子域覆盖为 \(\mathcal F=\bigcup_\theta\mathcal F_\theta\)，每个 \(L_\theta\) 仅对自己的子域有效，则能推出的全域界是 \(\inf_\theta L_\theta\)，不是 \(\max_\theta L_\theta\)。只有多个界各自已经全域有效，才可以取最大值。

这就是固定分区、固定签名或“不切链”证书不能直接升级为全局界的原因。

## 三、已有下界审计：理想服务证明基本成立，E0 数值桥仍有缺口

### 3.1 哪些 COPY 确实不可省

令 \(P(t),C(t)\) 为张量 \(t\) 的直接非 COPY 生产者和消费者。源码采用的必要集合是：

\[
I=\{t:P(t)=\varnothing,\ C(t)\ne\varnothing\},
\]

\[
O=\{t:P(t)\ne\varnothing,\ 
C(t)=\varnothing\text{ 或存在原 COPY\_OUT 消费者}\}.
\]

任意分区中，\(I\) 的某个消费 Task 没有本地计算生产者，因此必须重建输入 COPY；\(O\) 的生产者所在 Task 满足输出边界条件，因此必须重建输出 COPY。**同核 Task 边界没有豁免。**这与官方边界重建代码相符。:chatgpt-content-reference{index="8"}[E0 边界重建，110–171行](sandbox:/mnt/data/p1_r4_evidence/data/raw/a/official/code/multicore_cut_evaluate_problem_1.py)

多消费者时，选择实际服务“必要尾最长消费者”的那次读；若被 spill 重写，则选择实际重载读，而不是机械选择首条 COPY_IN。多生产者时，选择“必要释放最晚生产者”之后的那次写。按不同原张量选出的服务实例互不重复，输入、输出必要集合也不相交。

本100图没有多计算生产者张量或零字节张量，但通用代码仍应保留相应证明。零字节 COPY 的工作量是1，不是0。

### 3.2 已实现的不是完整窗口

原实现使用的是每个完整资源集合的

\[
r_{\min}+\left\lceil W/c\right\rceil+q_{\min},
\]

而非对所有 release/tail 双阈值求最大值。独立复算后，其500格标量、资源记录、关键路径及派生 JSON/CSV 全部一致。:chatgpt-content-reference{index="9"}[原下界实现，100–140行](sandbox:/mnt/data/p1_r4_evidence/src/q1/lower_bounds.py)

- 必要 COPY 逐条按 \(\max(1,\lceil\text{bytes}/60\rceil)\) 取整，再相加。
- COPY 同时占相应 MTE Pipe，因此其 Pipe 工作除以 \(K\)。
- 全局 DDR 服务不除以 \(K\)。
- 不同资源可重叠，只能取最大值，不能把计算界与 DDR 界直接相加。
- 计算关键路径只能使用确定保留的直接／张量计算依赖，不能使用可能在同 Task 重建中消失的原 COPY 桥。

## 四、两个全域有效的加强

### 定理一：保留计算 DAG 上的双阈值窗口

对每个非 COPY 操作 \(v\)，在确定保留的计算 DAG 上计算

\[
r_v=\max_{u\to v}(r_u+d_u),\qquad
q_v=\max_{v\to u}(d_u+q_u),
\]

空最大值为0，且 \(r_v,q_v\) 都不含 \(v\) 自身时长。

对 Pipe \(p\)，取非空集合

\[
S_p(a,b)=\{v:p(v)=p,\ r_v\ge a,\ q_v\ge b\}.
\]

则任意成功的官方方案满足

\[
\boxed{
M\ge
a+b+
\left\lceil\frac{\sum_{v\in S_p(a,b)}d_v}{K}\right\rceil.
}
\tag{1}
\]

**证明。**每个选中操作只能在 \([a,M-b]\) 内执行；该 Pipe 的 \(K\) 个槽至多提供 \(K(M-a-b)\) 的执行量。非 COPY 持续时间和时刻均为整数，故得到取整式。证明不需要自主提交 op 调度，也不需要任何 DDR 守恒假设。

空集必须排除；公共尾只加一次 \(b\)；不同 Pipe 分别计算后取最大值。

**实现与验证。**按 \(r\) 降序激活，按 \(q\) 坐标做前缀加／最大值查询，每 Pipe 为 \(O(n\log n)\)。只查询非空窗口。证书记录 Pipe、\(K,a,b\)、选中数量、总工作与 ID 哈希；验证器线性重新筛选即可，不必重做“最强窗口”搜索。

### 定理二：通用计算屏障的双向 Task gate 界

这是本轮更有价值的新加强：它不固定 Task 分区，也允许跨轮 Task 融合。

称计算节点 \(a\) 为**通用分隔节点**，当且仅当每个其他计算节点 \(v\) 都满足 \(v\leadsto a\) 或 \(a\leadsto v\)。这些节点按拓扑序把其余计算划成不重叠的首段、中间段和末段。

设中间段位于分隔节点 \(a,b\) 之间，令

\[
x=start(b)-finish(a),\qquad \tau=1000.
\]

假设 \(a,b\) 分别位于核 \(s,e\)。段内核 \(c\) 上的计算只能占用

\[
\left[
finish(a)+\tau[c\ne s],\
start(b)-\tau[c\ne e]
\right]
\]

中的时间：从 \(a\) 出核、向 \(b\) 回核的保留路径各至少包含一次跨核 Task 门控。

若两个端点同核，该 Pipe 的总容量至多

\[
F_{\rm same}(x)=x+(K-1)(x-2\tau)_+.
\]

若两个端点异核，则至多

\[
F_{\rm diff}(x)=2(x-\tau)_++(K-2)(x-2\tau)_+.
\]

分段检查可得 \(F_{\rm diff}(x)\le F_{\rm same}(x)\)。因此，在**未知端点放核**的情况下，取后者作为容量上包络仍然安全。

定义

\[
\phi_{K,0}(W)=\lceil W/K\rceil,
\]

\[
\phi_{K,h}(W)=
\min\left\{
W,\
\left\lceil\frac{W+h\tau(K-1)}{K}\right\rceil
\right\},
\quad h=1,2.
\]

其中 \(h\) 是段的分隔端点数。令 \(W_{jp}\) 为段 \(j\) 在 Pipe \(p\) 上的计算量，则

\[
\boxed{
M\ge L_{\rm sep}
=
\sum_{\text{分隔节点 }a}d_a
+
\sum_{\text{段 }j}\max_p\phi_{K,h_j}(W_{jp}).
}
\tag{2}
\]

**为什么可以相加？**这里的段按真实计算操作的开始／完成时刻划分，彼此不重叠；不是当前算法的 stage 估计。分隔节点自身只计一次。跨段融合不破坏证明，因为同核分支已经允许所有工作留在一个核；只有真实换核路径才强制1000。

**不能另外每段加100。**合法融合可能避开同核 Task 边界；首 Task 也没有自动100。

识别通用分隔节点可用正、反向 Kahn 唯一源／唯一汇交集，时间 \(O(n+e)\)。独立验证器采用另一种按段可达性检查，验证每个成员从左端可达、向右端可达，不复用生成器的识别逻辑。完整证明与算法见:chatgpt-content-reference{index="11"}[论文草稿第5节](sandbox:/mnt/data/p1_r4_report/theory_draft_zh.md)。

## 六、迭代有没有数学方向保证

### 6.1 可以证明的是“保留与选择规则”，不是所有构造修改

若固定同一图、核数、配置和准确目标，成功候选集满足

\[
\mathcal C_t\subseteq\mathcal C_{t+1},
\]

并始终保留旧成功输出、按同一精确 E0 取优，则

\[
U_{t+1}\le U_t.
\]

若新下界也经过同域验证，并令

\[
L_{t+1}=\max(L_t,L_{\rm new}),
\]

则 \(L_{t+1}\ge L_t\)，认证区间嵌套。

但这**不保证收敛全局最优**：候选集可能永远不包含最优计划。若按 makespan、extra DDR 字典序选择，只保证 makespan 不增加；makespan 改善时 DDR 可以增加。

### 6.2 实际 v4 尚不满足“无条件 E0 单调”的证明前提

源码确实限制最多6个不同候选，但用 E1 排序。缺少 E1 实现，就不能把其“exact”命名当作等价证明。:chatgpt-content-reference{index="15"}[v4 候选及选择控制器](sandbox:/mnt/data/p1_r4_evidence/src/q1/unified.py)

最小排序反例是：

\[
M_{E0}(P_{\rm old})=10,\quad M_{E0}(P_{\rm new})=11,
\]

而 E1 分别给10、9。即使保留旧候选，E0结果仍会退化。

预算与失败分支也有条件：`choose` 会保留此前成功评分者；但**首项就失败时返回的是未获在线验证的基本候选**，单候选快路径也不在线评分。新增构造或编译耗尽预算，使旧成功候选没有机会保留，不满足嵌套成功集定理。

可修复方式是保留同身份的旧已认证计划，或给评分器建立误差界并采用区间接受规则。没有误差证书时，不能用“E1多数样例一致”替代这一条件。

### 6.3 追加空核能证明最优值随核预算不增

官方允许尾部空核序。保持 mapping、Task ID、原核编号与核序不变，仅追加空数组，不改变原 Task 编译顺序；新核不发射任何操作。对事件归纳，既有发射、退休、DDR字典顺序及浮点运算次序均不变。因此：

\[
\boxed{OPT_{i,K+1}^{E0}\le OPT_{iK}^{E0}.}
\]

当前 v4 的13个4→5核退化，只说明其逐核独立构造没有继承该可行解，不说明物理最优值会恶化。

在线修复不能查历史图号：应在当前输入上生成较低核预算的父候选，追加空核后纳入准确选择。代价必须进入完整 solver 墙钟；若重做全部1–5核基础候选，最坏评分尝试规模可能从至多6扩大到 \(1+4\times6=25\)，缓存只能在签名等价有证据时抵扣重复工作。

历史包络 **4.036858344737648** 已算术复得，但仍不是新统一入口成绩，也没有对应的新墙钟。
