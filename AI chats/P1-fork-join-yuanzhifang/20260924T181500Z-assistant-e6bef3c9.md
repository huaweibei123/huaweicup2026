三、允许任意跨轮 Task 的严格界

下面的证明不要求整链不切、不要求独立共享尾，也不要求归约树串行。

3.1 两层适用条件

基础界 $210452$ 需要：

给出的重链、归约及跨轮根依赖都保留；

COPY 只能在所属 Task 激活后执行；

一个尚未在该 Task 内生成的 32KiB 链输入，进入新 Task 时必须有自己的 COPY_IN，包括同核 Task 边界；

DDR 总归一化容量至多 1，Task 完成与 100/1000 gate 保持原语义。

加强式 $(★)$ 还需要：跨 Task 的链内部 32KiB 张量必须在生产 Task 完成前 COPY_OUT，并由消费 Task COPY_IN，无同核直通例外。

容量阻塞、spill 和小 COPY 可以存在；证明没有把它们作为可省略的负开销。

3.2 核心结构引理：跨轮 Task 是一个串行前缀屏障

合法 Task 商图无环，意味着：

同一 Task 中两节点之间的任何计算依赖路径，都不能离开该 Task 后再返回。

否则商图出现环。

令 $t_j$ 为第 $j$ 轮根 ADD 操作的完成时刻，而不是根 Task 的结束时刻。设 $P$ 是包含上一轮根的 Task。

若 $P$ 包含本轮某条链的节点，则它必须包含该链从首操作开始的一段前缀。所有不在 $P$ 中的本轮操作，其 Task 都必须等待 整个 $P$ 完成，不能在 $t_{j-1}$ 时就启动。

因此可以定义：

$u$：本轮整条四节点链都在 $P$ 中的条数；

$c$：只有非空真前缀在 $P$ 中的条数；

$p_1,\ldots,p_c\in\{524,1048,1572\}$：这些前缀的计算长度。

令
$X=uL+\sum_{i=1}^{c}p_i,\qquad
p_{\max}=\max_i p_i,$
空集合时 $p_{\max}=0$。

由于一个核只有一个 PIPE_V，且本轮计算都依赖上一根，
$P.end\ge t_{j-1}+X.
\tag{2}$
这已经包含了跨轮融合的阻塞代价。

3.3 “第一个外部输入”窗口

若 $u<12$，每条没有完整留在 $P$ 中的链，都有一个“第一个在 $P$ 外执行的操作”。

它的 32KiB 输入要么是原始输入，要么是切口中间张量。因此至少有
$m=12-u$
个大 COPY_IN，必须在 $P$ 完成、并经过至少 100 的新 Task gate 之后执行。

公平共享并不改变以下容量事实：这些 COPY 全部完成，至少需要 $mw$ 的总归一化服务时间。

最后完成的这类 COPY 到本轮根，还至少有
$L-p_{\max}+13$
的计算路径。于是
$\begin{aligned}
\Delta_j:=t_j-t_{j-1}
&\ge X+100+(12-u)w+L-p_{\max}+13\\
&=8773+u(L-w)
+\left(\sum_i p_i-p_{\max}\right)\\
&\ge8773.
\end{aligned}
\tag{3}$
这里没有假设 COPY 独占服务器，也没有把多个 COPY 的实际驻留时长相加。

若 $u=12$，仅同一个 Task 内的重链计算就需要
$12L=25152>8773.$
首轮没有前一 Task gate，但十二个原始大输入都必须加载，故
$t_1\ge12w+L+13=8673.$
累加真实根操作之间的时间区间：
$\boxed{
C_{\max}\ge t_{24}
\ge8673+23\cdot8773
=210452.
}
\tag{4}$
这是任意合法 Task 分区的条件下界。它不使用 local_makespan，也不把当前算法的 stage 时间当作通用量。

3.4 强化：少重载一个输入，不能没有阻塞代价

现在加入强制 COPY_OUT 条件。

当 $u=0,c>0$ 时，$P$ 中本轮没有任何完整重链，因此也不能包含本轮归约 ADD。它最后一个本轮 V 操作必然产生一个交给外部 Task 的大张量。

这个 COPY_OUT 必须在该最后 V 操作结束之后，且在 $P$ 完成之前执行。因此式 (2) 加强为
$P.end\ge t_{j-1}+X+w.$
代回输入窗口：
$\Delta_j
\ge8773+w+\sum_i p_i-p_{\max}
\ge8773+547+(c-1)524.
\tag{5}$

$\boxed{\Delta_j\ge8773+524(u+c).}
\tag{7}$
还有两个更直观的判定：
$\Delta_j<9320
\quad\Longrightarrow\quad
P\text{ 不含本轮任何首操作};$$\Delta_j<10322

3.5 重载次数的量词

对一个原始输入，按 24 轮列出其首操作所属 Task。

同一个 Task 不可能在这个序列中离开后再出现：如果它包含第 $r$ 和第 $r+2$ 轮的首操作，路径凸性会强制它也包含中间轮的该首操作。

因此，令 $M$ 为十二个输入对应的不同“输入—消费 Task”对数，可写成
$M=288-\text{相邻轮中同输入、同 Task 的次数}.$
每次相邻轮同 Task，都意味着当前首操作位于上一根 Task 中。所以
$288-M\le\sum_{j=2}^{24}(u_j+c_j).$
结合式 (7)：
$\boxed{C_{\max}\ge210452+524(288-M).}
\tag{8}$
另一方面，每个输入—Task 对至少加载一次，每个大内部切口至少 OUT＋IN：
$\boxed{C_{\max}\ge547(M+2B).}
\tag{9}$
这就证明了开头的联合证书 $(★)$。

四、小 DP 的状态、停止条件与可提交构造

4.1 对完整 E0 语义，负载数不是充分状态

小事件内核至少要保留每核当前 Task 的实际 MTE2/V/MTE3 FIFO 位置、操作依赖就绪状态、在飞计算完成时刻、DDR COPY 剩余工作，以及 L1/UB 分配状态。

仅有“本核几条链、多少 V 工作、多少字节”不够：前面一个 2B 输入位置的反例已经说明，同样的统计量可以产生不同的启动与停顿。

若一个模板严格保持“本轮所有前沿完成后，才运行独立归约尾”，那么尾 Task 完成时，本轮所有其他 Task 已完成，DDR 也没有遗留在飞请求。下一轮重新加载输入，不依赖跨 Task 缓存。

在这种完整清空的轮边界上，且资源回收与同刻事件顺序不携带未建模历史时，状态可缩为上一尾核 $s$。其他核的旧 previous.end+100 已被下一轮的根依赖 gate 支配。

于是对固定、有限的结构模板集合 $\Theta_j$，有
$F_j(e)=
\min_{s,\theta\in\Theta_j}
\left[
F_{j-1}(s)+\delta_j(s,e,\theta)
\right].
\tag{10}$
其中 $\delta$ 必须来自该模板实际生成 FIFO 的小事件模型，不能用 local_makespan 替代。若用 $D_0$ 算 $\delta$，最优性也只属于 $D_0$。

若模板数上限为 $H$，每个模板有 $E$ 个事件，朴素复杂度约为
$O(Rk^2H\cdot E k\log k),$
另加官方局部 FIFO 构建与合法性检查。$k\le5$ 时，共享服务的排序部分很小。

停止条件是：有限轮数、有限模板的前向 DP 全部完成。不做“直到没有改进”，不扫描全体 Task 计划，也不需要 E0 在线选优。使用相同时间的最优状态时，可用额外 DDR 作第二排序键。

4.2 整子树融合可以进入模板，但旧的工作量树 DP 不能原样沿用

允许前沿 Task 吸收一棵完整归约子树，其输出变成少量 2B 子树根，可以减少小边界 COPY 和归约尾工作。

但在公平共享下，两个子树的代价不再由各自的“工作量＋release＋tail”独立决定：它们的 COPY 到达会相互影响。

因此可采用少量结构生成模板，例如整链负载模板与完整子树模板，再做式 (10)。**这是模板集合内的 DP，不是全体子树划分、更不是全体合法 Task 分区的精确 DP。**实际树形状和官方 FIFO 都必须进入模板，不可默认归约为十一条串行依赖。

4.3 当前直接构造不需要跨轮融合

对 143-Task 方案，按已识别的十二条完整链作确定性分组：

首轮负载为 3/3/3/3/0；其余轮为 4/2/2/2/2。每轮所有 ADD 放独立尾，尾固定 core0。

给 Task 标记
$(\text{轮号},\text{前沿或尾}).$
所有 Task 依赖及核序都严格增加该字典序：本轮前沿到本轮尾，上一轮尾到下一轮前沿；每核也按此顺序追加 Task。因此联合图无环。

这里直接生成计算节点的 node_to_subgraph 和各核 Task 顺序即可，不提交或篡改任何 op FIFO。

跨轮融合若满足共同拓扑序中同核连续区间合并的条件，仍可证明无环；但它会留下未完成的跨轮 Task，式 (10) 的“只记尾核”状态随即失效。需要记录在途 Task、剩余 FIFO、DDR 和内存状态，不能仍称为同一个小 DP。前面的全分区下界则没有这个限制。
