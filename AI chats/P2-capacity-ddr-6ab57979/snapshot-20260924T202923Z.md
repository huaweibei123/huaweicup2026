# 三、问题一：固定分核和 eligible 顺序，切分/合并到底改变什么？

## 3.1 必须分开三层图

令：

\[
D_{\rm legal}
\rightarrow D_{\rm base}(\pi)
\rightarrow G(\text{plan}).
\]

其中：

- \(D_{\rm legal}\)：stub 为计划合法性构造的 eligible DAG，包含原 COPY 路径收缩。
- \(D_{\rm base}(\pi)\)：P2 根据核映射 \(\pi\) 实际重建的本地 tensor、基础 COPY 与计算图。
- \(G(\text{plan})\)：经过 Step2 spill、Step3 内存复用编译，再加入 pipe FIFO 和跨核 COPY 延迟的实际全局执行图。

**第一层中的收缩边，不自动成为第三层中的计时边。**

源码依据：`stub_multicore_cut_and_schedule.py` 70–89、157–231 行；P2 61–274 行；`evaluation_validation.py` 226–243 行。全文报告列出了逐项定位。

## 3.2 P2 每核一个 Task，不是每子图一个 Task

冻结 P2 将同核全部子图汇集成**一个 Task**，统一经过 Step1、Step2、Step3。

因此不存在以下 P1 式推论：

> 每增加一个子图边界，就重新加载该子图所有输入，或者清空该子图之前的片上驻留。

P2 子图边界主要影响**优先级归属**，不是独立缓存域，也不是显式执行 barrier。

## 3.3 命题：固定核映射，基础 COPY 多重集不变

对原 tensor \(t\)，定义 eligible producer、consumer 所在核集合为 \(P_t,Q_t\)，大小为 \(s_t\)。

冻结 P2 的规则是：

- 无 eligible producer：每个消费核一份基础 IN。
- 是最终输出：每个生产核一份最终 OUT。
- 每个不同的生产核、消费核对：一份 OUT 加一份 IN。
- 跨核 direct eligible 边：另建本地 UB tensor 和一对 COPY。
- 原 DDR tensor 的本地副本放到 UB。

特别注意：**一个源 tensor 发往两个目的核，源端有两次 OUT，不是共享一次 OUT。**

基础 COPY 字节数为

\[
B_0(\pi)
=
\sum_t s_t(i_t+f_t+2x_t)
+
2\sum_{e\text{ 为跨核 direct 边}}s_e,
\]

其中

\[
i_t=\mathbf1[P_t=\varnothing,Q_t\ne\varnothing]|Q_t|,
\]

\[
f_t=
\mathbf1[P_t\ne\varnothing,\ t\text{ 按P2规则需最终输出}]|P_t|,
\]

\[
x_t=|P_t||Q_t|-|P_t\cap Q_t|.
\]

**证明要点：**这些生成条件只依赖原图和核映射；子图边界只决定 COPY 挂在哪个优先级桶，不决定生成次数或大小。依据是 P2 150–238 行。

所以：

| 固定分核、固定每核 eligible 投影后 | 是否必然不变 |
|---|---|
| eligible 工作量、pipe、分核 | 不变 |
| 基础 COPY 数量、大小、跨核配对及 500-cycle lag | 不变 |
| COPY 所属优先级桶、完整 Step2 输入序 | **可能改变** |
| spill、backing、incarnation、spill 字节 | **可能改变** |
| MTE2/MTE3 FIFO、内存复用边 | **可能改变** |
| 实际开始/结束时刻、M | **可能改变** |
| 商图及最终全局图是否合法 | 必须重验 |

另一个细节：**零字节 COPY 仍有最少 1 cycle 服务时间，跨核仍有 500-cycle lag。**

## 3.4 为什么只保留 eligible 顺序不够？

P2 先计算每核原始 Step1 序 \(R_c\)，再按子图 rank 稳定排序。同一子图内部保留 \(R_c\) 相对顺序。

因此，合并可能让 COPY 跨过其他 eligible 操作，即便 eligible 投影完全没变。

一个足够强的不变性命题是：

> 固定物理图、核映射、确定性 tie-break，并且**包含全部基础 COPY 的完整 Step2 输入序相同**，则 Step2、Step3、全局时序相同；子图标签与时间线分组除外。

证明就是对三个确定性状态机逐事件归纳。**不能把这里的“完整序”弱化成“eligible 序”。**

## 3.5 三个直接反例，以及一个合法性反例

**合并可以增加 spill。**  
两个 eligible 同核：\(u\) 在 M 上 10 cycles，\(v\) 在 V 上 10 cycles，且 \(u\to v\)。\(u\) 产生 80,000 B 最终输出 \(z\)，\(v\) 消费另一个 80,000 B 输入 \(x\)。

```text
singleton：u, OUT(z), IN(x), v
合并后：   u, IN(x), v, OUT(z)
```

eligible 顺序都是 \(u,v\)，但后一序列要同时保留 \(x,z\)，超过 UB。冻结结果：

\[
M:2688\to5356,\qquad spill:0\to160000\text{ B}.
\]

**合并也确实能提速。**  
核0 上 \(u(M,1),v(V,1)\)，核1 上 \(w(M,10000)\)。\(u\) 产生 60,000 B 最终输出 \(z\)，\(v\) 产生给 \(w\) 的 60 B 跨核输入 \(y\)。

```text
singleton：u, OUT(z), v, OUT(y)
合并后：   u, v, OUT(y), OUT(z)
```

基础 COPY 字节与 spill 均不变，M 从 **11,503 降至 10,505**。收益来自关键小 OUT 绕过大最终 OUT 的 MTE3 队头阻塞。:chatgpt-content-reference{index="6"}[合并提速原件](sandbox:/mnt/data/p2_analysis/merge-help-probe.json)

**COPY 收缩不能直接给时间下界。**  
原图：

```text
u(10000) → UB → COPY_OUT → DDR → COPY_IN → UB → v(10000)
```

\(u,v\) 分在两核。合法性收缩得到 \(u\to v\)，但冻结 P2 重建的是两个独立出入 COPY，没有对应 cross link。实际 \(u\) 在 0–10000，\(v\) 在 1–10001，官方：

\[
M=10001<20000.
\]

这反驳“收缩计算路径串行和必为 P2 下界”，不是建议利用语义缺口；合法性合同仍要满足。

**同核连续也不保证能合并。**  
\(u\to w\to v\)，\(u,v\) 在核0，\(w\) 在核1。合并 \(u,v\) 为 A 后商图成为 \(A\to W\to A\)，被拒绝。

以上反例的图、计划和结果均已保存。:chatgpt-content-reference{index="7"}[语义反例原件](sandbox:/mnt/data/p2_analysis/semantic-probes.json)

## 3.6 Step3 还有一个容易漏掉的约束

本地 Step3 不仅固定每条 pipe 的 FIFO，还按 `seq_ext` 的 allocation 顺序申请输出空间，并将空间复用编译成 WAR/WAW 边。

**全局 P2 保留这些 memory edges，却不重跑本地 allocation-order 门。**

因此：

- 自写“全局即时申请释放内存、任意 ready 操作发射”的模拟器，不等价于官方。
- 本地 Step3 时长不一定是全局下界。实测 008 旧方案本地为 **85,059**，全局却是 **84,303**。
- `memory_peak_by_core` 是本地 Step3 报告值，不能冒充从最终全局时间线重新计算的峰值。

# 四、问题二：主推“规范化 COPY 的生命周期前沿调度”

这是一条主路线，不另推多算法组合选优。**初版保持 singleton 输出**，先把容量与 COPY 队列做好；合并仅作为后续受限局部转移。

## 4.1 容量层：从真正的物理 token 开始

固定核映射后，按 P2 生成本地 token：

```text
(original_tid 或 direct_edge_id,
 core, pool, size,
 producer, consumers,
 import/export COPY obligations)
```

必须同时做到：

- 原 DDR 本地副本记 UB。
- 跨核 direct 边生成的 UB buffer 也计入容量。
- 一个源 tensor 发往多个核，源空间只计一次，COPY 工作按目的核分别计。
- 同核多个消费者不能重复计算基础 IN。

这一步使容量证书可以覆盖跨核分支，而不是直接把当前完整弱分量域内的 `footprint` 无条件套到 gap 上。

## 4.2 一个精确的 Step2 无 spill 判据

对完整基础 Step2 输入序，令本地 tensor \(t\) 的首次、末次触碰位置为 \(a_t,b_t\)。定义：

\[
H_{c,p}(i)=
\sum_{\substack{t\text{ 在核 }c\\pool(t)=p}}
s_t\,\mathbf1[a_t\le i\le b_t].
\]

**命题：冻结 Step2 返回零 spill，当且仅当所有 \(H_{c,p}(i)\le C_p\)。**

证明很直接：Step2 是先申请本步输入/输出、再检查、最后释放末次使用。没有此前 spill 时，第 \(i\) 步检查集合恰好是这些闭区间覆盖的 tensor。首次超容量时，要么发生 spill，要么因没有合法 victim 报错，不可能仍零 spill 返回。

对 singleton，可以把同桶触碰一起计入，构成更保守的 \(\bar H\)。在**唯一 producer、无未建模 alias、正确包含 P2 合成 token**的域内：

\[
\bar H\le C\Longrightarrow H\le C\Longrightarrow spill=0.
\]

这是充分证书，不是并行执行峰值公式，也不是 M 不退化定理。

## 4.3 用真实前沿替代永久共享输入预留 \(S\)

前缀 \(X\) 上维护：

\[
F(X)=\{t:\text{已经触碰，且仍有未来触碰}\}.
\]

下一桶 \(u\) 引入新 token 集 \(N(X,u)\)，本桶结束可以释放的集合为 \(Z(X,u)\)。转移为：

\[
peak_p(X,u)=
\sum_{t\in F(X)\cup N(X,u),\,pool(t)=p}s_t,
\]

先检查容量，再执行，最后

\[
F(X+u)=
(F(X)\cup N(X,u))\setminus Z(X,u).
\]

**共享输入不应从开头永久预留；但也不能在某个作业结束时释放，只要还有未来消费者。**

这里必须存 token 身份与未来引用数，仅存 L1、UB 两个字节总量不够。

### 可以严格突破 \(S\) 的结构

固定核映射、完整作业同核，若存在作业顺序，使每个共享输入的消费者作业连续出现，则串行作业 \(j\) 的共享驻留集合只是它实际使用的共享输入，而不是全核共享输入并集。

设该集合大小为 \(S_{j,p}\)，私有峰值为 \(P_{j,p}\)，则：

\[
\forall j,p,\quad S_{j,p}+P_{j,p}\le C_p
\]

足以保证无 spill，而且每个共享输入仍只做一次基础 IN。

例如，A 组共享 80,000 B 输入，B 组共享另一个 80,000 B 输入，各自私有峰值不超过 40,000 B。永久 \(S=160000\) 会拒绝；先 A 后 B 峰值不超过 120,000 B，实际可行。

但三角交叠不能这样消掉：

\[
J_1=\{a,b\},\quad J_2=\{b,c\},\quad J_3=\{a,c\},
\]

其中 \(a,b,c\) 各 65,536 B。任何顺序在第二个作业都需同时保留三输入，峰值 196,608 B。不能按签名分组后假释放。移一个作业到另一核可能消除该障碍，但输入副本从 3 份变 5 份，**基础 DDR 增加 131,072 B**。

## 4.4 有界前沿 DP：精确容量可行性，而非假装精确全局最优

区域内固定 \(w\) 条链或作业的内部词，长度为 \(n_1,\dots,n_w\)。状态：

\[
q=(q_1,\ldots,q_w)
\]

记录各词提交了多少操作，并携带边界 token 的未来引用状态。

转移只允许取某词的下一个操作，且满足：

\[
D_{\rm legal}\text{ 前驱已提交},\qquad peak_p(q,u)\le C_p.
\]

倒序计算 `CanFinish[q]` 并保存一条排空见证。这样排除的不只是“当前放不下”，还包括“走这一步后，该局部区域无法完整排空”。

穷尽时，它精确判定**给定内部词、给定边界、零 spill**条件下的可行交织。状态数上界：

\[
\prod_{j=1}^{w}(n_j+1),
\]

或对 \(r\) 个区域操作采用至多 \(2^r\) 个理想集状态。

必须诚实区分：

> \(n^w\) 不是关于 \(w\) 的 FPT；预算用完不是无解证明；区域可行不是整个 P2 最优。

建议初版固定小区域上限，例如 \(r\le12\)、单区最多 4096 状态，再限制全图总转移量。大的重复作业群用 profile 缓存和流式窄窗口，不一次塞入指数 DP。缓存依据结构、大小、pipe、输入等价关系，不依据图号或历史成绩。

separator 应建立在 **op–tensor 关联图/超图**上；只看 eligible 二元 DAG 的窄割，会漏掉跨很多作业共享的大输入。

## 4.5 DDR 层：真实服务规律，不是静态边延迟

每个 COPY 的独占服务量应为：

\[
d_v=\max(1,\lceil b_v/60\rceil),
\]

必须**逐 COPY 取整后相加**。

若当前有 \(m\) 个正剩余工作的 DDR COPY：

\[
\frac{dw_v}{dt}=-\frac1m.
\]

预测器必须处理分数 cycle 内的完成与带宽重新分配，以及：

\[
ready(IN_{a\to b,t})=
finish(OUT_{a\to b,t})+500.
\]

队列状态至少包括：各核各 pipe 的固定前缀与队头、待发与在飞操作、跨核 release、各 COPY 剩余独占工作，以及本地 Step3 的 allocation cursor、resident/refcount、credit FIFO 来源。

**不能只保留每条 pipe 的一个 tail。**

更重要的是区分两个接口：

- **`PredictWindow`**：对有限区域和固定补全见证运行队列预测。公平共享规律真实，但外部未来 arrival、最终 memory edges 未全部确定，因此返回的是预测分数，**不是 E0 M，也不是上下界**。
- **`CompileFinal`**：对唯一完整计划按冻结语义编译本地 Step3，再验证全局 DAG。此后在完整 \(G\) 上运行公平共享核，才可以要求逐操作时序与 E0 一致。

这避免了用“容量 DP 精确”偷换“整个队列预测也精确”。

## 4.6 可实施的整体构造

宏分配先保留轻弱分量作为完整分核单元；计算工作超过全图负载放松界的重分量，才开放内部链分核。完整单元至多检查 \(k\) 个核，尚未分配的最后父/join 小块至多检查 \(k^2\) 个核对。

每个候选同时更新真实 COPY obligations、生命周期 profile 和队列预测。完成后冻结核映射，再做前沿排序与最终精确证书。

```text
BUILD(graph, k, config):
    验证原图、配置，建立 D_legal
    保留现有 alias / 结构 guard
    超域则走现有确定性回退，明确不声称本证书

    用结构 profile 做有界宏分配
        比较真实 COPY 服务/字节增量、容量、出口完成预测

    计算固定物理图的 Step1 原始 rank

    while 尚有 eligible 操作:
        选择一个小的 ready 前沿区域
        计算容量 CanFinish 与排空见证
        排除容量失败或无排空见证的下一步
        对剩余下一步做有预算的 PredictWindow
        按固定规则选一个，提交桶，更新引用计数和队列状态

    生成真实完整 COPY 优先级序
```

没有合法下一步，只能说明当前路线或受限区域失败，不能宣布全图无解。回退按结构失败原因触发，不按 E0 成绩触发。

### 能保证和不能保证的事

**可以证明：**完整证书通过时无 Step2 spill；固定核映射时总 COPY 字节降到 \(B_0(\pi)\)，少掉的恰是旧 spill 字节。

**不能保证：**无 spill 总比少量 spill 快；输入分组不损失并行；改变分核后基础 DDR 不增加；主算法各图 M 都改善。

对 fork/join，一个严格排除条件是：

> 候选已经强制产生的真实服务/依赖下界，不小于某完整合法参考计划的已证上界，则候选不可能更好。

除此之外，“计算重叠收益大于新增 DDR 独占服务量”只是启发式，不是充分定理；最后父与 join 同核也不是普适最优规则。

### 求解耗时为什么有机会下降？

新增层使用稀疏引用计数、固定大小前沿、profile 复用和全图工作预算，不维护无界 AVL 历史插空搜索。DDR 同时活跃者最多 \(2k\)，事件处理本身很小。

但总耗时必须加上规范化、索引、Step1/2/3 编译、验证、回退和 I/O。**不能证明现有所有 Python 辅助过程都是线性的，也不能从源码外观把 014 的超时归因于 AVL。**

尤其是：先完整运行 gap 再修复，只能验证 M 的修复能力，不能据此宣称生产 solver 端到端更快。

## 5.2 对固定完整编译图的有效上下界

在真实 \(G\) 上定义：

\[
W_D=\sum_{v\in DDR\ COPY}d_v,
\]

\[
L_{\rm pipe}=\max_{c,p}\sum_{v\in(c,p)}d_v,
\]

\[
L_{\rm CP}=\operatorname{longestPath}(G;d,\text{lag}),
\]

\[
L=\max(W_D,L_{\rm pipe},L_{\rm CP}).
\]

则：

\[
L\le M(\text{plan}).
\]

这里通常是**固定计划下界**，不能拿含该计划 spill、FIFO、memory edges 的 \(L\) 去证明所有方案的最优值。

还有一个可计算的保守上界。因为最多 \(2k\) 个 DDR COPY 同时在飞，每个 COPY 持续时间至多 \(2k\,d_v\)。令：

\[
\bar d_v=
\begin{cases}
2k\,d_v,&v\text{ 为DDR COPY},\\
d_v,&\text{其他},
\end{cases}
\]

\[
U=\operatorname{longestPath}(G;\bar d,\text{lag}).
\]

对冻结全局阶段：

\[
M(\text{plan})\le U.
\]

**证明要点：**每个 COPY 的服务率至少 \(1/(2k)\)；固定 pipe 相邻边已经加入 \(G\)，全局发行是这些真实约束下的 ASAP，没有额外子图 barrier。按拓扑序归纳开始和结束时刻即可。

| 095 | 950,334 | 359,718 | \(U_{\rm new}<L_{\rm gap}\) |

```python
        return plan,{'accepted':False,'reason':'logical aliases outside certificate domain'}
    inverse={sg:int(u) for u,sg in mapping.items()}
    sequences=[[inverse[sg] for sg in s] for s in plan['core_schedules']]
    details=[];new_schedules=[]
    for c,sequence in enumerate(sequences):
        jobs=list(dict.fromkeys(ix.owner[u] for u in sequence))
        if set(sequence)!={u for j in jobs for u in ix.components[j]}:
            return plan,{'accepted':False,'reason':'split component outside this minimal probe domain'}
        width=ix.window_size(jobs)
        revised,clock=ix.pipe_window(jobs,width,prefer_fill=False) if jobs else ([],{})
        peak=footprint(ix,revised)
        if any(peak[p]>capacity[p] for p in capacity):
            return plan,{'accepted':False,'reason':'candidate not certified','failed_core':c,'peak':peak}
        new_schedules.append([mapping[str(u)] for u in revised])
        details.append({'core':c,'width':width,'bucket_peak_bytes':peak,'priority_coordinates':clock})
    candidate={'node_to_subgraph':dict(mapping),'core_schedules':new_schedules}
    derive_multicore_plan(graph,candidate)
    return candidate,{'accepted':True,'details':details,'online_E0_calls':0,'claim':'Step2 no-spill certificate only; no makespan guarantee; not the full joint DDR algorithm'}
```

```python
"""Fixed-plan P2 bounds; no global E0 evaluation and no plan search.

Compiles the frozen local pipeline (including actual Step2 spills and Step3
memory dependencies), validates the global DAG, and computes L <= M <= U.
The bound is plan-specific except for the separate eligible-compute bound.
"""
from __future__ import annotations
import argparse
from collections import defaultdict
import hashlib
import heapq
import json
from pathlib import Path
import sys
from typing import Any

FROZEN_AGG = 'de11a83db8d7c47ed328b15a7df71d613a833b16cd23ee9fe877999578a1ace0'
FROZEN_CONFIG = 'dcd10de54b23f8366428fb24e828812b1da9549e6eae4a3c3f38604fe5ae77b9'
OFFICIAL_FILES = (
    'contest_io.py', 'evaluation_validation.py',
    'multicore_cut_evaluate_problem_1.py', 'multicore_cut_evaluate_problem_2.py',
    'multicore_cut_evaluate_problem_3.py', 'schedule_step1.py',
    'schedule_step2.py', 'schedule_step3.py', 'singlecore_evaluate.py',
    'stub_multicore_cut_and_schedule.py',
)

def sha(path: Path) -> str:
    return hashlib.sha256(path.read_bytes()).hexdigest()

def check_identity(root: Path) -> dict[str, str]:
    directory = root / 'data/raw/a/official/code'
    text = ''.join(f'code/{name}\t{sha(directory/name)}\n' for name in sorted(OFFICIAL_FILES))
    aggregate = hashlib.sha256(text.encode()).hexdigest()
    config_hash = sha(root / 'data/raw/a/official/data/config.txt')
    if aggregate != FROZEN_AGG or config_hash != FROZEN_CONFIG:
        raise ValueError('Frozen code/config hash mismatch; bounds not evaluated under another identity.')
    return {'official_code_aggregate_sha256': aggregate, 'config_sha256': config_hash}

def compute_bounds(graph: dict[str, Any], plan: dict[str, Any], cfg: dict[str, Any], delay: int) -> dict[str, Any]:
    from multicore_cut_evaluate_problem_2 import _build_scene_b_tasks
    from schedule_step3 import _op_duration, _uses_ddr_bandwidth
    from evaluation_validation import validate_execution
    tasks, links, _, traffic, view = _build_scene_b_tasks(graph, plan, **cfg)
    validate_execution(tasks, links)
    weight: dict[tuple[int, int], int] = {}
    ddr: set[tuple[int, int]] = set()
    succ: dict[tuple[int, int], dict[tuple[int, int], int]] = defaultdict(dict)
    indegree: dict[tuple[int, int], int] = {}
    pipe_load: dict[tuple[int, str], int] = defaultdict(int)
    for core, task in tasks.items():
        for op_id, op in task['op_by_id'].items():
            node = (core, op_id)
            duration = _op_duration(op, task['in_tids'], task['out_tids'], task['tensor_by_id'], cfg['bandwidth'])
            weight[node] = duration
            indegree[node] = 0
            pipe_load[core, op['pipe']] += duration
            if _uses_ddr_bandwidth(op, task['in_tids'], task['out_tids'], task['tensor_by_id']):
                ddr.add(node)
    def add_edge(a: tuple[int, int], b: tuple[int, int], lag: int = 0) -> None:
        if b not in succ[a]:
            indegree[b] += 1
        succ[a][b] = max(lag, succ[a].get(b, 0))
    for core, task in tasks.items():
        for op_id, predecessors in task['op_preds'].items():
            for p in predecessors:
                add_edge((core, p), (core, op_id))
        for order in task['pipe_ops'].values():
            for a, b in zip(order, order[1:]):
                add_edge((core, a), (core, b))
    for link in links:
        add_edge((link['source_core'], link['source_copy_out_id']),
                 (link['target_core'], link['target_copy_in_id']), delay)
    k = view['num_cores']
    earliest = {v: 0 for v in weight}
    latest_bound = dict(earliest)
    ready = [v for v, degree in indegree.items() if degree == 0]
    heapq.heapify(ready)
    visited = 0
    while ready:
        u = heapq.heappop(ready)
        visited += 1
        low_end = earliest[u] + weight[u]
        high_end = latest_bound[u] + weight[u] * (2*k if u in ddr else 1)
        for v, lag in succ[u].items():
            earliest[v] = max(earliest[v], low_end + lag)
            latest_bound[v] = max(latest_bound[v], high_end + lag)
            indegree[v] -= 1
            if indegree[v] == 0:
                heapq.heappush(ready, v)
    if visited != len(weight):
        raise ValueError('Compiled global graph is cyclic.')
    W = sum(weight[v] for v in ddr)
    P = max(pipe_load.values(), default=0)
    C = max((earliest[v] + weight[v] for v in weight), default=0)
    U = max((latest_bound[v] + weight[v]*(2*k if v in ddr else 1) for v in weight), default=0)
    compute_load: dict[str, int] = defaultdict(int)
    for op in graph['ops']:
        if op['op'] not in ('COPY_IN', 'COPY_OUT'):
            compute_load[op['pipe']] += max(1, op['cycles'])
    universal = max(((v+k-1)//k for v in compute_load.values()), default=0)
    return {
        'scope': 'L and U are for this fixed compiled plan, not the optimum over repartition/reordering.',
        'num_cores': k,
        'universal_eligible_compute_load_LB': universal,
        'plan_specific_DDR_service_LB': W,
        'plan_specific_pipe_LB': P,
        'plan_specific_compiled_CP_LB': C,
        'plan_specific_L': max(W, P, C),
        'plan_specific_conservative_U': U,
        'upper_bound_copy_slowdown_factor': 2*k,
        'compiled_op_count': len(weight),
        'compiled_edge_count': sum(map(len, succ.values())),
        'ddr_copy_count': len(ddr),
        'data_movement_bytes': traffic,
        'global_E0_calls': 0,
    }

def main() -> None:
    ap = argparse.ArgumentParser(description=__doc__)
    ap.add_argument('--evidence-root', type=Path, required=True)
    ap.add_argument('--graph', type=Path, required=True)
    ap.add_argument('--plan', type=Path, required=True)
    ap.add_argument('--reference-plan', type=Path)
    ap.add_argument('--output', type=Path, required=True)
    a = ap.parse_args()
    root = a.evidence_root.resolve()
    identity = check_identity(root)
    sys.path.insert(0, str(root / 'data/raw/a/official/code'))
    from evaluation_validation import read_evaluation_config
    from multicore_cut_evaluate_problem_2 import read_scene_b_config
    config_path = root / 'data/raw/a/official/data/config.txt'
    cfg = read_evaluation_config(config_path)
    delay = read_scene_b_config(config_path)['cross_core_copy_delay_cycles']
    graph = json.loads(a.graph.read_bytes())
    plan = json.loads(a.plan.read_bytes())
    result: dict[str, Any] = {
        'identity': identity, 'graph_sha256': sha(a.graph),
        'candidate_plan_sha256': sha(a.plan),
        'candidate': compute_bounds(graph, plan, cfg, delay),
    }
    if a.reference_plan:
        reference = json.loads(a.reference_plan.read_bytes())
        result['reference_plan_sha256'] = sha(a.reference_plan)

            result['candidate']['plan_specific_conservative_U'] < result['reference']['plan_specific_L'])
        result['comparison_scope'] = 'Only these two fixed plans; not a universal algorithm or optimality claim.'
    a.output.parent.mkdir(parents=True, exist_ok=True)
    a.output.write_text(json.dumps(result, ensure_ascii=False, indent=2) + '\n', encoding='utf-8')
    print(json.dumps({'output': str(a.output), 'L': result['candidate']['plan_specific_L'],
                      'U': result['candidate']['plan_specific_conservative_U'],
                      'certified_strict_improvement': result.get('certified_strict_improvement')}, ensure_ascii=False))

if __name__ == '__main__':
```
