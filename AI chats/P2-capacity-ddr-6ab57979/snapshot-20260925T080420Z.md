# 三、问题一：固定分核和 eligible 顺序，切分/合并到底改变什么？

## 3.1 必须分开三层图

令：

\[
D_{\rm legal}
\rightarrow D_{\rm base}(\pi)
\rightarrow G(\text{plan}).
\]

其中：

- \(D_{\rm legal}\)：stub 为计划合法性构造的 eligible DAG，包含原 COPY 路径收缩。
- \(D_{\rm base}(\pi)\)：P2 根据核映射 \(\pi\) 实际重建的本地 tensor、基础 COPY 与计算图。
- \(G(\text{plan})\)：经过 Step2 spill、Step3 内存复用编译，再加入 pipe FIFO 和跨核 COPY 延迟的实际全局执行图。

**第一层中的收缩边，不自动成为第三层中的计时边。**

源码依据：`stub_multicore_cut_and_schedule.py` 70–89、157–231 行；P2 61–274 行；`evaluation_validation.py` 226–243 行。全文报告列出了逐项定位。

## 3.2 P2 每核一个 Task，不是每子图一个 Task

冻结 P2 将同核全部子图汇集成**一个 Task**，统一经过 Step1、Step2、Step3。

因此不存在以下 P1 式推论：

> 每增加一个子图边界，就重新加载该子图所有输入，或者清空该子图之前的片上驻留。

P2 子图边界主要影响**优先级归属**，不是独立缓存域，也不是显式执行 barrier。

## 3.3 命题：固定核映射，基础 COPY 多重集不变

对原 tensor \(t\)，定义 eligible producer、consumer 所在核集合为 \(P_t,Q_t\)，大小为 \(s_t\)。

冻结 P2 的规则是：

- 无 eligible producer：每个消费核一份基础 IN。
- 是最终输出：每个生产核一份最终 OUT。
- 每个不同的生产核、消费核对：一份 OUT 加一份 IN。
- 跨核 direct eligible 边：另建本地 UB tensor 和一对 COPY。
- 原 DDR tensor 的本地副本放到 UB。

特别注意：**一个源 tensor 发往两个目的核，源端有两次 OUT，不是共享一次 OUT。**

基础 COPY 字节数为

\[
B_0(\pi)
=
\sum_t s_t(i_t+f_t+2x_t)
+
2\sum_{e\text{ 为跨核 direct 边}}s_e,
\]

其中

\[
i_t=\mathbf1[P_t=\varnothing,Q_t\ne\varnothing]|Q_t|,
\]

\[
f_t=
\mathbf1[P_t\ne\varnothing,\ t\text{ 按P2规则需最终输出}]|P_t|,
\]

\[
x_t=|P_t||Q_t|-|P_t\cap Q_t|.
\]

**证明要点：**这些生成条件只依赖原图和核映射；子图边界只决定 COPY 挂在哪个优先级桶，不决定生成次数或大小。依据是 P2 150–238 行。

所以：

| 固定分核、固定每核 eligible 投影后 | 是否必然不变 |
|---|---|
| eligible 工作量、pipe、分核 | 不变 |
| 基础 COPY 数量、大小、跨核配对及 500-cycle lag | 不变 |
| COPY 所属优先级桶、完整 Step2 输入序 | **可能改变** |
| spill、backing、incarnation、spill 字节 | **可能改变** |
| MTE2/MTE3 FIFO、内存复用边 | **可能改变** |
| 实际开始/结束时刻、M | **可能改变** |
| 商图及最终全局图是否合法 | 必须重验 |

另一个细节：**零字节 COPY 仍有最少 1 cycle 服务时间，跨核仍有 500-cycle lag。**

## 3.4 为什么只保留 eligible 顺序不够？

P2 先计算每核原始 Step1 序 \(R_c\)，再按子图 rank 稳定排序。同一子图内部保留 \(R_c\) 相对顺序。

因此，合并可能让 COPY 跨过其他 eligible 操作，即便 eligible 投影完全没变。

一个足够强的不变性命题是：

> 固定物理图、核映射、确定性 tie-break，并且**包含全部基础 COPY 的完整 Step2 输入序相同**，则 Step2、Step3、全局时序相同；子图标签与时间线分组除外。

证明就是对三个确定性状态机逐事件归纳。**不能把这里的“完整序”弱化成“eligible 序”。**

## 3.5 三个直接反例，以及一个合法性反例

**合并可以增加 spill。**  
两个 eligible 同核：\(u\) 在 M 上 10 cycles，\(v\) 在 V 上 10 cycles，且 \(u\to v\)。\(u\) 产生 80,000 B 最终输出 \(z\)，\(v\) 消费另一个 80,000 B 输入 \(x\)。

```text
singleton：u, OUT(z), IN(x), v
合并后：   u, IN(x), v, OUT(z)
```

eligible 顺序都是 \(u,v\)，但后一序列要同时保留 \(x,z\)，超过 UB。冻结结果：

\[
M:2688\to5356,\qquad spill:0\to160000\text{ B}.
\]

**合并也确实能提速。**  
核0 上 \(u(M,1),v(V,1)\)，核1 上 \(w(M,10000)\)。\(u\) 产生 60,000 B 最终输出 \(z\)，\(v\) 产生给 \(w\) 的 60 B 跨核输入 \(y\)。

```text
singleton：u, OUT(z), v, OUT(y)
合并后：   u, v, OUT(y), OUT(z)
```

基础 COPY 字节与 spill 均不变，M 从 **11,503 降至 10,505**。收益来自关键小 OUT 绕过大最终 OUT 的 MTE3 队头阻塞。:chatgpt-content-reference{index="6"}[合并提速原件](sandbox:/mnt/data/p2_analysis/merge-help-probe.json)

**COPY 收缩不能直接给时间下界。**  
原图：

```text
u(10000) → UB → COPY_OUT → DDR → COPY_IN → UB → v(10000)
```

\(u,v\) 分在两核。合法性收缩得到 \(u\to v\)，但冻结 P2 重建的是两个独立出入 COPY，没有对应 cross link。实际 \(u\) 在 0–10000，\(v\) 在 1–10001，官方：

\[
M=10001<20000.
\]

这反驳“收缩计算路径串行和必为 P2 下界”，不是建议利用语义缺口；合法性合同仍要满足。

**同核连续也不保证能合并。**  
\(u\to w\to v\)，\(u,v\) 在核0，\(w\) 在核1。合并 \(u,v\) 为 A 后商图成为 \(A\to W\to A\)，被拒绝。

以上反例的图、计划和结果均已保存。:chatgpt-content-reference{index="7"}[语义反例原件](sandbox:/mnt/data/p2_analysis/semantic-probes.json)

## 3.6 Step3 还有一个容易漏掉的约束

本地 Step3 不仅固定每条 pipe 的 FIFO，还按 `seq_ext` 的 allocation 顺序申请输出空间，并将空间复用编译成 WAR/WAW 边。

**全局 P2 保留这些 memory edges，却不重跑本地 allocation-order 门。**

因此：

- 自写“全局即时申请释放内存、任意 ready 操作发射”的模拟器，不等价于官方。

- `memory_peak_by_core` 是本地 Step3 报告值，不能冒充从最终全局时间线重新计算的峰值。

# 四、问题二：主推“规范化 COPY 的生命周期前沿调度”

这是一条主路线，不另推多算法组合选优。**初版保持 singleton 输出**，先把容量与 COPY 队列做好；合并仅作为后续受限局部转移。

## 4.1 容量层：从真正的物理 token 开始

固定核映射后，按 P2 生成本地 token：

```text
(original_tid 或 direct_edge_id,
 core, pool, size,
 producer, consumers,
 import/export COPY obligations)
```

必须同时做到：

- 原 DDR 本地副本记 UB。
- 跨核 direct 边生成的 UB buffer 也计入容量。
- 一个源 tensor 发往多个核，源空间只计一次，COPY 工作按目的核分别计。
- 同核多个消费者不能重复计算基础 IN。

这一步使容量证书可以覆盖跨核分支，而不是直接把当前完整弱分量域内的 `footprint` 无条件套到 gap 上。

## 4.2 一个精确的 Step2 无 spill 判据

对完整基础 Step2 输入序，令本地 tensor \(t\) 的首次、末次触碰位置为 \(a_t,b_t\)。定义：

\[
H_{c,p}(i)=
\sum_{\substack{t\text{ 在核 }c\\pool(t)=p}}
s_t\,\mathbf1[a_t\le i\le b_t].
\]

**命题：冻结 Step2 返回零 spill，当且仅当所有 \(H_{c,p}(i)\le C_p\)。**

证明很直接：Step2 是先申请本步输入/输出、再检查、最后释放末次使用。没有此前 spill 时，第 \(i\) 步检查集合恰好是这些闭区间覆盖的 tensor。首次超容量时，要么发生 spill，要么因没有合法 victim 报错，不可能仍零 spill 返回。

对 singleton，可以把同桶触碰一起计入，构成更保守的 \(\bar H\)。在**唯一 producer、无未建模 alias、正确包含 P2 合成 token**的域内：

\[
\bar H\le C\Longrightarrow H\le C\Longrightarrow spill=0.
\]

这是充分证书，不是并行执行峰值公式，也不是 M 不退化定理。

## 4.3 用真实前沿替代永久共享输入预留 \(S\)

前缀 \(X\) 上维护：

\[
F(X)=\{t:\text{已经触碰，且仍有未来触碰}\}.
\]

下一桶 \(u\) 引入新 token 集 \(N(X,u)\)，本桶结束可以释放的集合为 \(Z(X,u)\)。转移为：

\[
peak_p(X,u)=
\sum_{t\in F(X)\cup N(X,u),\,pool(t)=p}s_t,
\]

先检查容量，再执行，最后

\[
F(X+u)=
(F(X)\cup N(X,u))\setminus Z(X,u).
\]

**共享输入不应从开头永久预留；但也不能在某个作业结束时释放，只要还有未来消费者。**

这里必须存 token 身份与未来引用数，仅存 L1、UB 两个字节总量不够。

### 可以严格突破 \(S\) 的结构

固定核映射、完整作业同核，若存在作业顺序，使每个共享输入的消费者作业连续出现，则串行作业 \(j\) 的共享驻留集合只是它实际使用的共享输入，而不是全核共享输入并集。

设该集合大小为 \(S_{j,p}\)，私有峰值为 \(P_{j,p}\)，则：

\[
\forall j,p,\quad S_{j,p}+P_{j,p}\le C_p
\]

足以保证无 spill，而且每个共享输入仍只做一次基础 IN。

例如，A 组共享 80,000 B 输入，B 组共享另一个 80,000 B 输入，各自私有峰值不超过 40,000 B。永久 \(S=160000\) 会拒绝；先 A 后 B 峰值不超过 120,000 B，实际可行。

但三角交叠不能这样消掉：

\[
J_1=\{a,b\},\quad J_2=\{b,c\},\quad J_3=\{a,c\},
\]

其中 \(a,b,c\) 各 65,536 B。任何顺序在第二个作业都需同时保留三输入，峰值 196,608 B。不能按签名分组后假释放。移一个作业到另一核可能消除该障碍，但输入副本从 3 份变 5 份，**基础 DDR 增加 131,072 B**。

## 4.4 有界前沿 DP：精确容量可行性，而非假装精确全局最优

区域内固定 \(w\) 条链或作业的内部词，长度为 \(n_1,\dots,n_w\)。状态：

\[
q=(q_1,\ldots,q_w)
\]

记录各词提交了多少操作，并携带边界 token 的未来引用状态。

转移只允许取某词的下一个操作，且满足：

\[
D_{\rm legal}\text{ 前驱已提交},\qquad peak_p(q,u)\le C_p.
\]

倒序计算 `CanFinish[q]` 并保存一条排空见证。这样排除的不只是“当前放不下”，还包括“走这一步后，该局部区域无法完整排空”。

穷尽时，它精确判定**给定内部词、给定边界、零 spill**条件下的可行交织。状态数上界：

\[
\prod_{j=1}^{w}(n_j+1),
\]

或对 \(r\) 个区域操作采用至多 \(2^r\) 个理想集状态。

必须诚实区分：

> \(n^w\) 不是关于 \(w\) 的 FPT；预算用完不是无解证明；区域可行不是整个 P2 最优。

建议初版固定小区域上限，例如 \(r\le12\)、单区最多 4096 状态，再限制全图总转移量。大的重复作业群用 profile 缓存和流式窄窗口，不一次塞入指数 DP。缓存依据结构、大小、pipe、输入等价关系，不依据图号或历史成绩。

separator 应建立在 **op–tensor 关联图/超图**上；只看 eligible 二元 DAG 的窄割，会漏掉跨很多作业共享的大输入。

## 4.5 DDR 层：真实服务规律，不是静态边延迟

每个 COPY 的独占服务量应为：

\[
d_v=\max(1,\lceil b_v/60\rceil),
\]

必须**逐 COPY 取整后相加**。

若当前有 \(m\) 个正剩余工作的 DDR COPY：

\[
\frac{dw_v}{dt}=-\frac1m.
\]

预测器必须处理分数 cycle 内的完成与带宽重新分配，以及：

\[
ready(IN_{a\to b,t})=
finish(OUT_{a\to b,t})+500.
\]

队列状态至少包括：各核各 pipe 的固定前缀与队头、待发与在飞操作、跨核 release、各 COPY 剩余独占工作，以及本地 Step3 的 allocation cursor、resident/refcount、credit FIFO 来源。

**不能只保留每条 pipe 的一个 tail。**

更重要的是区分两个接口：

- **`PredictWindow`**：对有限区域和固定补全见证运行队列预测。公平共享规律真实，但外部未来 arrival、最终 memory edges 未全部确定，因此返回的是预测分数，**不是 E0 M，也不是上下界**。
- **`CompileFinal`**：对唯一完整计划按冻结语义编译本地 Step3，再验证全局 DAG。此后在完整 \(G\) 上运行公平共享核，才可以要求逐操作时序与 E0 一致。

这避免了用“容量 DP 精确”偷换“整个队列预测也精确”。

## 4.6 可实施的整体构造

宏分配先保留轻弱分量作为完整分核单元；计算工作超过全图负载放松界的重分量，才开放内部链分核。完整单元至多检查 \(k\) 个核，尚未分配的最后父/join 小块至多检查 \(k^2\) 个核对。

每个候选同时更新真实 COPY obligations、生命周期 profile 和队列预测。完成后冻结核映射，再做前沿排序与最终精确证书。

```text
BUILD(graph, k, config):
    验证原图、配置，建立 D_legal
    保留现有 alias / 结构 guard
    超域则走现有确定性回退，明确不声称本证书

    用结构 profile 做有界宏分配
        比较真实 COPY 服务/字节增量、容量、出口完成预测
    冻结核映射
    按 P2 规范化全部本地 token 和 COPY
    计算固定物理图的 Step1 原始 rank

    while 尚有 eligible 操作:
        选择一个小的 ready 前沿区域
        计算容量 CanFinish 与排空见证
        排除容量失败或无排空见证的下一步
        对剩余下一步做有预算的 PredictWindow
        按固定规则选一个，提交桶，更新引用计数和队列状态
        不插入自定义 IDLE、SPILL 或额外控制边

    输出 singleton 映射和每核顺序
    生成真实完整 COPY 优先级序
    核验闭区间容量证书

    验证 data + memory + FIFO + cross 全局 DAG

```

没有合法下一步，只能说明当前路线或受限区域失败，不能宣布全图无解。回退按结构失败原因触发，不按 E0 成绩触发。

### 能保证和不能保证的事

**可以证明：**完整证书通过时无 Step2 spill；固定核映射时总 COPY 字节降到 \(B_0(\pi)\)，少掉的恰是旧 spill 字节。

**不能保证：**无 spill 总比少量 spill 快；输入分组不损失并行；改变分核后基础 DDR 不增加；主算法各图 M 都改善。

对 fork/join，一个严格排除条件是：

> 候选已经强制产生的真实服务/依赖下界，不小于某完整合法参考计划的已证上界，则候选不可能更好。

除此之外，“计算重叠收益大于新增 DDR 独占服务量”只是启发式，不是充分定理；最后父与 join 同核也不是普适最优规则。

### 求解耗时为什么有机会下降？

新增层使用稀疏引用计数、固定大小前沿、profile 复用和全图工作预算，不维护无界 AVL 历史插空搜索。DDR 同时活跃者最多 \(2k\)，事件处理本身很小。

但总耗时必须加上规范化、索引、Step1/2/3 编译、验证、回退和 I/O。**不能证明现有所有 Python 辅助过程都是线性的，也不能从源码外观把 014 的超时归因于 AVL。**

尤其是：先完整运行 gap 再修复，只能验证 M 的修复能力，不能据此宣称生产 solver 端到端更快。

## 5.1 旧 tensor 在这两图其实已经非常接近一个有效全局下界

对任意 \(k\) 核合法方案：

\[
L_{\rm comp}(k)
=
\max_p
\left\lceil
\frac{\sum_{v\in eligible,\ pipe(v)=p}\max(1,cycles_v)}k
\right\rceil.
\]

## 5.2 对固定完整编译图的有效上下界

在真实 \(G\) 上定义：

\[
W_D=\sum_{v\in DDR\ COPY}d_v,
\]

\[
L_{\rm pipe}=\max_{c,p}\sum_{v\in(c,p)}d_v,
\]

\[
L_{\rm CP}=\operatorname{longestPath}(G;d,\text{lag}),
\]

\[
L=\max(W_D,L_{\rm pipe},L_{\rm CP}).
\]

则：

\[
L\le M(\text{plan}).
\]

这里通常是**固定计划下界**，不能拿含该计划 spill、FIFO、memory edges 的 \(L\) 去证明所有方案的最优值。

还有一个可计算的保守上界。因为最多 \(2k\) 个 DDR COPY 同时在飞，每个 COPY 持续时间至多 \(2k\,d_v\)。令：

\[
\bar d_v=
\begin{cases}
2k\,d_v,&v\text{ 为DDR COPY},\\
d_v,&\text{其他},
\end{cases}
\]

\[
U=\operatorname{longestPath}(G;\bar d,\text{lag}).
\]

对冻结全局阶段：

\[
M(\text{plan})\le U.
\]

**证明要点：**每个 COPY 的服务率至少 \(1/(2k)\)；固定 pipe 相邻边已经加入 \(G\)，全局发行是这些真实约束下的 ASAP，没有额外子图 barrier。按拓扑序归纳开始和结束时刻即可。

| 图 | 保存 gap 的 \(L\) | 新 probe 的 \(U\) | 严格比较 |
|---|---:|---:|---|
| 008 | 179,508 | 86,430 | \(U_{\rm new}<L_{\rm gap}\) |
| 095 | 950,334 | 359,718 | \(U_{\rm new}<L_{\rm gap}\) |

所以新计划优于这两份保存 gap 计划，**有不依赖实测 M 比较的证书**。:chatgpt-content-reference{index="8"}[008 证书](sandbox:/mnt/data/p2_analysis/certificate-008.json) · :chatgpt-content-reference{index="9"}[095 证书](sandbox:/mnt/data/p2_analysis/certificate-095.json)

def compute_bounds(graph: dict[str, Any], plan: dict[str, Any], cfg: dict[str, Any], delay: int) -> dict[str, Any]:
    from multicore_cut_evaluate_problem_2 import _build_scene_b_tasks
    from schedule_step3 import _op_duration, _uses_ddr_bandwidth
    from evaluation_validation import validate_execution
    tasks, links, _, traffic, view = _build_scene_b_tasks(graph, plan, **cfg)
    validate_execution(tasks, links)
    weight: dict[tuple[int, int], int] = {}
    ddr: set[tuple[int, int]] = set()
    succ: dict[tuple[int, int], dict[tuple[int, int], int]] = defaultdict(dict)

    pipe_load: dict[tuple[int, str], int] = defaultdict(int)

            node = (core, op_id)

            if _uses_ddr_bandwidth(op, task['in_tids'], task['out_tids'], task['tensor_by_id']):
                ddr.add(node)
    def add_edge(a: tuple[int, int], b: tuple[int, int], lag: int = 0) -> None:
        if b not in succ[a]:
            indegree[b] += 1
        succ[a][b] = max(lag, succ[a].get(b, 0))
    for core, task in tasks.items():
        for op_id, predecessors in task['op_preds'].items():
            for p in predecessors:
                add_edge((core, p), (core, op_id))
        for order in task['pipe_ops'].values():

                add_edge((core, a), (core, b))

                 (link['target_core'], link['target_copy_in_id']), delay)

    visited = 0

        visited += 1

        'scope': 'L and U are for this fixed compiled plan, not the optimum over repartition/reordering.',
        'num_cores': k,
        'universal_eligible_compute_load_LB': universal,
        'plan_specific_DDR_service_LB': W,
        'plan_specific_pipe_LB': P,
        'plan_specific_compiled_CP_LB': C,
        'plan_specific_L': max(W, P, C),
        'plan_specific_conservative_U': U,
        'upper_bound_copy_slowdown_factor': 2*k,
        'compiled_op_count': len(weight),
        'compiled_edge_count': sum(map(len, succ.values())),
        'ddr_copy_count': len(ddr),
        'data_movement_bytes': traffic,
        'global_E0_calls': 0,

### 为什么能覆盖你列出的误差

把两次 DDR 集合变化之间称为一个区间。

**推进误差。**固定残余向量的精确公平共享推进 \(F_t\) 在 \(L_1\) 下不扩张，且改变时间 \(\Delta\) 只改变至多 \(|\Delta|\) 的总残余。`advance_ddr_work` 每个完整完成分支至少归零一项，所以一次调用至多 \(h+1\) 个小步。逐项计入阈值忽略、除法、残余减法、elapsed 减法及尾分支误判后，一次调用的 \(L_1\) 误差不超过 \(\beta\)；同区间 \(j\) 次调用误差不超过 \(j\beta\)。

**投影误差。**设区间起点存储残余为 \(r\)，无新加入者时的精确结束为 \(f_i\)，官方整数投影为 \(e_i\)。近并列合组、cursor 运算、阈值减法和 ceil 合起来满足：

\[
f_i-\beta\le e_i\le f_i+1+\beta.
\]

这里明确保留了一整个向上投影 cycle。

**次数与势能。**正常全局运行至多 \(R\) 次循环、\(R+Q\) 次推进、\(2Q\) 个非空重排区间。按区间的“存储残余总量”核算：

\[
\text{DDR 在飞占用时间}
\le W_A+2Q_A(1+\beta_A)+(R_A+Q_A)\beta_A.
\]

对下界，每批退休还须计入可能被 `pop` 丢弃的正残余，不能只统计已服务量：

\[
W_{\rm all}
\le M_B+Q_Bh\beta_B+2(R_B+Q_B)\beta_B.
\]

因此可取整数余量

\[
\boxed{\epsilon_A=
2Q_A+\left\lceil(R_A+3Q_A)\beta_A\right\rceil}
\]

\[
\boxed{\epsilon_B=
\left\lceil(2R_B+(h+2)Q_B)\beta_B\right\rceil}.
\]

没有 COPY 时相应误差为零。**这里的 \(2Q_A\) 来自已证明的重排区间次数，不是经验性“每 COPY 加一”。**

数值范围也闭合：存储残余不增加，最大为 \(d\)；每次时钟跳跃至多 \(J\)，故时刻至多 \(RJ\)，中间 cursor 也在所选 \(2^p\) 范围内。完整小步计数、水位表达和势能消项见 :chatgpt-content-reference{index="7"}[机器引理完整证明](sandbox:/mnt/data/p2_narrow/NUMERICAL-LEMMA-zh.md)。

**结论的准确形式是：在这些机器前提、守卫及两计划正常返回的前提下，**

\[
U_A+\epsilon_A<L_B-\epsilon_B
\quad\Longrightarrow\quad
M_A^{\rm E0}<M_B^{\rm E0}.
\]

旧 `p2_bounds.py` 的裸 `strict` 字段**不在本轮被追认**；旧文件未修改。

```python
"""Numerical comparison only; NOT a plan/capacity/execution validator.

Statistics must come from the frozen P2 physical-token rules:
  n, k: eligible op count and core count;
  q: number of BASIC DDR COPYs; W: their integer service sum;
  g: sum_t max(uses_of_local_token_t - 1, 0), an upper bound on spills;
  x: number of cross_links;
  d: maximum service of any basic/spill COPY (use 1 when absent);
  c: maximum individual eligible duration;
  C: tuple/list of eligible-duration sums per core;
  max_bytes: maximum relevant physical-token/COPY size.

Machine premise: each primitive uses binary64, with absolute rounding error
at most one ulp, no unmodelled arithmetic mode/implementation changes.
A's structural certificate and successful E0 returns are separate obligations.
"""
from fractions import Fraction
import sys


def ceilq(x):
    return -(-x.numerator // x.denominator)


def margins(s, *, zero_spill):
    for name in ('n', 'k', 'q', 'g', 'x', 'd', 'c', 'W', 'max_bytes'):
        if type(s[name]) is not int or s[name] < 0:
            raise ValueError('invalid integer statistic: ' + name)
    k, n, q0 = s['k'], s['n'], s['q']
    if not 1 <= k <= 5 or s['d'] < 1 or s['max_bytes'] > 2**31:
        raise ValueError('outside k/size/duration guard')
    if len(s['C']) != k or any(type(v) is not int or v < 0 for v in s['C']):
        raise ValueError('invalid eligible core loads')
    if (sum(s['C']) < n or not q0 <= s['W'] <= q0*s['d']
            or q0 < 2*s['x'] or (n and s['c'] < 1)
            or s['d'] < max(1, (s['max_bytes']+59)//60)):
        raise ValueError('inconsistent counts/work')
    if zero_spill and s['x']:
        raise ValueError('A requires no cross_links')
    q = q0 if zero_spill else q0 + 2*s['g']
    r = n + q + s['x'] + 1
    if r > 1_000_000:
        raise ValueError('outside global-event guard')
    if zero_spill and n + q + 1 > 100_000:
        raise ValueError('outside conservative local-iteration guard')
    if q == 0:
        return (0 if zero_spill else None), 0
    h = 2*k
    jump = max(s['c'], h*s['d'], 500 if s['x'] else 0) + 2
    horizon = (r + h + 2)*jump
    p = max(1, (horizon - 1).bit_length() + 1)
    if p > 36:
        raise ValueError('outside floating-point magnitude guard')
    beta = 32*(h + 1)**2*(Fraction(1, 2**(52-p)) + Fraction(1, 2**29))
    upper_error = 2*q + ceilq((r + 3*q)*beta) if zero_spill else None
    lower_error = ceilq((2*r + (h + 2)*q)*beta)
    return upper_error, lower_error


def gate(a, b, *, a_structure_certified, ieee_ops_attested):
    """Return a CONDITIONAL comparison; do not infer execution success."""
    f = sys.float_info
    if not ieee_ops_attested or (f.radix, f.mant_dig, f.max_exp) != (2, 53, 1024):
        raise ValueError('binary64 machine premise not established')
    if not a_structure_certified:
        raise ValueError('A structural/capacity certificate is missing')
    if a['n'] != b['n'] or a['k'] != b['k'] or sum(a['C']) != sum(b['C']):
        raise ValueError('A/B do not describe the same eligible workload')
    ea, _ = margins(a, zero_spill=True)
    _, eb = margins(b, zero_spill=False)
    u, lower = max(a['C'], default=0) + a['W'], b['W']
    return {'conditional_prefer_A': u + ea < lower - eb,
            'U_A': u, 'L_B': lower, 'epsilon_A': ea, 'epsilon_B': eb,
            'requires_successful_E0_returns': True}
```

# A．现有定理链与一个更强的全局界

## A1．先固定“上界”的对象

对固定图、配置及核数 \(k\)，令 \(\mathcal P(G,k)\) 为能成功返回有限官方 Makespan 的合法计划集合：

\[
M^*=\min_{\Pi\in\mathcal P(G,k)}M_{\rm E0}(\Pi),
\qquad U=M_{\rm E0}(\Pi_{\rm inc}).
\]

若 \(L\) 对所有这些计划均有效，则

\[
\boxed{L\le M^*\le U},
\qquad
\boxed{\frac A U\le\frac A{M^*}\le\frac A L}.
\]

这里 \(A/L\) 才是所求的**最大加速比上界**。固定计划执行时间上界、固定 owner/FIFO 子问题的最优值、求解墙钟，都是其他对象。A 是固定官方单核基线，不是优化后的 P2 单核最优值，因此不能直接假设 \(A/M^*\le k\。[现有定义与证明](https://github.com/huaweibei123/huaweicup2026/blob/c66559a6f8a31ef7b4720e1f7c3c28d61f8dff3f/docs/a/q2-nikolastarx/OPTIMALITY_BOUNDS.md)

## A2．现有四类计算界：成立，但须保留证明域

令 eligible 操作集合为 \(V\)，\(d(v)=\max(1,\mathrm{cycles}(v))\)，\(p(v)\) 为原 pipe。原 COPY 不计入这些工作；非 COPY 的 MTE2/MTE3 操作仍应计入。

**负载界。** 每条 pipe 有 \(k\) 个单槽，因此

\[
L_{\rm load}
=\max_p\left\lceil\frac{\sum_{v:p(v)=p}d(v)}k\right\rceil
\le M^*.
\]

**不可分割界。** 将某 pipe 时长降序排列为 \(d_1\ge\cdots\ge d_n\)。令 \(m=(q-1)k+1\le n\)，则

\[
M^*\ge\sum_{j=m-q+1}^{m}d_j.
\]

证明：前 \(m\) 个操作中必有一个核心拥有至少 \(q\) 个，其总时长不小于这 \(m\) 个中最小的 \(q\) 项之和。这里不可分割的是**单个操作**，不是整弱分量。不同 pipe、不同 \(q\) 的界取最大，不相加。[实现](https://github.com/huaweibei123/huaweicup2026/blob/c66559a6f8a31ef7b4720e1f7c3c28d61f8dff3f/src/q2_nikolastarx/global_bounds.py)

**保留计算路径。** 当前充分证明域是：**每个原 tensor 至多一个 eligible producer**。可保留原 eligible→eligible direct 边，以及同一原 tensor 的 eligible producer→consumer 边；不能把经过被删除原 COPY 的收缩边自动作为计时边。

同核 spill 经首次 backing 写回及后续 reload 保留 producer 因果；跨核 reload 即使重用 backing，仍不能越过初始跨核 IN 的固定 MTE2 FIFO。因此相应计算先后关系保留。多生产者域应停用这部分证明，而不是宣称所有此类图非法。[P2 重建](https://github.com/huaweibei123/huaweicup2026/blob/c66559a6f8a31ef7b4720e1f7c3c28d61f8dff3f/data/raw/a/official/code/multicore_cut_evaluate_problem_2.py) · [Step2](https://github.com/huaweibei123/huaweicup2026/blob/c66559a6f8a31ef7b4720e1f7c3c28d61f8dff3f/data/raw/a/official/code/schedule_step2.py)

**head/tail 窗口。** 在保留 DAG 上，令 \(h(v)\)、\(t(v)\) 分别为严格前驱、严格后继的最长计算路径。对同一 pipe 的任意非空集合 \(S\)：

\[
s(v)\ge h(v),\qquad e(v)\le M-t(v),
\]

\[
\boxed{
M^*\ge
\min_{v\in S}h(v)
+\left\lceil\frac{\sum_{v\in S}d(v)}k\right\rceil
+\min_{v\in S}t(v)}.
\]

证明是将 \(S\) 的占用区间全部装入共同窗口，再对 \(k\) 个槽积分。现有代码扫描 head 阈值子集、tail 阈值子集，不是所有子集。**最大值合成不重计；任意相加才可能重计。**

这些计算界可覆盖冻结实现：普通操作的结束是整数 `now + duration`；DDR 舍入改变调度时刻，但不消除这些整数计算时长及保留先后关系。[Step3 时长与 FIFO](https://github.com/huaweibei123/huaweicup2026/blob/c66559a6f8a31ef7b4720e1f7c3c28d61f8dff3f/data/raw/a/official/code/schedule_step3.py)

**必要反例。** 原图仅有 \(A(M,10)\to\text{原 COPY\_OUT}\to B(V,10)\)，无 tensor。验证收缩图有 \(A\to B\)，但 P2 丢掉含原 COPY 端点的两条 direct 边；剩下两个不同 pipe 操作可同时执行。20-cycle 收缩路径不能作时间下界。这里是源码推导，不是本轮 E0 实验。

## A3．主推：必需 I/O 整数事件窗口界

我选择了一个**较弱但机器层可证明**的方向，而没有继续补签前轮未验收的 DDR 误差引理。

### 引理：成功返回的每个 COPY 至少占一个整数周期

冻结 P2 的事件循环具有以下性质：

1. `now`、普通操作结束、COPY 投影结束和外部释放时刻都是整数。
2. 上一轮选择下一事件时检查 `next_now > now`，所以进入当前 `retire(t)` 时，所有已登记结束时刻均不小于 \(t\)。
3. `advance_ddr_work` 不改变已登记结束；遍历退休操作时，`end<=t` 因而实际是 `end=t`。统一 COPY 重排发生在遍历之后。
4. 发射发生在退休之后。新 COPY 不可能同轮退休；成功返回时只能在更大的整数时刻退休。不能前进的舍入结果会报错，不会成为有限可行见证。
5. 已退休 COPY 从残余字典移除，其结束不再被后续重排修改。

因此，对成功官方执行，

\[
\boxed{e_{\rm copy}-s_{\rm copy}\ge1}.
\]

这不需要估计 float 累计误差，**也不声称 COPY 区间至少等于 \(\lceil bytes/60\rceil\)**。[冻结全局循环，尤其 329–371、425–509 行](https://github.com/huaweibei123/huaweicup2026/blob/c66559a6f8a31ef7b4720e1f7c3c28d61f8dff3f/data/raw/a/official/code/multicore_cut_evaluate_problem_2.py)

### 增强图与全局投影定理

在前述保留计算 DAG 上构造 \(H_{\rm evt}\)：

对每个必需输入 tensor \(t\)，加一个 **MTE2、权重 1** 的虚拟 \(I_t\)，连向全部 eligible consumers。对每个必需最终输出 \(t\)，加一个 **MTE3、权重 1** 的虚拟 \(O_t\)，从其唯一 eligible producer 连入。计算节点保持原整数时长。

**定理：**在唯一 eligible producer 的证明域内，每个成功官方计划都能投影为 \(H_{\rm evt}\) 上不超过原 Makespan 的 \(k\) 核 per-pipe 排布。

**证明。**共享输入可能在多个消费核各有基础 IN。选其中**最早完成的一份**：它不晚于每个消费者所在核的初始 IN，也就不晚于所有消费者开始；后续 reload 的 FIFO 桥接仍适用。把虚拟 \(I_t\) 放进该真实 IN 的最后一个周期。不同输入对应不同基础 COPY，不重复占用同一实体。

最终输出只有一个 eligible producer 源核；实际基础 OUT 在 producer 之后。把虚拟 \(O_t\) 放进它的第一个周期。保留全部计算区间。虚拟区间都是不同真实 COPY 区间的子集，不增加 pipe 并发，所有增强边满足先后关系，故完成不晚于原 M。证毕。

这里的共享虚拟输入是**免费广播放松**，不是错误地宣称官方只读一次。构造没有固定 owner、FIFO、整分量分核或某个计划的 spill 边。

### 可计算公式、复杂度及证书

在增强图上计算 \(h,t\)，取

\[
S_{p,a,b}=\{v:p(v)=p,\ h(v)\ge a,\ t(v)\ge b\}.
\]

非空集合给出

\[
L_{p,a,b}
=a+\left\lceil\frac{\sum_{v\in S_{p,a,b}}d(v)}k\right\rceil+b.
\]

最终采用

\[
\boxed{
L_{\rm evt}=\max\left\{
L_{\rm old},\
CP(H_{\rm evt}),\
H_{\rm evt}\text{ 的负载/不可分割界},\
L_{p,a,b}
\right\}.}
\]

它弱支配旧界，并可严格加强：一个 10-cycle 计算带必需 0B 输入和最终 0B 输出时，旧界 10，新 CP 为 12。**这是结构例证，不是 500 格新结果。**

选 \(r\) 个 head 阈值、对每个扫描全部 tail 阈值，核心算术成本可做到

\[
O(N\log N+E_H+rN).
\]

全部 head 阈值最坏二次；固定小 \(r\) 只影响强度，不影响有效性。输入验证、边排序与完整证书输出另计。

证书必须包含图/config/源码哈希、边界 tensor 身份、保留边出处、\(h/t\) 标签或路径见证、窗口节点 ID、工作和与取整结果。不能仅保存一个 `certified=true`。

**已交付静态原型，但未全图验证。**现有保存证书没有完整 tensor 关联信息，无法重建全部增强图。仅由已存数量可算的弱推论

\[
\max\left\{
\left\lceil\frac{W_{\rm MTE2}+n_{\rm in}}k\right\rceil,\
\left\lceil\frac{W_{\rm MTE3}+n_{\rm out}}k\right\rceil
\right\}
\]

与旧界取最大后，**500 格加强数为 0**。所以本轮没有新的、更低的均值加速比上限。

### 加权 DDR 版本：明确只属理想模型

把虚拟 COPY 权重换成

\[
w_t=\max(1,\lceil size(t)/60\rceil).
\]

在精确实数、单位总服务率模型中，对一组必需 COPY \(J\)，由加权增强图的共同 head/tail 可得

\[
\boxed{
M_{\rm ideal}\ge
\min_{j\in J}h(j)+\sum_{j\in J}w_j+\min_{j\in J}t(j)}.
\]

证明：这些 COPY 的实际服务全部位于共同窗口，服务器总速率不超过 1。它耦合的是**同一组必需服务的前后计算条件**，不是独立 compute 下界加全部 DDR。

**此式本轮不进入冻结机器的严格 L。**近并列退休、残余量截断及整数投影仍需服务误差证明。前轮机器引理未验收，本轮不补签。

## C3．可进入论文的单调性定理

**定理。**同一图/config/\(k\) 下，保留上一轮完整合法 incumbent。仅在新候选成功精确评分且 \(U_{t+1}\le U_t\) 时接受；构造或评分失败则保留原对象。对同一有效正全局界 \(L\)：

\[
U_{t+1}-L\le U_t-L,
\]

\[
U_{t+1}/L-1\le U_t/L-1,
\]

\[
A/L-A/U_{t+1}\le A/L-A/U_t.
\]

若有效下界亦单调收紧，\(L_{t+1}\ge L_t\)，则

\[
\boxed{[L_{t+1},U_{t+1}]\subseteq[L_t,U_t]},
\]

且

\[
\boxed{
(U_t-L_t)-(U_{t+1}-L_{t+1})
=(U_t-U_{t+1})+(L_{t+1}-L_t)\ge0.}
\]

证明由接受规则及界的有效性直接得到。最后一个等式还能区分：**方案变快**与**证明变强**。只增加 L、U 不变时，成绩没有提高。

但算法永远返回 incumbent 也满足该定理，所以它**不保证严格进步、全局收敛或收敛速率**。按 \((M,DDR)\) 字典序接受时，只有 M 相同才要求 DDR 不增；M 下降时 DDR 可以增加。

### 当前实现与定理假设之间的缺口

现有顶层源码至多比较 baseline、gap、hypergap 三个不同完整计划；异常或评分失败会返回 baseline。只有当这个 baseline 就是要保护的 incumbent 时，失败分支才满足上述定理。真正改成迭代时，应保存旧 incumbent 对象和原评分，失败直接返回它，而不是重建另一个默认 baseline。[顶层选择源码](https://github.com/huaweibei123/huaweicup2026/blob/c66559a6f8a31ef7b4720e1f7c3c28d61f8dff3f/src/q2_nikolastarx/adaptive_hypergap_guarded.py)

本包没有 `_score` 与原生 E2 的完整实现，因此不能将现有验证范围写成“E2 对所有合法计划普遍等价 E0”。选中 500 份结果有独立 E0 记录，也不等于所有比较候选都已经得到普遍等价证明。

同样，“最多三个候选”本身不证明整个程序非暴力或便宜：还要计入候选内部搜索、准备、验证、失败回退和 I/O。保存的求解进程均值 4.029s、P95 18.841s、最大 40.187s 是原测主机条件下的记录，不是本轮计时或跨机器提速保证。[完整运行记录](https://github.com/huaweibei123/huaweicup2026/blob/1c00079aadbd071de62db17686d5ba3fed1da0f2/results/a/q2-nikolastarx/hypergap-full500-audit-20260925/RESULTS.md)

# D．证书轨迹、停止标准与交付

## 应实际记录的轨迹

最小记录结构是：

```text
instance: graph/config/k/official-source hashes
incumbent_before: complete plan hash, raw result hash, U, partition/spill DDR
action: constructor version, structural domain, neighborhood, proxy before/after
candidate: complete plan hash, scorer identity, success, exact objective, receipt
acceptance: accepted/rejected, reason, incumbent_after hash
bound: scope=global, proof kind, certificate hash, witness, L_before/L_after
cost: cold wall, construction, preparation, scoring, fallback, I/O, attempted calls
```

未知原件字段留空，不从摘要补成“已读 raw 回执”。轨迹分别展示 \(U_t\)、\(L_t\)、DDR 与墙钟；不能仅画字节或固定界残差并标成“向时间最优收敛”。

**停止标准有三种不同含义：**

- \(L=U\)，或整数 M 下严格有效实数界 \(L>U-1\)：全局最优停止。
- \(U\le(1+\delta)L\)：相对精度证书停止；均值也可用 \(\operatorname{mean}(A/L-A/U)\le\eta\)。
- 用尽预算或没有找到改进：只能报告未搜索区域，不能称局部最优。局部最优需要完整覆盖声明的邻域；guard 不支持不等于官方非法。

若发生 \(L>U\)，先停止并审计身份、证明和记录，不将矛盾解释为性能突破。

## 本轮最小证伪检查

新原型只运行了四个极小**静态**例子：COPY 收缩边排除；0B 边界的 10→12 下界加强；共享输入只设一个虚拟入口；eligible MTE2 与边界 COPY 共同计入槽负载。另检查多 eligible producer 时明确拒绝证明域。它们检验实现一致性，**不代替投影定理，也不是 E0 实验**。

R05 保存 pair 已足以证伪字节代理的一般单调性。后续原图补齐后，新界应首先针对同身份保存结果核查 \(L_{\rm evt}\le U\)；一例违反就停止推广并定位证明域或实现错误，而不是追加调参掩盖反例。
