# 第33页图5.4-1的候选图注

图 X　两个计算核心之间的局部最小割及计算工作量检查。图中 \(a\)、\(b\) 是允许重新分配计算链的两个核心；\(F_e\) 是超边 \(e\) 在本次调整区域外已经触及的核心集合。它与正文表示辅助网络最大流值的标量 \(f_{\max}\) 不同。例 A 取 \(F_e=\varnothing\)，例 B 取 \(F_e=\{a,c\}\)，其中 \(c\) 是区域外的另一个核心；两个例子均使用权重为 \(w\) 字节的符号超边，不是赛题实测数据。图中给定核心分配对应的割容量加固定偏移，等于这条超边的原始数据复制（COPY）字节数。例 A 的偏移为 \(-w\)，例 B 的偏移为 \(+w\)。这些给定分配的割容量不能称作未加锚定约束的自由网络最大流值；后者等于该网络的最小割值。

求得局部最小割后，算法分别检查两个核心在每类计算流水线（Pipe）上的工作量。这里的工作量是分配给该核心、该类流水线的各计算操作时长之和，单位为模拟时钟周期（cycle），并非完整方案的总完成时间。若某项超过调整前确定的上限，算法把一条新移入的计算链固定回原核心，再求一次最小割。每次超限至少固定一条此前可移动的计算链，因此若有 r 条可移动链，最多求解 r+1 次。只有计算工作量符合上限且本区域的原始 COPY 字节数严格减少，才保留新的核心分配。**这一步只减少编译前复制量 \(D_{\mathrm{pre2}}\) 中的局部贡献，并限制所述计算工作量；它不证明完整调度方案的总完成时间（Makespan）缩短，也不保证不会发生片上存储溢出。**最后是否采用完整方案仍取决于后续完整构造与评价。
