# 问题一：面向 Task 门控与共享 DDR 的多核计算图划分和调度

> **初稿版本：2026-09-25，真实 MEM 接口验证与 DDR 权衡更新。** 本章按用户提供《论文结构参考》的“问题分析—模型建立—评价指标—模型求解—结果分析”组织。完整实验采用统一构造算法 v4；后续结构试验、真实模型核验与尚未验证的研究分别说明范围。详细图先文字占位，最终数据冻结后统一制图。来源、复算入口和修订条件见 [证据与更新清单](../notes/P1-证据与更新清单.md)。章节号暂用“4”，整稿时统一调整。

## 4.1 问题描述与分析

问题一研究情况 A 下的多核并行执行。给定原始计算图和核数，需要同时确定计算操作到子图的划分、子图到核心的分配，以及各核心上子图的执行顺序。每个子图被封装为一个 Task。官方评估器根据方案重新生成 Task 边界的数据搬运，完成核内指令排序、内存换入换出与内存依赖处理，最后模拟多核执行，以全部任务完成所需的时钟周期数 Makespan 衡量方案质量。

该问题的难点在于，图上的计算并行性不等于实际执行的并行性。一方面，将较大的子图拆开能够释放并行工作，但跨 Task 的张量需要经过 DDR 搬运，后继 Task 还必须等待整个前驱 Task 完成。另一方面，将多个计算分支合并可以减少边界搬运和 Task 切换，却可能延后本可提前执行的操作，增大片上存储压力。各核虽然拥有独立的计算流水线，却共享 DDR 总带宽；同时启动更多核也可能增加输入竞争。因此，仅按节点数量均分、仅平衡计算量或仅最小化割边字节，都不能完整描述目标。

本章采用“图结构分析—有限结构构造—在线评价选择”的方法。首先识别独立分量、重分量、分叉归约、共享输入和同型计算链等结构；随后分别构造少量具有明确适用条件的方案；用固定 E1 在线比较候选并按规则回退，实验阶段再由未修改 E0 独立复评。在此基础上，针对同型链和重复分叉归约进一步研究变宽分组与输入错峰，并用理论下界和正负实验解释收益来源。

本章区分两个优化维度：**方案质量**由模拟周期和额外 DDR 字节衡量，**求解程序效率**由生成方案的端到端墙钟时间衡量。较小的 Makespan 不代表 Python 程序运行更快，较快的评价器也不自动产生更优方案。

## 4.2 模型建立

### 4.2.1 输入、符号与固定硬件条件

设原始图包含操作、张量以及它们之间的有向依赖，全部可分配操作构成集合

$$
V=\{v:\operatorname{op}(v)\notin\{\mathrm{COPY\_IN},\mathrm{COPY\_OUT}\}\}.
$$

原始 COPY 节点不直接参与方案映射。构造 Task 间依赖时遵循官方对 COPY 路径的处理；进入每个 Task 的实际局部图则按其计算成员重新生成边界 COPY。这两层图不能混为一谈，尤其不能把已删除的原 COPY 桥直接当作局部计算关键路径。

| 符号 | 含义 | 单位或范围 |
| --- | --- | --- |
| $K$ | 给定核心数 | 1～5 |
| $V,\mathcal T$ | 可分配计算操作集合、Task 集合 | 离散集合 |
| $p(v),d_v$ | 操作所属 Pipe、普通操作有效时长 | $d_v=\max(1,\mathrm{cycles}(v))$，cycle |
| $b_t,\ell(t)$ | 张量大小、存储位置 | byte；L1/UB/DDR |
| $\phi(v)$ | 操作 $v$ 所属 Task | $\mathcal T$ |
| $\kappa(\tau),\sigma_k$ | Task 所属核心、核心 $k$ 上的 Task 序列 | 核编号、序列 |
| $S_\tau,C_\tau$ | Task 激活与完成时刻 | cycle |
| $M(P),D_{\mathrm{extra}}(P)$ | 方案 $P$ 的 Makespan、额外 DDR 搬运量 | cycle、byte |
| $T_{\mathrm{solve}},T_{\mathrm{E0}}$ | 完整求解耗时、独立官方复评耗时 | s |

冻结配置规定每核 L1 容量为 524,288 B，UB 容量为 131,072 B，DDR 总带宽为 **60 B/cycle**；同核相邻 Task 的等待为 100 cycle，跨核依赖 Task 的等待为 1,000 cycle。每核具有 MTE2、MTE3、M、V 四条 Pipe，每条 Pipe 同一时刻最多执行一个指令。Pipe 类型由节点自带字段确定，不根据算子名称推测。[^official]

### 4.2.2 决策变量与结构约束

用 $P=(\phi,\kappa,\sigma)$ 表示一个方案。令 $V_\tau=\{v:\phi(v)=\tau\}$，则必须满足完整且不重复的划分：

$$
\bigcup_{\tau\in\mathcal T}V_\tau=V,\qquad
V_\tau\cap V_\nu=\varnothing\ (\tau\ne\nu),\qquad
V_\tau\ne\varnothing.
\tag{4-1}
$$

每个 Task 只分配给一个核心，并且在该核心序列中恰好出现一次：

$$
\kappa:\mathcal T\rightarrow\{1,\ldots,K\},\qquad
\sum_{k=1}^{K}\operatorname{count}(\tau,\sigma_k)=1.
\tag{4-2}
$$

允许某些核心没有 Task，不强制占满全部核心。将跨 Task 数据依赖记为 $E_D$，将各核序列的相邻关系记为 $E_\sigma$，形成联合图

$$
G_P=(\mathcal T,E_D\cup E_\sigma).
\tag{4-3}
$$

联合图必须无环。单独检查数据依赖图无环不够，因为新增的核内次序也可能与数据依赖组成环。该条件保证结构一致性，完整可执行性仍需通过官方的局部编译、容量处理和事件模拟。

对应的提交文件严格只含 `node_to_subgraph` 和 `core_schedules`。候选得分、时间、诊断信息另存，不向提交方案增加自定义的操作级优先序或流水线控制字段。

### 4.2.3 Task 完成门控与资源约束

设 $\operatorname{prev}_k(\tau)$ 是核心 $k$ 上紧邻 $\tau$ 的前一个 Task。若前项存在，官方同核等待要求

$$
S_\tau\ge C_{\operatorname{prev}_k(\tau)}+100.
\tag{4-4}
$$

对数据前驱 $\nu\in\operatorname{Pred}(\tau)$，必须先完成前驱；若两者跨核，还要等待额外的门控周期：

$$
S_\tau\ge C_\nu+1000\,\mathbf 1[\kappa(\nu)\ne\kappa(\tau)].
\tag{4-5}
$$

无前驱且为本核首项的 Task 不凭空增加初始 100 cycle。式（4-4）与（4-5）以最大值共同约束激活时刻，不能把所有前驱等待机械相加。即使某个中间张量已经产生，后继也不能绕过 Task 整体完成门控提前激活。

Task 内部由官方三步编译过程处理：Step1 产生初始操作序列，Step2 根据容量和生命周期插入 spill，Step3 形成逐 Pipe 顺序与内存复用依赖。由此得到的扩展图与 Pipe 队首约束共同决定哪些操作能够发射。原 DDR 张量的 Task 内副本按官方规则进入 UB。

对于一次搬运 $o$，其独占 DDR 的服务工作量为

$$
w_o=\max\!\left(1,\left\lceil\frac{b_o}{60}\right\rceil\right).
\tag{4-6}
$$

官方事件模拟以这一服务量为基础，使所有活跃 DDR 请求共享总服务能力。故搬运持续时间还受同期其他请求影响；MTE2 与 MTE3 的读写竞争也包含在内。式（4-6）描述独占服务量，并非并发环境下的实际完成时间。

本章不把“一个 Task 触及的全部张量大小之和”写成官方容量可行性的充要条件。完整张量并集不超过对应容量，是部分构造采用的保守充分守卫；超出并集上界的 Task 仍可能通过生命周期复用或 spill 执行。进一步地，编译过程中的内存额度约束与任意重放下的动态峰值并不是未经证明就可互换的量。模型以冻结官方容量与执行规则定义最终可行域。

### 4.2.4 优化目标

令 $\mathcal F(G,K,\Theta)$ 表示给定图、核数与冻结配置下，满足格式、覆盖、依赖和官方执行规则的方案集合。问题一首先求解

$$
\min_{P\in\mathcal F(G,K,\Theta)}M(P),\qquad
M(P)=\max_{\tau\in\mathcal T}C_\tau.
\tag{4-7}
$$

额外 DDR 搬运量按官方计数定义为

$$
D_{\mathrm{extra}}(P)
=D_{\mathrm{scheduled}}(P)-D_{\mathrm{original}}(G).
\tag{4-8}
$$

其中，实际执行搬运量包含 Task 边界 COPY 与 spill COPY。不能直接将原图所有割边字节累加来代替式（4-8），因为同一张量的边界实例数量取决于生产者、消费者和 Task 划分。

候选选优采用 $(M,D_{\mathrm{scheduled}})$ 的字典序：优先减小 Makespan，在 Makespan 相同时优先减少搬运。对同一输入图，原图搬运量固定，因此该次目标与额外搬运量排序一致。这是本文的选优规则，不是题目提供的加权总分。求解耗时另行比较，不通过任意权重与模拟周期相加。

## 4.3 模型评价指标

### 4.3.1 官方加速比与统计口径

设官方固定单核启发式基线在用例 $i$ 上的 Makespan 为 $B_i$，本文方案在 $K$ 核上的结果为 $M_{i,K}$。逐用例加速比与 100 个给定用例的平均加速比分别为

$$
A_{i,K}=\frac{B_i}{M_{i,K}},\qquad
\overline A_K=\frac1{100}\sum_{i=1}^{100}A_{i,K}.
\tag{4-9}
$$

采用逐例比值的算术平均，不能改用总基线时间除以总多核时间。官方曲线的单核基点为 1；若另运行本文求解器生成单核方案，其结果属于单核再优化实验，不能悄然替换式（4-9）的固定分母。由于该分母是固定启发式基线而非单核最优值，个别用例出现高于核数的加速比，并不自动构成计算错误。

除平均值外，报告中位数、最小值和最大值，保留逐例退化与失败记录。对于未完成的实验批次，仅报告其实际覆盖范围，不用成功子集的均值代替全部给定用例的均值。

### 4.3.2 数据搬运与求解效率

数据搬运报告总实际搬运、额外搬运与 spill 搬运，并在具有相同输入身份的方案间比较。某一方案 Makespan 更短而额外 DDR 更多时，明确说明取舍，不能称作全指标改进。

求解耗时从求解程序启动到方案落盘及必要收尾结束，包含输入读取、结构分析、候选生成、在线评价、回退、子进程通信与结果写出。求解完成后的独立官方复评时间另列；若评价发生在在线选优阶段，则必须计入求解时间。用中位数、95% 分位与最大值刻画典型和尾部耗时，并记录硬件、并发、缓存与重复次数。

题面建议单例在 5～10 分钟内给出结果，并要求避免暴力迭代搜索。这是求解效率的设计要求和时间建议，不是“超过 600 秒必定无效”的规则，也不要求算法至少运行 5 分钟。本文比较质量与时间的 Pareto 关系：若一种方法既不增加求解耗时，也不增加官方 Makespan，并在其中至少一项严格改善，则在这两个维度上支配另一种方法。没有同条件的完整计时证据时，不声称程序速度优势。[^objectives]

## 4.4 模型求解

### 4.4.1 结构特征与基本构造

首先根据官方依赖关系形成计算 DAG，提取弱连通分量、各 Pipe 工作量、分叉位置、后缀可分性、外部输入集合与张量大小。对操作集合 $U\subseteq V$，定义 Pipe 工作向量

$$
W_p(U)=\sum_{v\in U:\,p(v)=p}d_v,
\qquad W_{\max}(U)=\max_p W_p(U).
\tag{4-10}
$$

这一向量比节点数更能表达异构 Pipe 的负载差异。例如，两组节点数量相同的计算可能分别集中在 M 和 V Pipe，其并行与重叠关系不同。式（4-10）只用于结构构造和排序，未包含全部 DDR、FIFO 和内存代价。

基本构造尽量保留完整独立分量。按最大 Pipe 工作量等稳定规则排序后，将分量装入当前负载合适的核心，比较放置后的最大 Pipe 负载、总工作量及稳定的平局项。分量间没有计算路径时，保留完整分量能够避免对其内部链额外切割。

当独立分量不足以提供足够并行性，且满足朝向汇点的树森林结构时，从根部逐步展开过重子树，保留彼此独立的前沿子树作为工作单元，把剩余归约部分合并为尾部 Task。基本构造对过大 Task 的进一步分块只发生在独立分量边界，避免任意截断依赖链。节点数阈值用于控制构造颗粒度，不作为容量证明。

### 4.4.2 分叉分阶段与树前沿

对于含多次分叉归约的图，直接保持完整弱分量会把大量可并行工作放在同一核。为此，在计算 DAG 上定义分叉阶段

$$
\rho(v)=\max_{u\in\operatorname{Pred}(v)}
\bigl\{\rho(u)+\mathbf1[\deg^+(u)>1]\bigr\},
\tag{4-11}
$$

源点阶段取 0。每条边上的阶段不下降；若边的起点是分叉点，则阶段严格增加。因此，同一阶段诱导图中的任一节点至多有一个后继，形成朝向汇点的树森林。

在阶段内部先收缩单入单出的串行链，得到保留完整链的原子单元。自各树根向前展开：若一个子树的最大 Pipe 工作量超过阶段对应工作量的 $1/(4K)$，且仍可沿子链展开，则把根链移入归约尾部并暴露其子树；否则保留该子树。因而无需扫描大量切点或随机重启，就能得到具有明确颗粒度的前沿。

前沿子树按工作量排序，结合已有依赖释放与核内等待估计分配到核心；新增输入字节用于平局处理。随后把归约尾部放在依赖允许且估计较早完成的核心。所有阶段按递增次序投影到各核序列。v4 不只在显式含 fork 的图上尝试这一候选，也将其作为一般多核备选，用来补充完整分量装箱可能遗漏的排列。

**命题 1：上述前沿—尾部构造的联合 Task 图无环。** 阶段诱导图出度至多为 1，故原子链收缩后仍为入树森林。根部展开留下的前沿子树互不相交且相互独立，移走部分构成朝向汇点的尾部，数据边只能由前沿指向尾部。跨 Task 数据边因此严格增加“阶段、前沿/尾部”字典序。若同一阶段同一相位在单核有多个 Task，则其中只有该核的前向顺序边。假设存在联合环，环不可能包含严格增加字典序的边，余下又只能是单核链，仍无法成环，矛盾。完整覆盖由每个链单元只被保留或移入尾部一次得到。

该命题证明覆盖与依赖结构，不证明容量、spill 数量或 Makespan 改善。尤其是较大的归约尾部与反复读取的输入，仍可能抵消新增并行性的收益。

### 4.4.3 结构互补的六类候选

统一 v4 入口最多保留六个不同方案，各构造针对不同瓶颈，均只读取当前图、核数和固定配置。它不根据用例编号、历史成绩或保存的优秀方案进行选择。[^v4source]

| 候选 | 结构依据 | 主要构造及作用 |
| --- | --- | --- |
| 完整分量与有界树前沿 | 独立分量、入树森林 | 保留完整依赖链，平衡 Pipe 工作量，作为基本方案 |
| 重分量与独占后缀 | 工作集中或可剥离的多出口结构 | 从汇点剥离独占后缀，按波次释放工作，避免单个重分量长期占据一核 |
| 超载分量分解 | 某分量的 Pipe 工作量超过总工作量的 $1/K$ | 构造可分波 Task DAG，以剩余路径和就绪关系安排核分配 |
| 输入预算与活跃核选择 | 分量数不少于核数、外部输入并集超过 524,288 B | 在 1～$K$ 个活跃核的结构配置中比较输入/工作代理，择一构造，再按深度整层划分输入窗口 |
| 容量约束回转分组 | 私有、同型、有序的 M→V+→M 链 | 以 L1/UB 保守占用限制链分组，调整前段与回转操作的 Task 边界 |
| 分叉阶段前沿 | 一般多核图中的分叉、链和树结构 | 按式（4-11）分阶段，保留完整链、展开前沿并集中归约尾部 |

重分量构造采用固定的主导负载判据，并限制后缀剥离轮数和每轮汇点数；超载分量构造优先安排剩余路径较长的就绪 Task。输入窗口每窗外部输入并集的 262,144 B 阈值及最多 32 个阶段是启发式控制量，不能当作所有内部张量均适配容量的证明。输入预算路线只比较至多 $K$ 个元数据配置，选定后实例化一个方案；它也可适用于大量私有输入，不要求外部输入必须被多个分量共享。

六类构造不是六轮任意参数扫描。每个候选由一个固定结构机制导出，构造结束后不根据评价分数反复修改切点。原图结构与各机制内部回退可能产生相同方案，统一入口按实际输出 JSON 字节的 SHA-256 去重。这里保留 Task 编号、映射顺序及数值类型，不假定任意 ID 重命名都保持官方编译行为。

### 4.4.4 在线选优、回退与整体流程

若去重后只有一个候选，则无需在线排序；单核也仅生成基本候选。多候选使用固定版本 E1 逐一评价，比较 Makespan 与实际 COPY 字节。E1 是队内加速评价实现，能够为选优提供执行反馈，但正式实验成绩仍由未修改的官方 E0 给出。

当评分返回失败时，停止后续评分并保留此前已成功评分的最优方案；若首项评分即失败，则保留基本候选并记录未获在线验证的状态。必要的基本构造失败意味着求解失败，不能把空输出记为有效方案。完全同分时保留已有候选顺序，避免无意义替换。

**算法 4-1：结构化有限候选求解。**

```text
输入：原始图 G、核数 K、冻结配置 Θ
输出：仅含规定两键的方案 P，以及独立诊断记录
1  从 G 提取计算依赖、分量、Pipe 工作和输入张量特征。
2  生成基本方案；若失败，记录求解失败并终止。
3  若 K > 1，按固定结构条件生成重分量、超载分量、
   输入预算/早期前沿、容量回转及尚未尝试的一般前沿候选。
4  对构造结果检查覆盖与联合依赖，按实际方案字节去重。
5  只有一个不同方案时直接保留；否则按固定顺序在线评分，
   按 (Makespan, scheduled COPY bytes) 更新当前最好方案。
6  遇到评分失败停止选优，保留已知最好；记录失败与调用次数。
7  写出方案和诊断，完成求解计时。
8  实验阶段另用未修改 E0 复评最终方案，保存结果与失败原件。
```

v4 至多生成六个不同计划、发起六次在线评分尝试。在线评分使用一个 worker、16 MiB 序列化缓存、每项 60 s 请求限额和 10 s worker 启动限额。缓存大小不是进程内存上限，单次请求限额也不是完整求解器的总时限。

设构造实际尝试集合为 $\mathcal C$，评分集合为 $\mathcal E$，端到端时间应写为

$$
T_{\mathrm{solve}}
=T_{\mathrm{启动与读取}}
+\sum_{c\in\mathcal C}T_{\mathrm{构造},c}
+\sum_{e\in\mathcal E}T_{\mathrm{在线评价},e}
+T_{\mathrm{通信、选择与收尾}}.
\tag{4-12}
$$

已经发生的重复候选构造也计入第一项求和。邻接图形成后，阶段扫描和森林处理主要为线性扫描加工作单元排序，但原始张量的生产者—消费者展开、COPY 路径收缩、集合操作和评价器事件处理需另计。因此，常数候选数限制了方案比较次数，却不能单独证明完整求解器为线性时间。

### 4.4.5 同型链的变宽分组动态规划

为继续改善容量回转候选，在私有同型 M→V+→M 链上引入“已处理链数—待回转链数”状态。直观上，一部分链可以先执行前段，把末端 M 操作留到下一 Task；这样可能让不同 Pipe 的工作更加均衡，但同时增加切口 COPY 与 Task 门控。分组宽度因此不宜只按容量取一个固定最大值。

设共有 $L$ 条同型链，按原有序链列表轮转分配到 $K$ 个核；每核同步处理的公共前缀含 $N=\lfloor L/K\rfloor$ 条链，其余链在终端收尾时处理。以下讨论 $N\ge1$，没有同步前缀时直接处理余数。状态 $(n,r)$ 表示已引入 $n$ 条链，其中最近的 $r$ 条尚未执行末端回转。一次普通转移继续引入 $q$ 条链，并留下其中 $s$ 条的回转，其 Task 包含：旧的 $r$ 个回转、新增的 $q-s$ 条完整链，以及新增的 $s$ 条前段。记单链前段、回转及整链在存储区域 $\ell$ 的张量并集大小分别为 $P_\ell,R_\ell,W_\ell$，采用保守守卫

$$
rR_\ell+(q-s)W_\ell+sP_\ell\le C_\ell,
\qquad \ell\in\{\mathrm{L1},\mathrm{UB}\}.
\tag{4-13}
$$

这里的私有性、操作及张量顺序同型性必须先由识别器验证，不能把式（4-13）直接推广到任意共享张量图。状态范围和分组宽度由容量与链数推导，不按用例编号指定。

具体取 $Q_{\max}=\min\{N,\min_{\ell:P_\ell>0}\lfloor C_\ell/P_\ell\rfloor\}$，$R_{\max}=\min\{Q_{\max},\min_{\ell:R_\ell>0}\lfloor C_\ell/R_\ell\rfloor\}$；空的内层限制忽略。普通转移满足 $0\le r\le\min(n,R_{\max})$、$1\le q\le\min(Q_{\max},N-n)$、$0\le s\le\min(q,R_{\max})$，并通过式（4-13）。只清空回转的转移要求 $r>0$。

将每个通过守卫的 Task 通过冻结官方 Step1/Step2/Step3 编译，提取实际逐 Pipe 队列和前驱需求，形成包含 FIFO 与共享 DDR 作用的响应代价。该已测细化入口使用的响应契约限定于无 spill、无 MEM 复用依赖且无跨核 Task 依赖的保守域；其他合法 P1 方案可能不被该契约接受，后续 MEM 扩展的验证边界另见 4.6 节。

代价跨层复用还依赖更强的有序性检查：相邻链的计算节点 ID 区间和所触及张量的 ID 区间分别不交错，链内操作、张量、直接依赖及原始输出标记的有序描述相同。实现以保留相对编号和边界 COPY 信息的完整有序键复用代表编译；一般图同构或相同工作量不足以建立这一关系。只有在该守卫与编译响应契约下，普通转移才按 $(r,q,s)$ 建表，并在满足剩余链数条件的不同 $n$ 层复用。记其字典序代价为 $\mathbf c(r,q,s)$，三个分量依次是响应周期、COPY 字节和 Task 数。普通转移为

$$
\mathbf D(n+q,s)
=\min_{\mathrm{lex}}\left\{
\mathbf D(n+q,s),\ \mathbf D(n,r)+\mathbf c(r,q,s)
\right\}.
\tag{4-14}
$$

另允许只清空待回转部分的转移 $(n,r)\to(n,0)$。后者不增加已引入链数，但只从非零回转状态指向零状态；普通转移则严格增加 $n$，所以状态图仍可按层求最短路。末尾不足一个均匀分组的链单独处理，比较规定的合并与分离收尾策略。代价中统一计入的初始门控在最终还原时扣除，避免给首 Task 多加等待。

动态规划在给定响应表和上述状态图内满足最优子结构：到达相同 $(n,r)$ 的后续可行转移集合相同，保留字典序最小前缀不会损失该状态图内的最优路径。在上述两个容量上限均为正、转移表已生成的条件下，$N$ 层状态松弛的上界可写为

$$
O\!\left(N R_{\max}Q_{\max}\min(Q_{\max},R_{\max})\right),
\tag{4-15}
$$

静态编译、响应模拟及最终全方案重编译成本另计。当这些上限都随链数增长时，不能将其笼统称作线性动态规划。实现还设置代表 Task 编译数、最终 Task 数及子进程时间预算；超过预算表示本轮未能完成该构造，不表示该结构不可行。

输出前在原始图与原 ID 上重新编译全部选中 Task，核对响应签名、COPY 总字节和完整模型响应与所选路径一致。当前响应模型采用有理数服务与整数退休，而官方事件循环使用浮点剩余服务、容差和取整。因此，Bellman 证书只能证明所声明同步状态图在指定响应代价下的最优性；它不证明任意异步 P1 方案的全局最优，也不能仅凭响应表等式声称与 E0 全域等价。最终候选仍由在线 E1 选择并由独立 E0 验证。[^refinement]

### 4.4.6 完整链错峰与局部归约融合

重复 fork/join 的另一个瓶颈是多个核心在同一时刻发起较大的输入 COPY。切断计算链虽然可能提前释放后继，却会增加内部张量搬运。为此，保留每条完整计算链，只调整源核的一组链在 Task 间的分配，让部分源核输入稍后发起，以缓解远端输入的同时竞争。

当前实现限于严格识别器接受的全 V Pipe 完整链—归约结构。在已测的 24 轮结构中，每轮包含 12 条四节点完整链及 11 个 ADD 归约节点。三核配对试验保持链到核映射、尾核和归约方式不变，仅将第 2～24 轮源核的四条链从一个 Task 改为“先一条、后三条”两个 Task。跨 Task 数据边和核序仍沿轮次与相位前向推进，完整链未被切断。其设计依据是：当归约必须等待远端 Task 返回时，源核的一部分推迟可能被已有等待覆盖，而远端输入更早完成能够缩短整轮时间。

另一种构造把依赖完全位于同一链组的局部归约子树融合进该组 Task，减少不必要的归约边界与数据搬运，同时保留跨组依赖。这种融合依赖实际依赖闭包，不能仅凭“节点在同一核”就任意合并。

最新研究入口先运行 v4 及条件性的变宽分组改进，再在严格完整链识别器接受的结构中，最多补充错峰与局部归约融合两个候选。进入这一层之前，必须取得与当前输出方案字节哈希相匹配的成功在线评分；没有该证据则保留父方案。整个研究入口最多有六次基础候选评分、一次分组细化评分和两次完整链细化评分。该调用上界属于研究入口，不能与 v4 的六候选上界混用。[^refinement]

### 4.4.7 下界、证书与改进空间

理论分析用于区分“构造较差”和“资源本身受限”，并排除不值得继续优化的固定方案。为避免把某个候选的约束误当成全局约束，本章区分通用下界、固定方案下界和受限构造族证书。

**（1）通用计算资源与关键路径界。** 对非 COPY 操作按 Pipe 求和，每条 Pipe 总共只有 $K$ 个执行槽，因此

$$
L_{\mathrm{comp}}
=\max_p\left\lceil\frac{\sum_{v:p(v)=p}d_v}{K}\right\rceil.
\tag{4-16}
$$

另在官方必然保留的计算边上求最长路径 $L_{\mathrm{cp}}$。这些边只包括原始计算操作直接相连，以及经原张量相连的计算生产者—消费者关系，不穿越被删除的 COPY 桥进行收缩。同 Task 内保留这些边；跨 Task 时整体完成门控也不会放松它们。故两项均提供必要时长，组合时取最大值而非相加。

还可给每个操作计算不含自身时长的必要释放下界 $r_v$ 和完成后尾部长 $q_v$。对同一 Pipe，选非空集合

$$
U(a,b)=\{v:r_v\ge a,\ q_v\ge b\}.
$$

这些工作全部落在 $[a,M-b]$ 内，$K$ 个槽最多提供 $K(M-a-b)$ 的处理量，因此

$$
M\ge a+b+\left\lceil\frac{\sum_{v\in U(a,b)}d_v}{K}\right\rceil.
\tag{4-17}
$$

阈值只需取实际出现的释放和尾部坐标。按释放时间降序激活操作，对尾部坐标做前缀加和最大值查询，可在每条 Pipe 上用线段树完成 $O(n\log n)$ 的窗口计算。只查询非空窗口，避免空集产生虚假的大下界。

**（2）必要 DDR 服务界。** 对张量 $t$，令 $P(t),C(t)$ 为直接相邻的非 COPY 生产者和消费者。至少一次输入服务对应 $P(t)=\varnothing,C(t)\ne\varnothing$ 的张量；至少一次输出服务对应存在计算生产者且无计算消费者或存在原始 COPY_OUT 消费者的张量。对这些必要实例分别按式（4-6）取整再累加，得到理想服务模型中的 $L_{\mathrm{DDR}}$。DDR 是共享资源，不能再除以核数。该推导也不允许直接累加原图全部 COPY，因为其中某些节点在重建 Task 后不会原样出现。涉及理想服务与官方浮点事件实现的等价性时，必须保留数值域和验证范围限制。[^bounds]

**（3）固定方案的门控界。** 给定 Task 划分和核序，对每个 Task 用其保留计算关键路径与最大 Pipe 工作量得到时长下界，再在式（4-3）的联合 DAG 上加入对应的同核、跨核等待求最长路，得到 $L(P)$。如果 $L(P)$ 已大于对照方案的实际 Makespan，那么只改变该方案的 DDR 重叠、而不改变 Task 划分和核序，就不足以超过对照。此时应更换释放边界或分配方式。由于 $L(P)$ 使用了固定划分，它不能作为任意 P1 方案的全局下界。

若已获得适用于同一优化域的有效下界 $L$，当前合法方案值为 $U$，则

$$
L\le M^*\le U,\qquad
\frac{U}{M^*}-1\le\frac{U}{L}-1.
\tag{4-18}
$$

上式能够给出当前解相对最优值差距的上界；较大的 $U/L$ 只说明现有证据尚不能收紧差距，不保证存在相应幅度的可实现改善。当前没有覆盖全部 P1 合法方案、并与已得成绩闭合的最优性证明。

## 4.5 求解结果与分析

### 4.5.1 实验设置与数据范围

完整实验使用 100 个官方给定图，核数取 1～5，形成 500 个“图—核数”单元。源代码固定为统一 v4 的同一提交；每格重新生成方案，再由未修改 E0 评价最终输出。该批 500 次求解与 500 次外部 E0 均成功，共记录 1,028 次在线 E1 调用，未使用 E2，未重试。全部分母来自同一份固定官方单核基线。[^full500]

运行环境记录为 Apple M5 Pro、macOS 27 arm64、Python 3.12.13，内存 51,539,607,552 B，批次最多 4 个 worker；候选内部评分采用单 worker。每次求解启动新的解释器进程，但没有清空操作系统文件缓存，因此不称作严格的整机冷启动实验。现有记录没有同条件重复计时与置信区间，硬件环境中的离线准备成本也未被独立量化。

### 4.5.5 负结果与模型修正

共享输入的矩形分块试验说明了代理目标的局限。该构造在同构 job 与连续计算位置上采用容量并集约束，并用区间动态规划和简化流水递推选择一个计划。044 三核和四核实际 Makespan 分别为 84,041 和 82,479 cycle，均差于 v4 对应的 64,624 cycle。两格均无 spill，重新统计的边界 COPY 字节与官方结果一致，四核独占 DDR 服务量 49,494 cycle 也与代理一致，但实际执行仍明显更慢。

四核 trace 中，core 0 在 22,460 cycle 结束，而 core 3 直到 43,334 cycle 才开始，暴露出填充、收尾和有效重叠不足。因而，正确计算字节量和独占 DDR 服务量，是构造代理的必要基础，却不足以保证时间预测准确。后续响应模型需要保留 FIFO 队首、就绪条件和真实竞争状态；不能仅扩大原代理上的参数搜索。[^negative]

### 4.5.6 当前研究入口的验证边界

变宽分组与完整链两候选已经组合进 `structural_refine.py` 研究入口。该固定入口的一次 500 格尝试实际完成 68 格，另有 1 格外部 E0 超时和 431 格未运行，尚未构成新的完整结果。

超时格 014/4 的求解程序已在约 76.235 s 完成；达到 900 s 实验限额的是之后的独立 E0。新计划与此前 v4 的计划字节相同，可以作为身份对照，但旧结果不能把这次失败改写为一次新的成功。其失败与未运行范围均保留，因此当前完整统计仍采用 v4。[^partial]

### 4.5.7 含内存复用依赖的真实模型验证

后续逐步展开原型已在 008 五核上完成一次真实编译与模型衔接试验。固定入口包含结构初始路径，实际进行了 16 次 Task 编译，其中 8 次用于最终方案重新编译，并完成 3 次有理数响应模拟。输出的 8 个 Task 覆盖 864 个计算操作；逐 Task 签名、搬运字节及整图模型回放均与分段预测一致，得到模型周期 101,836、额外 DDR 为 0 的候选。该试验未运行 E0、E1 或 E2，因此属于真实模型接口验证，不能列为新增官方成绩。[^memorypilot]

该例也说明了保守容量守卫的适用边界。以首个 Task 为例，编译后受管张量的 L1、UB 总量分别为 903,168 B 与 1,556,394 B，均超过对应容量；Step3 报告的峰值却分别为 36,864 B 与 37,056 B，且无 spill。接口保留了内存复用前驱并通过该 Task 的执行契约检查，因此能够表示仅按张量总并集筛选时被排除的结构。这里引用的是该次编译的 Step3 峰值与契约记录，不把它推广为任意重放或真实硬件上的峰值保证。

本次初始路径在每核首组引入 21 条完整链、使用零回转切口，再以合并策略处理剩余 3 条链。预设的两次边查询预算在取得初始路径后用尽，搜索仍有未展开区域，模型最优性未证。资源选点值 97,068 cycle 尚未计入终端的 100 cycle 门控，补计后为 97,168 cycle；搜索保留的前沿下界则为 52,146 cycle。路径资源界与前沿下界作用不同，均不能替代官方全局下界。该记录推进了“代码已连接接口”到“一个真实用例的模型核验通过”，完整 v4 均值及后续研究入口的批次覆盖仍按前述范围分别报告。

## 4.6 方法评价与后续衔接

本章的主要方法是用图结构约束构造空间，显式考虑 Task 整体完成门控、Pipe 负载和共享 DDR，再以少量在线评价修正静态代理无法覆盖的执行效应。完整 v4 在 100 个官方图、1～5 核上取得了可追溯的结果；后续变宽分组、输入错峰和归约融合提供了进一步改善的机制证据。理论分析同时给出联合图合法性论证、资源下界和受限状态图证书，使性能解释与可证明范围对应。

当前方法仍有三方面局限。首先，六类结构不能覆盖任意复杂图的最佳划分，识别器拒绝某种构造不意味着原问题不可行。其次，在线评价增加了尾部耗时，其返回成功和当前测试域的一致性不能代替 E0 全域等价证明。再次，动态规划证书依赖同步模板、响应代价与内存守卫；内存复用、编号敏感释放及不对称流水可能使该模型需要进一步扩展。

**按下界逐步展开转移的研究方向。** 变宽分组动态规划若预先编译大量代表 Task，前置成本可能抵消方案质量的收益。因此，可先用必要计算工作和共享 DDR 服务量为一组分组选择计算下界，再优先查询仍可能改善当前方案的转移。新的抽象控制器将尚未处理的整数对 $(q,s)$ 放在矩形区域内，二分时保持对合法选择的完整、不重叠覆盖；仅当区域缩小到一个整数选择时才查询精确边代价，清空回转与终端收尾另行处理。边代价查询次数和区域展开次数分别设预算，避免虽然只允许少量编译，却耗费大量时间拆分候选区域。

这一方向可结合更强的 FIFO 条件界：若实际编译保证完整链片段先于前段和回转片段执行，完整链内部的计算空隙便不能任意由后两类工作填补。该性质需要私有同型链、保留原图 ID 与链内结构顺序、无 spill、无内部原始 COPY_OUT 输出分支等结构守卫；其中末端 V 必须产生被末端 M 消费的张量，仅存在 V→M 操作边不足以替代张量条件。由这些条件得到的界，只用于对应受限模型，不能推广为任意图的官方 Makespan 下界。

为降低有限预算内尚未找到完整路径的风险，后续 MEM 原型先尝试一条有结构依据的初始路径：每核首组一次引入公共前缀的 $N$ 条链，即固定 $q=N$，再用合并策略处理回转与余数。对于 $1\le s\le N$，取整前的首组和终端必要资源表达式之和是若干仿射函数最大值的和，因而为凸分段线性函数。取一个连续极小点 $s^\star$，凸性使其左侧不增、右侧不减，故 $\lfloor s^\star\rfloor$ 与 $\lceil s^\star\rceil$ 中至少包含一个整数极小点；另行比较 $s=0$ 的特殊分支，最多检查三个整数选择。这里最小化的是资源放松，只决定优先尝试哪个切口数量；不能用所得下界代替实际响应或直接提供可行上界。

只有首组与终端的模型代价均成功取得，完整费用才作为同一模型的当前上界；空终端费用为零，无需额外响应模拟。两次查询占用既定总预算，遇到未知或不支持时不生成上界，后续再次遇到相同边也不隐性重试。初始路径不会删去其他分组和多阶段转移；无公共前缀或查询预算不足两次时仍用普通搜索。因而，这一步是确定先尝试的结构，并不把优化空间限制为每核只用两个 Task，也不提供全 P1 最优性保证。[^seed]

进一步的研究考虑重复固定分组与回转数量的多阶段形状，把集中收尾的工作分散到连续 Task 中，代价是增加门控和边界搬运。只有各核实际响应签名一致、各同步阶段先后串接时，才能把各段的必要资源下界与段间门控相加；剩余尾部资源只在最后计入一次，不能反复累加包含完整尾界的区域下界。当前诊断扫描至多 $N(N+3)/2$ 个分组参数对，只做整数资源计算，不编译或评估实际方案。更低的下界只说明某形状尚未被该放松排除，不能推出其可行性或实际优于另一方案。该诊断用于确定后续证伪对象；若用于在线求解，其计算成本也须计入端到端时间。[^periodic]

控制器还区分“已证不支持”与“未知或超时”。后者仍保留未解决路径及其下界，不能作为不可行边删除；某状态获得更小前缀代价时重新展开，但缓存同一抽象边的查询结果，不因重开状态而隐性重试。这要求未来可行转移与代价只由当前状态决定。只有在同一抽象模型内，已知完整路径的上界与全部活跃未决路径的下界相等，才能得到该模型的标量最优证书。操作之间的协作式停止检查保留未展开区域；单次操作被外部强制中断，则只能按实际保留的记录报告未知，不能宣称仍持有完整的最优性证书。[^lazy]

**MEM 响应接口与候选核验。** 最新研究原型已在代码层将上述控制器连接到 Task 编译与内存复用响应接口。接口读取经官方 Step3 验证的执行图，把内存复用前驱纳入逐 Pipe 的完成前缀要求，从而允许研究张量总并集守卫之外的候选；仍要求官方编译确认无 spill，且不接受跨核 Task 依赖。缓存仅对相同原始节点元组复用，不假定跨 ID 编译等价。每个同步组只有在各核实际编译所得的响应签名相同时，才作为一条标量转移；首组不附加前置门控，后续组与清空回转各加一次，终端按剩余任务整体模拟。没有公共前缀或终端为空时，不凭空增加终端前置门控。

模型候选发布前，须在原图和原 ID 上重新编译全部选中 Task，并同时核对逐 Task 响应签名、总搬运字节和完整响应的整数 Makespan。核验预算预先保留；即使搜索尚未证明标量最优，也可保留通过最终核验的候选，并明确最优性未证。预算耗尽、编译未完成或核验不一致不能改写为原问题不可行。此处的构造时限只覆盖程序内部规定的一段流程，不能代替启动至结果落盘的端到端墙钟。[^memoryprobe] 含初始路径的版本先有 27 项数学及替身接口测试和结构元数据选点记录，随后完成第 4.5.7 节的 008 五核真实模型验证。[^seed][^memorypilot] 后者尚无独立 E0 或同条件质量—耗时对照，不能据此宣称官方质量提升或完整程序提速。模型核验、官方数值复评与完整批次验收仍是三个不同阶段，当前主表继续采用 v4。

后续改进应优先完成新统一入口的完整验证，分析低核数共享输入结构与容量约束下的广泛退化，再决定是否增加候选。相邻 Task 合并可减少边界 COPY，但必须重新核查容量、联合依赖以及编号变化对编译的影响，不能把字节非增直接提升为 Makespan 非增。数据更新时将固定新入口、保留失败、重算全体均值，并同步修改正文和图表来源。

问题二和问题三可沿用本章的输入身份、合法映射与核心分配表示、逐例统计及求解计时口径，再按各自官方语义重新建模。情况 A 的 Task 整体门控不能直接套入后续场景；问题三还需在同核数下比较无 L2 与只读 Cache，并按字节统计命中率。各问共享表示和证据规范，执行约束与改进效果分别验证。
