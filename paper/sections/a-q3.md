# 问题三：共享只读 Cache 下的结构化图划分与多核调度

> 论文初稿，2026-09-25。章节编号暂用“6”，合稿时统一调整。本稿整理 P3 完整方法，详细图件采用文字占位；占位不代表实验结果。完整统一算法固定为 `311322b996c0948e8a6a9c7ec6ddfe6ae41fbee1` 的 `src.q3.forest_solve`，完整结果采用 `19bebf35205d23fdd832781540f8879da52eeb62` 的 revision2 数据。容量改进和单尾拓展另列验证范围，不混入该统一算法的总表。来源及修订规则见[证据索引](../notes/a-q3-evidence.md)。

## 6.1 问题分析与建模思路

问题三在问题二的多核执行模型上增加共享只读 Cache。多个计算核访问同一逻辑张量时，已经进入 Cache 的数据可以通过更快的通路读入，减少部分 DDR 服务需求。然而，Cache 收益取决于数据何时读入、其他核何时再次访问，以及两次访问之间是否发生淘汰。因此，具有相同分核负载的两个方案，也可能因访问次序不同而表现出明显差异。

本问同时存在三类相互制约的因素。首先，计算任务需要分散到多个核，以减小最繁忙核的计算负载；其次，共享输入应尽量形成有效复用，避免工作集超出片上容量引发反复搬运；最后，原始依赖、各执行流水线的 FIFO 次序和跨核 COPY 等待会限制并行启动的时刻。只优化其中一项，容易在另一项上产生更大的损失。例如，将访问相同权重的运算集中处理可能提高命中率，却也可能延迟后续归约；过度追求核间均衡，则可能增加跨核通信和内存溢出。

据此，本文采用“结构识别—直接构造—条件下界剪枝—官方模拟接受”的求解框架。利用同构作业、共享输入和归约树等可识别结构形成少量有明确动机的候选；保留原图运算与依赖，通过合法划分、分核和核内顺序实现优化；最终以官方 Makespan 决定候选是否被接受。命中率、额外搬运量和静态峰值用于解释结果，不代替首要目标。

## 6.2 符号、执行语义与优化模型

### 6.2.1 输入与决策变量

设原始图为 $G=(V,T,E)$，其中 $V$ 是计算操作集合，$T$ 是张量集合，$E$ 表示原始依赖；张量 $t$ 的大小为 $b_t$ 字节，计算操作 $v$ 的流水线记为 $p(v)$，有效计算时长为 $d_v=\max(1,\mathrm{cycles}_v)$ 周期。原始 COPY 和 DDR 端点保留在官方输入中，构造提交方案时遵循官方对计算节点的映射要求。

| 符号 | 含义 | 单位或范围 |
|---|---|---|
| $K$ | 请求使用的核数 | $1,\ldots,5$ |
| $\phi(v)$ | 计算节点到子图的映射 | 子图编号 |
| $\kappa(g)$ | 子图 $g$ 的核分配 | $0,\ldots,K-1$ |
| $\sigma_c$ | 核 $c$ 上的子图顺序 | 有序序列 |
| $P=(\phi,\kappa,\sigma)$ | 一个可提交的调度方案 | — |
| $p(v),d_v$ | 操作的执行流水线、有效计算时长 | 流水线类型、周期 |
| $M_3(G,P)$ | 只读 Cache 场景的 Makespan | 周期 |
| $M_2(G,P)$ | 相同方案在无 L2 场景的 Makespan | 周期 |
| $D_{\mathrm{extra}}$ | 官方总额外搬运量 | 字节 |
| $H$ | Cache 按字节命中率 | $[0,1]$，无有效读取时按源数据约定处理 |
| $T_{\mathrm{solve}},T_{\mathrm{E0}}$ | 完整求解墙钟、独立外部复评墙钟 | 秒 |

方案仅通过 `node_to_subgraph` 和 `core_schedules` 两个字段提交；后者同时编码核分配与核内顺序。每个要求映射的计算节点应恰好属于一个子图，每个子图应在请求核数对应的一个执行列表中恰好出现一次，并通过官方依赖、拓扑和执行合法性检查。不能借助附加字段控制模拟器，也不能修改计算操作、张量大小或固定硬件配置。

P2/P3 按每核提交顺序构造合并 Task，重建基础 COPY 和跨核通信，再执行官方内存处理与事件模拟。因此，$\sigma_c$ 是合法的构造与优先顺序输入，不等于可任意指定的操作开始时间。P1 的 Task 完成门控和等待规则不能直接用于 P3。本文大量构造采用单计算节点子图，以表达较细的核内顺序；这仍然使用原题接口，并未引入新的提交自由度。

### 6.2.2 只读 FIFO Cache 与带宽竞争

所有对照采用冻结配置：每核 L1 为 524,288 B、UB 为 131,072 B；共享 Cache 容量为 1,048,576 B；DDR 和 Cache 读取带宽分别为 60 B/cycle、250 B/cycle；P2/P3 跨核 COPY 等待为 500 cycles。

模拟开始时 Cache 为空。只有符合条件的 `COPY_IN` 在开始执行时查询其逻辑张量是否驻留；命中进入 Cache 读取池，未命中进入 DDR 通路。`COPY_IN` 完成时尝试插入相应条目：若已经存在，则不改变其顺序；若不存在且能容纳，则按 FIFO 淘汰最早插入的条目直至容量足够。超过 Cache 总容量的单个条目不被插入。命中本身不会刷新 FIFO 次序；插入发生在读取完成时，不能以提交列表中的相邻关系直接判定命中。

DDR 与 Cache 读取是两个共享服务池。池内活动传输平分服务能力，传输加入或完成都会改变剩余操作的预计结束时刻。因此，单次 COPY 的实际历时不能始终写成独占情况下的 $\lceil b_t/B\rceil$；该式只适合用作独占传输的名义成本。跨核消费者还必须等待相应生产端 COPY 完成及固定跨核延迟，不能简单地把所有跨核边统一替换成可自由移动的等待操作。

还需区分两处取整。对进入共享池的 COPY，官方先按该次相关张量的总大小计算 $\max(1,\lceil\sum_t b_t/B\rceil)$，将这个整数作为初始服务工作量；随后按活跃传输数推进剩余工作，再将预计完成时刻按带容差的向上取整确定退休事件。因此，前缀名义工作量应逐笔计算后求和，不能先汇总字节再取整，也不能把服务工作量直接当作共享竞争下的实际历时。

上述语义解释了 Cache 优化的非单调性：较早完成的一次命中会改变后续操作的启动时刻，进而改变两个共享带宽池的竞争和最终关键路径。局部读取变快与整体完成时间变短之间，需要通过完整事件模拟建立联系。

### 6.2.3 目标函数与指标口径

记 $\mathcal F(G,K)$ 为通过官方合法性与执行检查的方案集合，主问题为

$$
\min_{P\in\mathcal F(G,K)} M_3(G,P).
\tag{6-1}
$$

同时报告 $D_{\mathrm{extra}}$ 与 $H$，用于刻画搬运代价和 Cache 行为。总额外搬运采用官方字段定义，即调度后 COPY 字节相对于原图 COPY 字节的增加量；该量与实际从 DDR 服务池读出的字节不是同一个概念，Cache 命中不会自动使计划中的 COPY 操作消失。字节命中率为

$$
H=\frac{B_{\mathrm{hit}}}{B_{\mathrm{hit}}+B_{\mathrm{miss}}}.
\tag{6-2}
$$

为区分并行调度质量与 Cache 的独立影响，使用两组指标。设 $A_i$ 为第 $i$ 个用例固定的官方 A 场景单核基线，$P_{i,K}$ 为当前统一算法生成的方案，则相对基线的算术平均加速比为

$$
\overline A_K=\frac1N\sum_{i=1}^{N}
\frac{A_i}{M_3(G_i,P_{i,K})}.
\tag{6-3}
$$

同计划 Cache 收益定义为

$$
C_{i,K}=\frac{M_2(G_i,P_{i,K})}{M_3(G_i,P_{i,K})},\qquad
\overline C_K=\frac1N\sum_{i=1}^{N}C_{i,K}.
\tag{6-4}
$$

式（6-4）要求原图、核数、方案字节及其他固定配置相同，只有 Cache 场景发生变化。分别为 P2、P3 重新优化所得的最佳成绩之比，可用于比较最终方案，但不能直接解释为同计划 Cache 加速。两种平均均逐用例取比值后再平均，不使用总时间之比。若报告跨用例命中率，还须区分各用例命中率的算术平均与汇总 hit/miss 字节后的加权比例。

同计划 CacheGain 是本问评价 Cache 相对效益的核心比较指标。需要说明的是，当前冻结算法的候选接受条件仍只比较 $M_3$；$C_{i,K}$ 已进入完整报告，尚未直接进入候选接受规则。因此，本稿不能将“已经做了 Cache 对照”写成“已经同时优化了 CacheGain”。后续应同时考察实际 $M_3$ 与同计划 $C$，报告两者的取舍；不能通过恶化无 L2 分子抬高比值，也不能把命中率当成 $C$ 的替代量。此实现边界已与队长的[目标审计](https://github.com/huaweibei123/huaweicup2026/blob/a73d1e1e664ef95e6cdc8d9d0da2d95fba7aa718/results/a/q3-nikolastarx/forest-cachepair-delta-20260925/OBJECTIVE_AUDIT.md)对齐。

求解程序效率另用 $T_{\mathrm{solve}}$ 衡量，包含输入读取、结构分析、候选构造、在线评价、回退及合法方案写出。在线调用 E0 选优时，该评价耗时必须计入求解墙钟；最终独立复评另列为 $T_{\mathrm{E0}}$。原题给出的 5～10 分钟为问题一的求解效率建议，本队在 P3 沿用这一设计目标，并继续追求更低时延；它不是 Makespan，也不是本问另行规定的 600 秒淘汰线。

## 6.3 结构化统一求解算法

### 6.3.1 共享输入描述与结构识别

预处理首先建立计算依赖、张量生产者/消费者、流水线类型、计算时长和张量字节索引。对外部输入张量 $t$，将所有消费者视为一个共享输入超边 $\mathcal U_t$。分核后可定义结构性访问代价

$$
I(P)=\sum_{t\in T_{\mathrm{in}}}
b_t\left|\{\kappa(\phi(v)):v\in\mathcal U_t\}\right|.
\tag{6-5}
$$

它描述输入被多少个核使用，可帮助识别重复输入和分核取舍，但不计真实驻留、预取和再次淘汰，因而不是官方 DDR 字节的精确公式，也不能单独用于最终选优。本文早期尝试过围绕共同输入排序和负载受限分核，随后将这些特征用于识别可稳定利用的结构，而不将“共享更多”直接等同于“运行更快”。

统一算法按结构条件选择构造路线：同构阶段/汇聚结构采用阶段构造；受支持的注意力及前馈结构采用行或模块构造；一般分叉—汇聚 DAG 尝试依赖感知的空闲区间插入；不满足专用条件时保留通用结构方案。路由条件来自图结构、算子类型和资源配置，不读取用例名称或历史最优表。所有专用构造在不满足条件时明确退出该路线。

一般 DAG 构造同时考虑任务就绪与各资源已占用的区间，将可执行操作放入满足依赖的较早空闲区间，而不是只追加到当前最长队列尾部；汇聚后继的释放约束用于避免分支被过度拉开。此资源日历是候选构造模型，官方共享 DDR、内存补边和 Cache 状态仍以 E0 为准。对注意力路线，算法进一步比较固定的空闲区间放置候选；若最终就绪排序破坏了放置阶段已有的代理优势，则在剩余调用预算内保留原放置次序作为一个候选。该机制只决定尝试什么方案，不预先断言其官方性能更好。

一般 DAG 路线具体将单前驱、单后继的连续计算段凝聚为链，按剩余计算关键路维护就绪队列；每核 M/V 空闲区间以持久 AVL 树存储。普通就绪链考察 $K$ 个核；若其完成恰好释放一个汇聚链，则联合考察两条链的至多 $K^2$ 种归核，按预计汇聚完成、前链完成和跨核边数的固定次序打破平局。每条链只被正式放置一次，试放置使用独立的持久日历版本，不能覆盖已提交区间。设计算依赖展开后有 $N$ 个操作、$E_c$ 条边，使用对数时间的空闲区间查询与预订，可给出 $O(K^2(E_c+N\log N))$ 的构造时间上界；输入展开、其他路由和官方评价另计。传输只用固定等待与名义 COPY 服务估计，故该复杂度不代表完整缓存模拟复杂度。

冻结入口的调用顺序如下，各行共享一个在线评价账本：

| 顺序 | 构造模块 | 进入条件与候选作用 |
|---:|---|---|
| 1 | 基础结构路由 | 窄条件阶段迁移 → 一般阶段 → 注意力/前馈 → 一般 DAG 或通用结构策略；仅结构守卫拒绝时进入下一路线 |
| 2 | 注意力空隙放置 | 仅注意力多核路线，至多增加一次固定放置候选 |
| 3 | 共享输入连续流水 | 多核且同构链、共同输入签名等守卫通过，至多增加一个连续划分候选 |
| 4 | 注意力放置次序保留 | 放置阶段代理严格优于就绪重排代理，且评价次数仍少于 3 |
| 5 | 森林内部峰值排序 | 归约森林守卫通过，且评价次数仍少于 3 |

第一行中的窄条件迁移先以五核、12 个计算源点触发检查，仍需构造器进一步确认严格重复阶段签名；不能仅凭源点数量认定图具有相应结构。阶段和注意力直达路线各产生并评价自己的一个基准；一般 DAG/通用路线可在新结构基准上再试一个候选。这个入口不同时运行所有基础路线后挑最优，也不保证某条路线优于其他历史方法。

### 6.3.2 同构作业的连续阶段划分

设图包含 $J$ 个同构作业，每个作业有 $L$ 个有序计算位置，第 $\ell$ 个位置耗时为 $w_\ell>0$。仅在作业具有相同流水线、时长及共同输入消费签名，且原图支持该串行位置模型时使用本构造。将位置序列切为 $s\le K$ 个非空连续阶段

$$
0=x_0<x_1<\cdots<x_s=L,
\qquad p_j=\sum_{\ell=x_{j-1}}^{x_j-1}w_\ell.
$$

每个阶段占用一个不同的核，所有作业按同一顺序依次经过各阶段；同一阶段一次只处理一个作业。忽略 COPY、容量和流水线重叠时，这一串行阶段流水模型的完成时间为

$$
\widehat M_{\mathrm{pipe}}=
\sum_{j=1}^{s}p_j+(J-1)\max_j p_j.
\tag{6-6}
$$

第一项与切点无关，因此只需求连续分段的最小最大段和。令 $W_i=\sum_{\ell<i}w_\ell$，递推为

$$
D_j(i)=\min_{j-1\le h<i}
\max\{D_{j-1}(h),W_i-W_h\},
\quad D_0(0)=0.
\tag{6-7}
$$

其余不可达状态为 $+\infty$，记录前驱可恢复切点。对每个末段起点枚举一次即可完成递推，时间复杂度 $O(sL^2)$，空间复杂度 $O(sL)$。这是固定串行阶段抽象中的精确解，不是原始 P3 问题的全局最优解；式（6-6）也不作为未经证明的官方上下界。

### 6.3.3 归约森林的内部张量峰值排序

对存在多个归约树、内部结果只有唯一父消费者的结构，保留原树和组件归核，只调整孩子子树的完成次序。设完整计算孩子子树 $i$ 的内部张量峰值为 $h_i$，完成后必须为父节点保留的结果为 $r_i$，二者单位均为字节，满足 $h_i\ge r_i\ge0$。

限定每次完整执行一个孩子子树、兄弟子树互不交错。若先计算 $i$ 后计算 $j$，这一局部顺序的峰值为

$$
\max\{h_i,r_i+h_j\}.
$$

当 $h_i-r_i\ge h_j-r_j$ 时，有

$$
\max\{h_i,r_i+h_j\}
\le \max\{h_j,r_j+h_i\}.
\tag{6-8}
$$

证明如下：由排序条件得 $r_i+h_j\le r_j+h_i$，又因 $r_j\ge0$，有 $h_i\le r_j+h_i$，故左侧两项均不超过右侧。此前已经保留的字节在两种顺序下相同，两子树完成后的总保留量也相同，因此交换不会恶化其余部分。反复交换逆序对，得到按 $h_i-r_i$ 降序执行的次序；它在固定树、固定归核且兄弟子树完整不交错的模型中，使内部输出张量的标量峰值最小。

对父节点自底向上计算

$$
h_v=\max\left\{
\max_j\left(\sum_{a<j}r_{i_a}+h_{i_j}\right),
\sum_j r_{i_j}+b_{\mathrm{out}(v)}
\right\},\qquad r_v=b_{\mathrm{out}(v)}.
\tag{6-9}
$$

相等时使用固定节点编号打破平局，形成可复现的深度优先后序。记节点 $v$ 的孩子数为 $a_v$，排序与遍历复杂度为 $O(|V|+|E|+\sum_v a_v\log\max(1,a_v))$；输入索引、组件分配和官方验证成本另计。

该结论的范围是“不交错子树的内部张量标量峰值”。外部输入、工作空间、L1/UB 分池、COPY、跨流水线并行及 Cache 均未进入式（6-8），因此它不是零 spill 证书或 Makespan 最优性证明。算法不改变归约结合关系、不重写运算，只生成一个原图上的顺序候选，再由官方评价判定收益。

### 6.3.4 条件下界与严格接受

对于受支持的单计算节点子图、M/V 流水线和整数持续时间，可建立仅含必需计算约束的有向图：保留已核实的原始计算依赖，并加入每核同一流水线的相邻 FIFO 约束；对确实必需的跨核依赖加入固定跨核等待。同一对节点上的多个约束取最大延迟，不能将重复依赖当成串联等待累加。COPY 收缩若引入未经证明的依赖，则不使用该界。

设该图中边 $(u,v)$ 的必需延迟为 $d_{uv}\ge0$，必要完工时间满足

$$
f(v)=d_v+
\max\left(\{0\}\cup\{f(u)+d_{uv}:u\to v\}\right),
\quad d_v=\max(1,\mathrm{cycles}_v),
\tag{6-10}
$$

并令 $L(P)=\max_vf(v)$。在上述守卫成立时，任何成功的官方执行都必须遵守这些约束，因此 $L(P)\le M_3(G,P)$。若 $L(P)$ 已不小于当前合法方案的完成时间，就可在无需 E0 的情况下排除其严格改进可能。下界不能证明候选能执行；不支持该界时也不能据此拒绝一个候选。

完整版本的处理步骤如下。

1. 读取原图与固定配置，建立结构索引，按确定规则产生并评价新的基准方案。
2. 根据结构形成一般 DAG、注意力顺序或共享输入流水候选；后续森林候选也使用同一总预算。
3. 与当前方案按规范化提交字节比较，重复方案不再次评价；对符合条件的候选计算必要界，并剔除不可能严格改进者。
4. 对剩余候选调用未修改 E0。仅在执行合法且官方 Makespan 严格更小时更新当前方案；被明确识别为评价合法性拒绝的增量候选或相同成绩保留已有合法方案。
5. 输出最终两字段方案，保存各次评价、选择原因、输入/源码身份与完整求解墙钟。

固定统一入口每个图/核数最多调用 3 次在线 E0，包括基准评价；这是该实现的总调用上限，不是每个候选模块各有 3 次。算法的效率依据在于结构化直接构造、动态规划和有证明的剪枝，不能仅以“限制尝试次数”说明其方法合理。候选较少也不意味着总墙钟等于某一内部动态规划的运行时间。

上述非退化保证仅相对于本次运行已经成功评价的基准，并非相对于所有历史算法。初始基准若评价失败，便不存在可供承诺的合法回退方案。实现只把明确的结构不适用作为换路线理由；程序缺陷、保存失败和未归类的评价错误向外报告，不能被静默吞掉并伪装成成功回退。

## 6.4 容量约束的共享输入流水改进

本节是已完成单例官方验证的扩展，尚未并入上述完整 500 格版本。它用于补充共享输入流水模型遗漏的首次搬运和驻留约束。

### 6.4.1 首次装入成本

设每个共享输入仅在一个相同的作业位置被消费，第 $\ell$ 个位置的名义首次装入成本为

$$
q_\ell=\sum_{t\in T_\ell}
\left\lceil\frac{b_t}{B_{\mathrm{DDR}}}\right\rceil.
$$

在“各阶段串行服务、首次作业承担一次装入、随后共享权重可复用”的抽象中，阶段 $j$ 的首次装入成本为 $\eta_j=\sum_{\ell=x_{j-1}}^{x_j-1}q_\ell$，每个作业的阶段计算耗时为 $p_j$。对串行流水递推展开，得到

$$
\widehat M_{\mathrm{cold}}
=\sum_{j=1}^{s}p_j+
\max_{1\le j\le s}
\left((J-1)p_j+\sum_{a=1}^{j}\eta_a\right).
\tag{6-11}
$$

式（6-11）说明，仅均衡各阶段计算量会忽略装入成本在前缀上的累积。若大量共享权重集中在较早阶段，后续作业的稳态平衡并不能抵消首次启动延迟。

为说明其精确范围，令 $F_{j,n}$ 为第 $n$ 个作业在阶段 $j$ 的结束时刻。本抽象中，首次装入在该阶段处理首个作业时发生，不允许提前与其上游工作重叠；于是 $F_{j,1}=F_{j-1,1}+\eta_j+p_j$，而 $n\ge2$ 时有 $F_{j,n}=\max(F_{j-1,n},F_{j,n-1})+p_j$，边界 $F_{0,n}=0$。归纳可得

$$
F_{j,n}=\sum_{a=1}^{j}p_a+
\max_{1\le b\le j}\left(\sum_{a=1}^{b}\eta_a+(n-1)p_b\right).
$$

归纳中，从同阶段前一作业递推得到的某项含 $p_j+(n-2)p_b$，当 $p_j\le p_b$ 时被同一 $b$ 的 $(n-1)p_b$ 项支配；当 $p_j>p_b$ 时被包含更长非负装入前缀的 $b=j$ 项支配。上游阶段项提供所有 $b<j$，同阶段前一作业项也保留了 $b=j$，因而得到等式。取 $j=s,n=J$ 即式（6-11）。若真实执行允许预取或 M/V 重叠，此递推前提不再成立，所以不能把该公式当成 E0 的精确时间。

### 6.4.2 驻留约束与动态规划

对连续区间 $[h,i)$ 和存储空间 $r\in\{\mathrm{L1},\mathrm{UB}\}$，令 $A_r[h,i)$ 为区间共同输入的总字节，$U_r[h,i)$ 为其中任意单次操作的非共同输入/输出工作集字节最大值。仅允许

$$
A_r[h,i)+U_r[h,i)\le C_r,
\qquad r\in\{\mathrm{L1},\mathrm{UB}\}.
\tag{6-12}
$$

令 $Q_i=\sum_{\ell<i}q_\ell$，以 $W_i$ 表示计算量前缀和，带容量筛选的递推为

$$
D_j(i)=\min_{\substack{j-1\le h<i\\[h,i)\ \text{满足式（6-12）}}}
\max\{D_{j-1}(h),Q_i+(J-1)(W_i-W_h)\}.
\tag{6-13}
$$

最终抽象目标为 $W_L+D_s(L)$。固定末端 $i$ 向前扫描 $h$ 时，共同输入量与单次操作最大工作集均单调不减，一旦超容量就可停止扫描。两类存储空间数为常数，故时间仍为 $O(sL^2)$，空间为 $O(sL)$。无可行分段或结构守卫不满足时，返回原有流水构造；不会为得到可行解任意放宽容量。

式（6-12）只排除了明显无法同时驻留的区间。它没有覆盖多操作交叠生命周期、预取、输出排队和官方分配过程，因而不保证零 spill。原始 DDR 端点仍按合法输入处理；若共同计算输入需要由 DDR 物化为局部 UB，而当前模型不能准确表示，则由守卫回退，不能将这部分容量记为零。

> **图 6-2 占位：容量约束对阶段切分的影响。** 横轴为作业计算位置，分面显示计算均衡、含首次装入、含驻留约束三种切分；颜色表示核归属，叠加各段共同输入与单次操作工作集，标注 L1/UB 容量线。采用 case044/k4 的固定结果及元数据，真实峰值与静态估计分别标识，不以估计值替代实测峰值。

### 6.4.3 从静态驻留估计到完整 Task 的前缀构造

最新的单例扩展进一步利用子图合并影响官方核内构造的能力：保持阶段切点与核归属，选取一个先导作业，将其下游阶段内部操作合为子图，使相关共享 COPY 在官方生成的顺序中形成受控前缀。先导作业由实际结构与官方排序条件选择，而不是提交人工等待、直接移动 COPY 或修改缓存规则。对 case044/k5，固定切点为 $[0,24,51,68,96,124]$，11 个作业采用同一排列；原始运算、分核及 121 条跨核 link 保持不变。

这种构造需要检查实际展开 Task，不能仅对共享输入求和。已发布的静态验证对全部局部张量按首次/末次使用计算闭区间驻留，同一步按先分配、后释放计峰值；其零 spill 推断还要求无初始驻留、完整字序对应固定 Step2 语义。提前装入则另需验证 COPY 位于 Task 前缀、没有跨核释放门控、输入不是本 Task 内部产生、且初始容量足够。该项比式（6-12）检查范围更完整，但容量可行仍不能推出 Makespan 最优，共享 DDR 竞争需要实际模拟。后续已取得一次官方 P3 结果，见 §6.6.3；尚未成为新的完整统一算法。

### 6.4.4 部分分桶的离线构造与静态筛选

部分预加载已进一步形成保存快照上的离线转换。保持阶段切点、各核归属及计算投影不变，将某个下游核先导作业的首个子图拆成非空前部与后部，后部子图紧随前部。依据实际计算消费者/生产者，分别把 COPY_IN 分配到最早消费者桶、COPY_OUT 分配到最晚生产者桶，再按保存的 Step1 原始顺序稳定分桶。输出仍只有原题允许的两个字段，构造器给出的操作顺序只是预测的 pre-Step2 顺序，尚不等同于官方重新构建的 Task。

在 044/k5 保存快照的核 2 上，先导链有 17 个计算操作、7 笔原前缀冷读。按冷读首次消费者变化选择的受限断点族为 $(h,q)=(1,0),(2,1),(5,2),(7,3),(10,4),(12,5),(15,6)$，其中 $h$ 为前部计算操作数，$q$ 为提前冷读数。发布结果中这 7 个结构均通过计算覆盖、原依赖拓扑、闭区间驻留和全核 pre-Step2 无环检查；联合图包含 1678 个操作和 3825 条去重边，尚未包含 Step3 内存复用边。

该族不是全部合法切分。同一个 $q$ 下，不同 $h$ 仍可能改变中途激活或 COPY_OUT 的归桶，因此不能仅按冷读数相同就把所有切点判为等价。示例事先取 $h=10,q=4$ 展示转换，其 4 笔前缀冷读后仍有两笔先导激活；静态闭区间峰值为 L1 516,480 B、UB 0 B。这说明构造已能表达多个激活前后的输入顺序，不说明该示例是性能最优或已经通过官方容量事件检查。

设保存 Task 的操作、边集合为 $V_s,E_s$，张量 $t$ 的生产者、消费者集合分别为 $\mathrm{Prod}(t),\mathrm{Cons}(t)$，则单候选的端口索引、稳定分桶、生命周期及全核拓扑处理为 $O(|V_s|+|E_s|+\sum_t|\mathrm{Prod}(t)|\,|\mathrm{Cons}(t)|)$ 时间和空间；原始官方 Task 构建与复评另计。快照、计划与原容量证书必须绑定固定来源，输入检查不等于认证任意外来证书。新的候选仍须重新检查官方 Task/COPY 身份、Step2/Step3 及完整依赖，并取得 E0 结果；本节只引用保存结构上的离线验证。[固定构造及审计](https://github.com/huaweibei123/huaweicup2026/tree/3d22453deb0d2e3618f9d6cb41795ff164c6c84e/results/a/q3-nikolastarx/partial-bucket-compile-20260925)

在此基础上，后续验证冻结了一个结构规则：在末两笔冷读具有不同首次消费者、且先导链可拆分的下游阶段中，选择原前缀名义 DDR 服务总量最大的核，并列时取较小核号；取能将最后一笔冷读留在后部的最早计算断点。规则比较的是原输入工作量，不读取候选成绩。在 044/k5 上，它选择核 2、$h=15$，把 17 个计算操作分成 15+2，7 笔冷读分成 6+1。这个选择是针对启动竞争提出的可证伪启发式，不是由 §6.5.7 的三个非支配模型自动推出的唯一最优解，也未验证在其他图上的收益。

## 6.5 必要界与结构化拓展

### 6.5.1 完整作业分配的能力边界

若 $J$ 个相同作业均不可拆分地分配到 $K$ 核，且每个作业在同一串行计算流水线上的工作量为 $w$，则至少一个核承受 $\lceil J/K\rceil$ 个作业，故该方案族满足

$$
M\ge\left\lceil\frac JK\right\rceil w.
\tag{6-14}
$$

在 case067/k5 中，$J=71$，每作业 M 流水线工作量为 829,792 cycles，因此完整作业归核的必要界为 12,446,880 cycles。已有合法方案达到 12,237,901 cycles，低于该家族界。因此，继续在“所有作业保持完整”的分配族中改顺序，无法超越这一已有成绩；至少需要切分部分作业或改变家族限制。该判断排除了一个研究方向，并不证明已有方案是整个 P3 问题的最优解。

### 6.5.2 单尾切分与首波阶梯

针对作业数不能整除核数的情况，将大部分作业完整归核，只把一个余量作业按连续区间分给多个核，可降低整作业粒度造成的负载偏差。但负载均衡后，余量作业仍沿多个核传递；若各核同一流水线前方积压过多本地工作，就会形成 FIFO 等待。

为此构造首波阶梯：各核使用确定的首波完整作业数，使余量段与本地作业的相位相互配合，而不是让所有核采用完全相同的启动批量。针对固定 case067/k5 的一个构造，切点为 $[0,20,44,66,94,124]$，首波完整作业数为 $[2,3,4,5,6]$。在去除 COPY 和额外跨核延迟、保留原始计算依赖与核内 FIFO 的模型中，该构造的必要完成时间为 11,856,672 cycles。

这一数值是固定构造的计算松弛界，不能填入官方 Makespan 表。对应真实方案已完成一次冷构造，但随后的评测流程在父进程读回阶段失败，尚未执行 P2/P3 E0。因此，本稿只将它用于分析后续瓶颈，不报告该候选的 CacheGain、搬运量或官方改善百分比。

### 6.5.3 四系数响应压缩与切点优化

进一步限定各核局部次序固定、唯一跨核交互是一条串行余量链、所有额外传输延迟为零。设余量进入核 $c$ 的时刻为 $R_c$，则每个局部操作的完成时刻可写成固定常数与 $R_c$ 加固定常数的最大值。该形式对取最大与加固定操作时长封闭，因此本核全部计算完成和余量离开分别可压缩为

$$
E_c(R_c)=\max(A_c,R_c+B_c),\qquad
R_{c+1}=\max(C_c,R_c+D_c).
\tag{6-15}
$$

系数可通过局部 DAG 自底向上求得，全图建模成本为 $O(|V|+|E|)$，固定系数后的跨核组合为 $O(K)$。这不是说完整求解器能以 $O(K)$ 完成，也不是把 COPY 服务压缩成了四个数。

对上述 case067/k5 固定构造，8804 个计算操作的完整 FIFO DAG 与四系数组合在各核完成、余量到达及总完成时间上逐项一致。当前每核均满足 $R_c+B_c\le A_c$，从而 $E_c=A_c$。这意味着，在不改变局部次序和 $A_c$ 的条件下，仅让余量更早到达不能继续降低该零 COPY 模型的完成时间，后续改进应关注本地排序、切点或真实搬运成本。

若每个阶段的候选区间 $[h,i)$ 都已具有固定四系数，且后缀只依赖阶段、切点和 $R$，可将最优切点问题转为阈值可行性判定。给定目标 $T$，在每个状态只保留“所有已选阶段 $E\le T$ 的前缀中，最早的余量完成时刻” $R[j,h]$。对满足 $\max(A,R[j,h]+B)\le T$ 的区间更新

$$
R[j+1,i]=\min\{R[j+1,i],\max(C,R[j,h]+D)\}.
\tag{6-16}
$$

由于式（6-15）对 $R$ 单调，较早的前缀到达时间不会使任何相同后缀恶化。由此可在给定阈值下精确合并状态，再通过整数二分求最小可行 $T$。若区间表有 $m$ 项、最大系数为 $F$，单位成本整数运算下的建表后复杂度为 $O((m+KL)(1+\log(1+KF)))$，空间为 $O(m+KL)$。

该动态规划已通过小规模固定表与全部切点枚举的合成对照；真实图的完整区间系数表及带 COPY 的端到端版本尚未完成。若前缀切分会改变后续容量、首波数或 Cache 状态，后缀便不能只由当前 $R$ 表示，式（6-16）的状态合并也不再自动成立。

### 6.5.4 固定读取集合的 Cache 命中上界

对一个固定的 Cache 查询键多重集，设逻辑键 $t$ 被完整读取 $n_t\ge1$ 次，每次有效读取字节均为 $b_t>0$。初始 Cache 为空且只有读取完成可以填入条目时，每个键的首次读取必定未命中，因此

$$
B_{\mathrm{hit}}\le\sum_t(n_t-1)b_t,
\qquad
H\le 1-\frac{\sum_t b_t}{\sum_t n_tb_t}.
\tag{6-17}
$$

这里的首次读取指首次发起的查询：在它之前没有同键读取可以完成并将该键装入。若同键多个读取在第一次填入前重叠发起，还可能出现额外未命中。故式（6-17）是该固定读取集合的必要上界，而不是任意排序都能达到的值。

当全部不同键的总字节不超过 Cache 容量，且后续读取都在首次填入后发起时，可以没有淘汰并让所有重复读取命中，从而达到此上界。一旦保存的事件表已经证明“首次全 miss、重复全 hit”，继续重排同一读取集合便不能增加命中字节；但它仍可改变带宽竞争和 Makespan。重新切图、改变归核或 spill 状态若改变了读取键多重集，就必须重新计算该界，不能把局部饱和扩大为全问题最优。

### 6.5.5 全量预加载前缀的共享服务必要界

前缀构造还揭示了独占 COPY 时长的不足。考虑一组从时刻 0 开始就绪、无外部依赖等待的冷读前缀，每核同一时刻至多一笔传输，均进入同一个 DDR 服务池。将独占服务能力归一化为每周期 1 单位，前缀 $c$ 的名义服务工作量为 $\omega_c$，前缀 $j$ 内有 $m_j$ 笔传输，内部完成—下一笔发起的间隙数为 $g_j=m_j-1$。

即使前缀始终就绪，官方事件方式也会将分数时刻完成的传输推迟到向上取整的整数退休时刻，再发出下一笔；因此不能直接套用连续流同时服务的公式 $F_c\ge\sum_j\min(\omega_c,\omega_j)$。已保存的有理数合成反例中，四个前缀的独占工作序列分别为 $[4,1]$、$[1,1,3,2]$、$[2]$、$[1,1,4]$，时刻 1 再到达一笔工作量为 1 的额外传输；第一条前缀在 16 完成，而朴素公式给出 17。它是模型反例，不是新的官方用例成绩。

在精确有理数公平共享、每个内部退休间隙小于 1 周期的模型中，可以保守扣除这些间隙：

$$
F_c\ge\omega_c+
\sum_{j\ne c}\min\{\omega_j,\max(0,\omega_c-g_j)\}.
\tag{6-18}
$$

证明分两种情况。若 $j$ 在 $c$ 完成前已经结束，则它已经获得 $\omega_j$ 服务；否则，在两者同时活跃时，两者获得相同服务，$c$ 只能在 $j$ 的内部退休间隙中累计多获得少于 $g_j$ 的服务，因此 $j$ 已获得的服务至少为 $\max(0,\omega_c-g_j)$。取两种情况下共同有效的下限，再与 $c$ 所需的 $\omega_c$ 相加；总服务率不超过 1，得到式（6-18）。额外流量的服务未计入右端，证明不需要假设其对取整后的各个完成时刻具有单调影响。

该式约束前缀最后一次读取的**完成时刻**，可作为后继计算的释放下限，不能把它当作该读取的开始时刻再加一遍持续时间。其前提也不覆盖带跨核释放、命中 Cache、多个在飞传输或主动暂停的前缀。当前仅证明精确有理数共享与取整模型；官方浮点实现及 $10^{-9}$ 容差的数值稳健性尚未独立证明，因此该研究界尚未用作官方执行器的严格剪枝证书。

### 6.5.6 部分预加载的单激活模型与适用边界

全前缀构造把冷读集中在计算前，能够避免被跨核激活挡住，却也可能加重多个核的同时启动竞争。一个结构化改进方向是保持阶段切点、归核和作业次序，仅将先导作业的阶段链分成前部与后部两个子图。若官方分桶后，MTE2 队列恰好为“前部冷读—首部激活—后部冷读”，后部读取就有机会与前部计算交错。这一操作仍通过子图划分与提交顺序表达，不能在输出中直接指定 COPY 队列或开始时刻。

先研究一个明确的数学子问题：单阶段只有一条串行计算链，总计算服务为 $C_{\mathrm{comp}}$；唯一首部激活在固定时刻 $R$ 释放，传输服务为固定的 $d_a$。共有 $m$ 笔不同冷读，均在时刻 0 已就绪，按首次消费顺序排列，在同一 MTE2 上串行执行，固定服务为 $w_1,\ldots,w_m$，前缀和为 $U_r=\sum_{i=1}^{r}w_i$，$U_0=0$。读取 $r$ 首次消费之前的累计计算服务记为 $\pi_r$，满足 $0\le\pi_1\le\cdots\le\pi_m\le C_{\mathrm{comp}}$。不考虑其他传输、额外激活、容量阻塞、Cache 状态变化和跨核反馈；MTE2 与计算可以并行。

设 $q$ 是合法子图边界所对应的预读笔数，队列先完成前 $q$ 笔冷读，再等待并传输激活，最后依次读取其余输入。在上述固定服务模型中，精确完成时刻为

$$
T(q)=\max\{R,U_q\}+d_a+C_{\mathrm{comp}}
+\max\left\{0,\max_{r>q}(U_r-U_q-\pi_r)\right\}.
\tag{6-19}
$$

无尾读时，最后一项取零。证明如下：计算最早从 $t_0=\max\{R,U_q\}+d_a$ 开始，尾读 $r$ 在 $t_0+U_r-U_q$ 就绪，而不等待的链在 $t_0+\pi_r$ 首次使用它。因此，至该位置累计等待必须至少为 $U_r-U_q-\pi_r$。串行执行并仅在输入未就绪时等待，其累计等待恰为已遇到约束的非负最大值，故式（6-19）的下限可达。该证明依赖固定服务与单个激活，不能用旧 trace 的实际 COPY 历时替代假设。

令 $Z_q=\max_{r>q}(U_r-\pi_r)$、$Z_m=-\infty$，通过一次前缀和与后缀最大值扫描即可求全部候选时间。在预先给定的合法断点集合 $\mathcal Q$ 内，选择 $\arg\min_{q\in\mathcal Q}T(q)$ 的时间为 $O(m+|\mathcal Q|)$，空间为 $O(m)$；这里不包括从原图证明合法断点的成本。处于同一首次消费者位置的多笔读取不能任意拆开。模型时间相同时选择较大的 $q$，仅作为确定的平局规则。

激活释放时间会改变最优断点。例如取 $w=(1,8)$、$\pi=(0,2)$、$d_a=1$、$C_{\mathrm{comp}}=3$：当 $R=1$ 时，部分预读 $q=1$ 的完成时刻为 11，全前缀 $q=2$ 为 13；当 $R=10$ 时，两者分别为 20 和 14。后一情形中，激活的队首等待挡住了服务量为 8 的尾读。这是固定服务微例，说明仅凭冷读总量或“计算越早启动越好”不能选择断点，不是官方方案性能结论。

已有真实 Task 守卫给出了更直接的限制：044/k5 的核 1 先导阶段有 1 次首部激活，核 2 有 2 次激活，核 3、4 各有 4 次。核 2 的两次首次消费位于局部计算位置 0 和 3，因而当前关键启动瓶颈不满足单激活前提；核 1 也只通过了这一项守卫，尚不能由此推出固定服务、队列和内存条件全部成立。一般多激活阶段还须保留各中途释放时刻，单个 $R$ 不足以描述它。

因此，部分预加载目前属于有精确局部模型的研究设计。后续需要依据原始结构给出多个释放时刻和共享服务约束，核对真实 COPY 顺序、容量及完整依赖无环，再决定是否形成候选。固定全前缀下的 36,592 周期界不直接适用于新的交错结构。现有材料只报告纯模型测试和保存 Task 的静态守卫，没有产生新的官方成绩。[部分预加载设计与守卫](https://github.com/huaweibei123/huaweicup2026/blob/734914db51cecf094453c2b02e67fc5f5619b090/results/a/q3-nikolastarx/partial-preload-design-20260925/DESIGN.md)

### 6.5.7 多个输入释放时刻的完成时间包络

为保留中途激活信息，将单个 $R$ 扩展为释放向量 $\mathbf R$。考虑固定 FIFO 中的 $n$ 笔输入传输，服务工作量为 $w_i>0$，释放时刻 $a_i$ 或为 0，或等于某个外部变量 $R_\ell\ge0$；同一标签可被多笔输入共享。串行计算链总服务仍为 $C_{\mathrm{comp}}$，输入 $i$ 首次使用前的计算量为 $\pi_i$。$\pi_i$ 不必按 FIFO 次序递增，但所有输入均有消费者，且没有内部计算释放、分配阻塞或其他资源干扰。

令 $S_i=\sum_{j=1}^{i}w_j$，$S_0=0$，则输入完成和计算链完成满足

$$
\begin{aligned}
E_i&=\max\{E_{i-1},a_i\}+w_i
=S_i+\max\left\{0,\max_{j\le i}(a_j-S_{j-1})\right\},\\
T&=C_{\mathrm{comp}}+
\max\left\{0,\max_i(E_i-\pi_i)\right\},\qquad E_0=0.
\end{aligned}
\tag{6-20}
$$

第一行由 FIFO 递推展开得到，第二行来自串行链对所有首次消费就绪约束的最大累计等待。令 $\Lambda_j=\max_{i\ge j}(S_i-\pi_i)$；对于释放标签 $\ell$，取 $\lambda_\ell=\max_{j:a_j=R_\ell}(C_{\mathrm{comp}}-S_{j-1}+\Lambda_j)$。将常数项规范化为全部释放取零时的完成时间 $\theta=\max\{C_{\mathrm{comp}}+\max(0,\Lambda_1),\max_\ell\lambda_\ell\}$，交换式（6-20）的最大值次序可得

$$
T(\mathbf R)=\max\left\{\theta,
\max_\ell(R_\ell+\lambda_\ell)\right\}.
\tag{6-21}
$$

一次前缀和与一次后缀最大值扫描即可在 $O(n)$ 时间和空间内得到整个函数，无需采样释放时刻；无变量标签时忽略相应最大项，无输入时直接有 $T=C_{\mathrm{comp}}$。这扩大了单激活模型的状态范围，但仍假定每笔服务固定。

对于相同释放标签域、相同非负独立变量的两个规范化候选 $A,B$，有

$$
T_A(\mathbf R)\le T_B(\mathbf R)\quad\forall\mathbf R\ge0
\quad\Longleftrightarrow\quad
\theta_A\le\theta_B\quad\text{且}\quad
\lambda_{A,\ell}\le\lambda_{B,\ell}\quad\forall\ell.
\tag{6-22}
$$

逐项比较给出充分性；令全部释放为零得到常数项的必要条件，再令一个释放变量单独趋于无穷，即得到对应系数的必要条件。真实释放若存在相关约束，该判据仍是保守的充分条件，但不再是受限可达域上的必要条件。若改变候选会改变释放向量本身或共享服务时长，则不能将式（6-22）直接用作官方剪枝。

将 §6.4.4 的 7 个结构与原全前缀共 8 个保存结构代入模型，核 2 首个作业的计算总量为 1120、固定输入服务总量为 8609，均以模型周期计。以 $R_a,R_b$ 分别表示上游核 1 的 COPY_OUT 1000001655、1000001652 完成并经过固定跨核延迟后的释放，独立非负变量域中剩下三个互不支配的签名：

| 2 | 1 | 9565 | 8336 | 959 |
| 15 | 6 | 8759 | 1385 | 1382 |
| 17（原全前缀） | 7 | 9726 | 1123 | 959 |

这些数是首个作业的固定服务函数系数，不是官方 Makespan。示例 $h=10$ 只用于证明离线转换可以生成预期结构，在此模型中被 $h=15$ 支配。上游两次 COPY_OUT 本身存在 FIFO 次序，实际释放并非任意独立变量；当前表不使用这类耦合进一步筛选，更不把各核局部优选拼成全图保证。本次基于已发布传输记录重算了 8 个签名及支配关系，没有重新编译候选或重建 Task。[固定模型与数据](https://github.com/huaweibei123/huaweicup2026/tree/3d22453deb0d2e3618f9d6cb41795ff164c6c84e/results/a/q3-nikolastarx/release-envelope-model-20260925)

### 6.5.8 共享服务对激活释放的反作用

多个释放变量仍未解决共享资源反馈：预读占用的 DDR 服务可能推迟上游，进而改变这些释放时刻。一个两流数学反例足以说明局部总量不够。目标阶段只有一笔可提前冷读，服务为 5，首次消费前计算为 1，总计算为 2，激活传输服务为 1；上游串行供给过程完成后再等待 500 周期。

| 上游原过程 | 不预读时释放 | 不预读完成 | 提前该笔后的完成 |
|---|---:|---:|---:|
| DDR 10 → 计算 10 → 固定等待 500 | 520 | 527 | 528 |
| 计算 10 → DDR 10 → 固定等待 500 | 520 | 527 | 523 |

两行的总 DDR、总计算、原释放时刻及目标摘要相同，区别只是上游原服务顺序。第一行中预读与上游同时抢占 DDR，使上游多耗时 5，最终慢 1；第二行中预读藏在上游计算期间，上游不延后，最终快 4。因此，旧释放时刻不能被当作不受本次选择影响的“免费预取窗口”，这些局部摘要也不能支持各核独立最优后的拼接。此表是解析数学反例，不是新官方用例成绩。

一个可精确研究的受限族是：激活前只有一条串行上游供给流和一个目标预读流，每流至多一笔 DDR 传输在途；上游由固定 DDR 段与原计算/依赖等待段交替组成，不反向依赖目标；目标只有一次激活，激活与后续冷读期间没有第三路竞争或未建模阻塞。设上游总 DDR 服务为 $W$，非 DDR 时间为 $G$，不预读时释放为 $R_0=W+G$。假想目标一直有可执行的预读，以它已取得的服务 $x$ 为横轴，定义 $Y(x)$ 为与它同时完成的上游 DDR 服务：顺着上游原段构造曲线，DDR 段斜率为 1，非 DDR 段斜率为 0，$x\ge R_0$ 后固定为 $W$。这条曲线来自原依赖与工作量，不使用旧 trace 的实际历时。

预读未完成时目标始终有工作，由服务守恒，上游新释放和目标前缀完成分别为

$$
R(x)=R_0+Y(x),\qquad F_{\mathrm{prefix}}(x)=x+Y(x).
\tag{6-23}
$$

目标消耗的 $x$ 与上游同时消耗的 $Y(x)$ 相加给出前缀结束时刻；上游共享的每单位服务又使其相对独占多耗一个单位时间，故释放推迟 $Y(x)$。令 $\Delta=\max\{0,\max_r(U_r-\pi_r)\}$ 为 §6.5.6 固定输入链的最大加载欠账。对真实合法断点的累计服务 $x=U_q$，前 $q$ 笔的欠账不超过 $x$，故式（6-19）的尾部等待可以合并为 $(\Delta-x)_+$。得到该封闭两流模型的精确出口时间

$$
T(x)=d_a+C_{\mathrm{comp}}+Y(x)+
\max\{R_0,x\}+(\Delta-x)_+.
\tag{6-24}
$$

当 $x\le\min(\Delta,R_0)$ 时，相对不预读的改善为 $x-Y(x)$，即真正利用上游非 DDR 时段完成的服务量，而非全部预读量。若这一段供给完全为连续 DDR 工作，则 $Y(x)=x$，提前读取无法严格改善模型出口；它只是等量推迟上游。利用 $Y$ 的斜率和饱和性质，还可证明式（6-24）在 $\min(\Delta,R_0)$ 左侧不增、右侧不减，因而只需比较转折点两侧最近的可实现服务量。按已排序断点和上游阶段合并扫描，模型选择时间与空间均为输入读数加上游阶段数的线性量级。

上述两流、整数工作量、整数计算/等待且无第三路到达的特例，其事件可保持整数，不能据此取消一般多流模型的退休间隙或官方浮点容差问题。044 当前有多路启动流、中途残差、其他作业和写回，尚未证明满足这个受限族。即使局部出口下降，也只有在它代表全图出口，或后续状态相同且只整体平移时，才可推出总 Makespan 改善。当前结论用于说明应保留哪些共享服务状态，不能登记为新官方算法或成绩。[R7 归档推导](https://github.com/huaweibei123/huaweicup2026/blob/3d22453deb0d2e3618f9d6cb41795ff164c6c84e/AI%20chats/20260924-Pro-P3-%E5%BD%92%E7%BA%A6%E6%A3%AE%E6%9E%97%E5%88%87%E5%88%86/FINAL-r07-bb41cb93.rendered.txt)

### 6.5.9 与三问共同的全域性能证书

在冻结官方语义下，当前合法方案提供 Makespan 上界 $U$，对全部合法成功方案成立的必要条件提供下界 $L$。两者满足 $L\le M_3^*\le U$；固定官方单核分母 $B$ 后，$B/L$ 才是最优加速比的上界。前述固定归核、固定 FIFO 或理想服务模型中的界，不能未经证明并入这个全域 $L$。

对原图中唯一计算生产者、无原始 logical 身份混叠等充分条件，任意成功执行均可投影为原计算调度：保留原计算时长、每核每 Pipe 单槽及原计算直接边、tensor 生产者—消费者因果。spill 的 backing 因果和接收端 MTE2 FIFO 共同保证 reload 不绕过必要输入。计算时长不受 COPY 共享池的浮点重投影影响，因此这个计算松弛适用于 P1/P2/P3。100 张原图通过了所用充分条件检查；这不是任意官方输入的完整合法性刻画。

记不含自身的最长计算前后缀为 $h_v,t_v$，同 Pipe 非空窗口为 $S=\{v:p(v)=p,h_v\ge a,t_v\ge b\}$。其时长降序为 $d_{(1)}\ge\cdots\ge d_{(n)}$，定义

$$
A_K(S)=\max_{\substack{r\ge1\\m=(r-1)K+1\le n}}
\sum_{j=m-r+1}^{m}d_{(j)}.
$$

全部 $S$ 操作完整落在 $[a,M_3-b]$ 中。容量要求窗口长度至少为 $\lceil W(S)/K\rceil$；前 $(r-1)K+1$ 个操作中至少一核承担 $r$ 个，又要求窗口长度至少为 $A_K(S)$。因此

$$
M_3\ge a+b+\max\{\lceil W(S)/K\rceil,A_K(S)\}.
\tag{6-25}
$$

这将共同窗口与不可分割计算真正组合起来：二者取最大后只加一次头尾，不能把两个资源下界相加。空窗口不贡献 $a+b$。

进一步，若原计算图有与所有其他计算可由有向路径比较的通用屏障，可将执行分为互不重叠的屏障区间和中间块。原计算跨核因果在 P3 中必经源 OUT、外部 500 周期释放及基础 IN/reload；Cache 命中在释放检查之后，不能省去该等待。令块长为 $x$，左右屏障是否存在为 $\ell,r\in\{0,1\}$，在块内重新计算局部 $h,t$。置

$$
c(a,b)=\ell(500-a)_++r(500-b)_+,\qquad
\phi_{K,c}(W)=\min\left\{W,\left\lceil\frac{W+(K-1)c}{K}\right\rceil\right\},
$$

则有

$$
x\ge a+b+\max\{\phi_{K,c(a,b)}(W(S)),A_K(S)\}.
\tag{6-26}
$$

原因是窗口已覆盖部分跨核等待，其他核相对窗口只需额外晚入 $(500-a)_+$、早退 $(500-b)_+$。两端同核时总容量不超过 $z+(K-1)(z-c)_+$，其中 $z=x-a-b$；两端异核时由 $(z-A)_++(z-B)_+\le z+(z-A-B)_+$ 仍得到同一容量上包络。反解容量再与原子界取最大即可。各块取有效界后与屏障自身时长相加，是利用真实区间不重叠，不是假设各块最优解可以独立实现。P1 采用其已证明的 1000 周期必要延迟，P2 采用 500，证明结构相同。

三问还可共同加入必需输入/输出各 1 周期的虚拟事件；但免费广播输入边只有先后关系，不能附加跨核等待。输入可能提前完成，不能因消费者位于屏障块内就将其 I/O 计入该块。缺少事件定位证明时，不同全域证书只取最大值。一般 COPY 的字节/带宽加权界仍需机器浮点服务证明。

式（6-25）与（6-26）的证明和核查见[三问统一理论札记](../notes/a-theory-coherence-final.md)。本轮没有生成新组合式的 500 格证书，故下一节理论包络仍使用已发布的原计算窗口/原子证书，不杜撰强化后的均值。

### 6.6.7 部分预加载的冻结预算与已发布验证

为检验“少一笔首部预读、由前部计算覆盖末笔读取”的机制，实验事前只冻结上述核 2、$h=15$ 的一个候选。其他核归属、计算次序和原始操作保持不变，旧全前缀的 38,024 cycles 及固定官方原件作为控制。最初发布了计划、预测字、前缀清单及验证程序；随后已发布正式结果。以下保留原判定规则，记录预算如何约束验证，而不是新的实验授权。

1. 最多执行一次新的官方准备，核对实际 Task/COPY 身份与预测操作序列、零 spill、冷读前缀释放条件，以及包含 Step3 内存复用边的全核依赖无环。保存快照的静态通过不替代这一阶段。
2. 准备通过后，最多执行一次新 P3。只有其 Makespan 严格小于 38,024 cycles 才继续；否则终止本候选，不换断点、不重跑至出现改进。
3. 仅在 P3 严格改善后，对新计划和旧全前缀计划分别执行一次 P2，得到两组各自同计划的 CacheGain，并比较总额外搬运、spill 与完整按字节 Cache 统计。若这两次配对未执行或失败，相应收益继续标为未知，不能用其他方案的 P2 值补齐。

因此，事前上限是一轮准备及三次新增 E0，其中两次 P2 为条件调用。这是机制验证预算，不是官方求解时限。程序保留异常及未消费的调用槽，准备、观察与评分的诊断墙钟另列；由于构造使用保存快照，该耗时不能冒充从原始图冷启动的完整求解墙钟。仅在 M 改善后配对还意味着所得 CacheGain 属于条件样本，不能据此估计整个候选族的平均 Cache 收益。

已发布的执行消费了三次新增 E0：候选 P3、候选同计划 P2、控制同计划 P2；控制 P3 复用保存原件。四份结果给出控制 P2=P3=38,024、候选 P2=P3=37,060，降低 964 cycles，即 2.5352409%，两组同计划 CacheGain 都为 1。因此不能将此改善归因于 Cache。P3 在理论第三轮整理时已重新读取四份保存结果并核对可取得原件哈希；本次写作没有新增评价。

已有独立审阅指出，计算归核及 M/V 次序保持，但 MTE2、MTE3 都有变化；核 2 首次计算提前不等于其最终出口提前，其他核出口才出现 964 周期变化。因此可报告综合 COPY 队列时序的实际改善，尚不能把全部收益唯一归因于末笔读取与计算重叠。准备及带追踪评分时间不等于完整冷启动 solver wall，后者仍未知。统一主表仍保留原版本 case044/k5=41,205，不将该机制单格替换进去。[冻结验证预算](https://github.com/huaweibei123/huaweicup2026/blob/a35d384653d175bf36a59f7d7bed26c19979d3cc/results/a/q3-nikolastarx/partial-preload-one-20260925/README.md)，[本机原件核查与来源](../notes/a-q3-theory-r3.md)。

## 6.7 模型评价与适用范围

本方法将原始图中的同构、共享输入和归约结构转化为可直接计算的构造问题。连续阶段划分和限定森林排序具有明确的局部最优性论证，条件下界能够节省不必要的评价，严格 E0 接受则使候选是否改善与官方目标一致。完整统一版本与专项候选分别保存结果，便于在算法更新时检查收益来源。

其局限首先来自官方执行语义与简化模型之间的差距：真实内存生命周期、双存储池、COPY 依赖和动态共享带宽不能由一个负载或命中率指标完整表达。其次，各精确结论都有结构前提，森林交换论证不覆盖交错子树，容量动态规划只精确求解其静态抽象，单尾响应尚未覆盖实际 COPY 和 Cache。多释放包络保留了中途激活，仍未覆盖候选相关的共享服务；两流供给曲线只在封闭串行供给族中精确，不能把未满足条件的真实多核阶段强行合并为一条供给流。最后，全部用例均已参与开发反馈，当前结果不足以代表未知结构上的无条件泛化。

当前接受规则也存在目标覆盖的局限：相较上一完整版本，森林版本有 24 格 Makespan 改善、476 格持平，但五核同计划平均 CacheGain 从约 1.084465 降至 1.082917。实际周期降低与 Cache 相对收益下降可以同时发生。后续研究应保留周期更低的真实收益，同时公开 CacheGain 是否退化；如果一个候选在更低 $M_3$、更高 $C$ 两项都不差且至少一项更好，则另一候选在这两个质量维度上被支配。涉及搬运和求解墙钟时仍需另列取舍，不能只为维持比值而隐瞒实际周期改善。

后续应优先围绕完整结果中仍有实质差距的结构补充容量与通信模型，并在同一计划上验证 Cache 机制；新候选先通过小规模可证伪对照，再决定是否进入统一入口及完整复评。论文随统一算法和固定数据更新，已经失败或未验证的路线保留其边界，避免将理论潜力、代理改进或未完成批次写成竞赛成绩。
